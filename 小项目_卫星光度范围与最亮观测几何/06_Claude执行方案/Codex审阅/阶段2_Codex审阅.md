# 阶段2 Codex审阅：高轨与 STK 场景需求设计

审阅时间：2026-06-05

审阅对象：

```text
06_Claude执行方案/Claude输出/阶段2_高轨与STK场景需求设计.md
```

## 总体结论

阶段2输出中关于 STK 的定位基本正确：STK 更适合作为高轨/地面站/太阳几何生成器，而不是光度或 BRDF 模型。其导出字段清单也基本完整。

但该文档对“5组相位角 + 既有 yaw-pitch 姿态网格足以找到最亮姿态条件”的判断过于乐观。当前方案可以作为第一轮基线筛查，不能保证找到真实或模型内的全局最亮条件。

用户当前担心“5组相位角和有限姿态覆盖不全”，这个担心是正确的。

## 关键问题

### 1. 5组相位角不能保证覆盖最亮 glint 条件

当前已有相位角：

```text
phase24 / phase45 / phase63 / phase90 / phase120
```

可以覆盖从近背向散射到前向散射的粗略范围，但不能保证覆盖镜面反射峰。对于 specular/glint，最亮条件往往由以下关系决定：

```text
surface normal ≈ normalize(sun_direction + observer_direction)
```

只扫 5 个离散相位角，可能错过：

- 极窄的金属主体 specular peak；
- 太阳能板在特定相位角和 roll 下的 glint；
- 相位角连续变化中的局部峰值；
- 高轨真实时间序列中短时最亮窗口。

因此，阶段2中“5组相位角已覆盖范围，完全满足需求”的表述应降级为：

```text
5组相位角足以做第一轮粗筛和对比，但不足以证明全局最亮条件。
```

### 2. yaw-pitch 网格且 roll 固定，不能保证姿态全覆盖

现有 OCS 扫描通常是：

```text
yaw 73 × pitch 37, roll=0
```

这能回答“roll 固定时 yaw-pitch 平面里的最亮姿态”，但不能回答完整三维姿态空间的最亮姿态。

尤其对太阳能板、平板、镀铝膜等镜面/准镜面表面，roll 可能决定表面法向是否接近太阳-观测角平分线。若 roll 固定，可能错过最亮 glint。

建议阶段2增加限制：

```text
现有 yaw-pitch 扫描只能作为二维姿态切片。若目标是寻找最亮姿态条件，必须在阶段5设计 roll 扫描或局部三维姿态精扫。
```

### 3. STK 不一定必须，但“完全不需要 STK”的结论过强

Claude 写：

```text
本小项目不强制需要 STK
```

这句话可以保留。但后面写：

```text
最小替代方案完全满足本小项目需求
```

这句话不应保留。更稳的判断是：

```text
若目标只是复用已有 OCS 数据做相对亮度基线，最小替代方案足够；
若目标是定位高轨真实可观测场景下的最亮时间/相位角/距离/地影条件，STK 或等效轨道-观测几何生成器是有价值的。
```

STK 的必要性取决于目标：

| 目标 | STK必要性 |
|---|---|
| 在现有5个相位角中找最亮姿态 | 不必要 |
| 生成 GEO 距离和相位角 sanity check | 可选 |
| 找某地面站一年/一日内最亮观测窗口 | 推荐 |
| 验证地影、太阳角距、仰角、access window | 推荐 |
| 导出连续相位角供 OCS 局部重算 | 推荐 |

### 4. GEO距离不应简单写成 35,786 km

阶段2多次写：

```text
range_km = 35,786 km
```

这个值是 GEO 轨道高度，不是目标到观测站的 slant range。地面站到 GEO 卫星的距离通常与仰角、星下点经度差、观测站纬度有关，接近但不等于 35,786 km。

建议写法：

```text
GEO轨道高度约 35,786 km；
目标到观测站的 slant range 应由地面站-卫星几何计算，通常约 3.6e4-4.2e4 km 量级。
```

如果只是量级估算，可用 `R≈3.6e7 m`，但不能把它写成严格观测距离。

### 5. “太阳方向固定/观测方向固定可接受”需要限定

对于姿态反演基准，固定几何可以接受。但对于“高轨最亮观测条件”，固定几何只够做受控样例，不够定位真实最亮窗口。

建议阶段2把任务分成两层：

1. 基线层：已有 5相位角 × yaw-pitch 网格，找已有数据中的最亮。
2. 搜索层：连续相位角/时间序列 + roll/局部姿态精扫，找模型意义上的最亮条件。

## 建议的修订方向

### A. 将阶段2结论改为分级

建议改成：

```text
P0 最小方案：可用于第一轮粗筛，不足以证明全局最亮。
P1 多相位角加密：在 phase angle 上加密采样，定位相位角峰值。
P2 姿态扩展：在 top-K yaw/pitch 附近加入 roll 扫描和局部精扫。
P3 STK/等效几何：生成真实高轨时间序列，筛选可观测窗口。
```

### B. 给“最亮条件搜索”单独设计流程

建议后续阶段5采用：

```text
Step 1: 用已有5相位角 × yaw-pitch 扫描做粗筛。
Step 2: 取每个相位角 total OCS top-K 姿态和 per-part top-K 姿态。
Step 3: 对 top-K 姿态加入 roll 0-360 deg 扫描。
Step 4: 对出现尖峰的区域做 yaw/pitch/roll 局部细化。
Step 5: 若需要高轨真实窗口，用 STK 生成时间序列，提取 phase/range/eclipse/elevation。
Step 6: 将 STK 几何映射到 OCS 输入，必要时新增相位角附近 OCS scan。
```

### C. 加入解析 glint 候选条件

对于每个主要平板或部件，可先用解析条件生成候选：

```text
n_body(attitude) ≈ normalize(s + v)
```

用途：

- 检查 yaw-pitch-roll 网格是否覆盖镜面条件；
- 指导 roll 扫描，而不是盲扫；
- 解释“为什么这个姿态最亮”。

### D. 修正距离表述

将 `range_km=35,786 km` 改为：

```text
orbit altitude h≈35,786 km；
slant range R 需由观测站和卫星位置计算；
若仅做量级估算，可先取 R≈3.6e7 m，并标注为近似。
```

## 对用户担心的直接回应

用户担心：

```text

```

审阅结论：

```text
担心成立。
```

当前 5 相位角 + yaw-pitch 网格只能回答：

```text
在已有离散相位角和 roll=0 的二维姿态切片中，哪个姿态最亮。
```

不能回答：

```text

```

要支撑后者，至少需要：

- 相位角加密或 STK 时间序列；
- roll 扫描；
- top-K 局部细化；
- per-part glint 解析条件校验；
- range/elevation/eclipse 等高轨观测约束。
