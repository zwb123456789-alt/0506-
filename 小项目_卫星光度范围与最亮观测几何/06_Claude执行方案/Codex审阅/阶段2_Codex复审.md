## 仍需小修的问题

### 1. `range_km = 35,786 km` 仍有残留

文档 1.2 和 6.1 中仍写到：

```text
range_km | GEO 固定 ~35,786 km
range_km | GEO 标称距离 | 35,786 km（常数）
```

问题：

35,786 km 是 GEO 轨道高度，不是地面观测站到卫星的 slant range。阶段2其他位置已经修正，但这些残留会让后续星等换算误用。

建议统一改为：

```text
GEO 轨道高度 h≈35,786 km；
目标到观测站 slant range R 需由观测站-卫星几何计算；
粗略估算可取 R≈3.6e7-4.2e7 m，并标注为近似。
```

### 2. `range_km = 35,786,000 m` 单位字段混乱

6.2 步骤 3 写：

```text
用 range_km = 35,786,000 m 计算绝对视星等
```

问题：

字段名是 `range_km`，值却写成米。建议改为：

```text
用 R≈3.6e7 m（或 range_km≈3.6e4 km）做量级换算。
```

### 3. “完整三维姿态空间搜索”表述仍过强

P2 表格写：

```text
姿态扩展（roll 扫描 + 局部精扫） -> 完整三维姿态空间搜索
```

如果只是对 top-K yaw/pitch 加 roll，外加局部精扫，它是“局部三维扩展搜索”，不是完整全局三维姿态空间搜索。真正完整全局搜索需要 yaw/pitch/roll 全局网格或优化算法。

建议改为：

```text
局部三维姿态扩展搜索，用于补足 roll 维度并细化 top-K 附近最亮条件；不等同于全局三维穷举。
```

### 4. 最小方案局限表重复

6.3 出现了两张“局限”表，第二张是旧版残留。建议删除重复旧表，只保留包含“5组相位角离散采样”和“roll固定为0”的新版表。

### 5. 阶段4建议不应说“执行换算”

9.2 写：

```text
阶段4：用 P0 参数执行 OCS → 星等换算，输出 5 个相位角下的绝对视星等估算
```

但阶段4原本是接口设计阶段，而且绝对星等仍需阶段1/3条件确认。建议改为：

```text
阶段4：设计 P0/P1/P2 几何到 OCS 和星等换算的数据接口，明确哪些字段进入 OCS、哪些字段只进入光度/星等换算。
```

绝对视星等估算应放在后续实施阶段，且必须标注假设。

### 6. STK “太阳方向在目标本体系中的投影”需加前提

1.1 写 STK 可提供：

```text
太阳方向在目标本体系中的投影
```

这需要目标姿态/姿态坐标系定义。如果 STK 只提供轨道和太阳方向，目标本体系投影仍需姿态变换。建议改为：

```text
STK 可提供太阳方向和观测方向；若定义目标姿态，可进一步转换到目标本体系。
```

## 对用户担心的回应

修改版已经承认：

```text
5组相位角 + roll=0 只能粗筛，不能保证全局最亮。
```

这是正确方向。下一步阶段5必须真正落实为实验设计：

1. 5相位角粗筛；
2. 每相位角 total/per-part top-K；
3. top-K 姿态 roll 扫描；
4. 必要时相位角加密；
5. 对尖峰区域做局部 yaw/pitch/roll 精扫；
6. 用解析 glint 条件解释峰值。
