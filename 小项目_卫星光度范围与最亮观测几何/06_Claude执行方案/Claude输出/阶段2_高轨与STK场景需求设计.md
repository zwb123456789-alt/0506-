# 阶段2：高轨与 STK 场景需求设计

最后更新：2026-06-05

---

## 1. STK 必要性判断

### 1.1 STK 能提供什么

STK（Systems Tool Kit）是专业的轨道力学与访问分析工具，可提供：

- 精确时间依赖的卫星-观测站距离（range_km）
- 精确时间依赖的相位角（太阳-目标-观测者夹角）
- 太阳方向和观测方向（若定义目标姿态，可进一步转换到目标本体系）
- 地影/食（eclipse）时段
- 可见性窗口（access interval）
- 多圈轨迹下的几何变化

### 1.2 本小项目实际需要什么

| 需求 | STK 是否必要 | 替代方案 |
|---|---|---|
| range_km | GEO 轨道高度 h≈35,786 km；slant range R 需由观测站-卫星几何计算，量级约 3.6-4.2×10⁴ km | 量级估算可取 R≈3.6×10⁷ m，标注为近似 |
| 相位角 | 可由太阳/观测方向计算 | 已有 5 组相位角（24/45/63/90/120°） |
| 太阳方向 | 可由太阳历 + 简化几何计算 | 高精度太阳位置算法（astropy 等） |
| 观测方向 | GEO 几何下可解析计算 | 由观测站经纬度 + 卫星星下点计算 |
| 姿态扫描 | OCS 代码已有 yaw×pitch 网格 | 不需要 STK |
| 地影分析 | 简化模型可判断卫星是否在地影中 | 圆锥地影模型 |
| 多圈时间序列 | 仅当需要连续光变曲线时才需要 | 本项目只需离散几何点 |

### 1.3 判定

**本小项目不强制需要 STK**，但 STK 的价值取决于具体目标：

| 目标 | STK 必要性 |
|---|---|
| 在已有 5 个相位角中找最亮姿态 | 不必要 |
| 生成 GEO 距离和相位角 sanity check | 可选 |
| 找某地面站一年/一日内最亮观测窗口 | 推荐 |
| 验证地影、太阳角距、仰角、access window | 推荐 |
| 导出连续相位角供 OCS 局部重算 | 推荐 |

若目标只是复用已有 OCS 数据做相对亮度基线筛查，最小替代方案足够；若目标是定位高轨真实可观测场景下的最亮时间/相位角/距离/地影条件，STK 或等效轨道-观测几何生成器是有价值的。

**建议记录 STK 接口设计**，以便后续如果需要扩展到时间序列光变分析或真实观测比对时可快速接入。

### 1.4 推荐方案

采用**简化高轨距离模型 + 解析太阳几何**，具体为：

- 轨道高度 h ≈ 35,786 km（GEO 标称）；目标到观测站的 slant range R 应由地面站-卫星几何计算，通常约 3.6×10⁴ ~ 4.2×10⁴ km 量级；若仅做量级估算可先取 R ≈ 3.6×10⁷ m，标注为近似
- 相位角：复用已有 5 组 OBS_GEOMETRIES 作为第一轮粗筛
- 太阳方向：选取若干典型太阳几何（如春分/夏至/冬至 + 子午线方向）
- 观测方向：由 GEO 星下点经度 + 观测站位置解析计算

## 2. 推荐优先场景

### 2.1 场景分级

| 优先级 | 场景 | 范围_km | 相位角来源 | 复杂度 | 本项目价值 |
|---|---|---|---|---|---|
| **P0** | 简化 GEO + 已有 5 组相位角 | ~36,000 | 复用已有 5 组 | 低 | 第一轮粗筛：在已有离散相位角和 roll=0 的二维姿态切片中找最亮 |
| P1 | 多相位角加密 | ~36,000 | 连续相位角采样 | 中 | 定位相位角峰值，弥补 5 组离散采样可能遗漏的 glint |
| P2 | 姿态扩展（roll 扫描 + 局部精扫） | ~36,000 | 复用已有 + roll | 中 | 局部三维姿态扩展搜索，补足 roll 维度并细化 top-K 附近最亮条件；不等同于全局三维穷举 |
| P3 | STK/等效几何生成器 | 计算 | 时间序列 | 高 | 真实高轨可观测窗口、地影、仰角、连续几何 |

**推荐先做 P0 粗筛**，P1-P3 作为分级扩展。P0 只能回答"在已有离散相位角和 roll=0 的二维姿态切片中哪个姿态最亮"，不能回答"完整三维姿态空间和连续相位角下的全局最亮条件"。

### 2.2 P0 详细设计：简化 GEO 模型

#### 卫星参数

| 参数 | 值 | 说明 |
|---|---|---|
| 轨道类型 | GEO（地球同步静止轨道） | |
| 轨道高度 | h ≈ 35,786 km | 标称 GEO 高度 |
| Slant range | R ≈ 3.6×10⁴ ~ 4.2×10⁴ km | 需由观测站-卫星几何计算；量级估算可取 R ≈ 3.6×10⁷ m，标注为近似 |
| 偏心率 | 0 | 假设圆轨道 |
| 轨道倾角 | 0° | 标称 GEO |
| 星下点经度 | 可选，如 110°E（覆盖中国） | 影响观测方向 |

#### 观测站参数（可选）

| 参数 | 值 | 说明 |
|---|---|---|
| 纬度 | 30°N（如成都） | 可调整 |
| 经度 | 104°E（如成都） | 可调整 |
| 海拔 | 0.5 km | 简化 |

#### 太阳几何

不使用 STK 时，太阳方向由以下方式确定：

1. **简化方案**：直接使用 config.py 中的 SUN_VECTOR，归一化后作为惯性系太阳方向
2. **扩展方案**：选取 3-4 个典型太阳几何（如太阳在卫星东/西/正后方/侧方），覆盖不同相位角
3. **完整方案**：使用太阳历计算指定日期的太阳赤经/赤纬，转换为惯性系方向

#### 观测方向

由观测站-卫星几何确定：

```
观测方向 = normalize(卫星位置 - 观测站位置)
```

在 GEO + 地面站简化模型中，观测方向近似为从地面站指向天顶偏南（取决于纬度和卫星星下点经度差）。

## 5. STK 导出字段 → OCS 代码输入的映射

### 5.1 映射关系

```
STK 导出                          OCS 代码输入
─────────────────────────────────────────────────
sun_x, sun_y, sun_z        →     SUN_VECTOR (config.py)
obs_x, obs_y, obs_z        →     DET_VECTOR (config.py)
range_km                   →     R (绝对星等公式中的距离)
phase_angle_deg            →     选择对应 OBS_GEOMETRIES 标签
eclipse_flag               →     若 True，则该时刻 OCS = 0
```

### 5.2 数据流

```
STK 导出 CSV
    ↓
解析每行：time, range, phase_angle, sun_vec, obs_vec
    ↓
对每个时间步：
  ├─ 若 eclipse_flag = True → OCS = 0, 跳过
  ├─ 若 phase_angle 匹配已有 OBS_GEOMETRIES → 用对应 OCS 结果
  ├─ 否则 → 需要新的 OCS 计算（超出当前范围）
  └─ range_km → 绝对星等换算
    ↓
输出：时间序列视星等曲线（或离散采样点）
```

### 5.3 关键约束

- OCS 代码的 SUN_VECTOR 和 DET_VECTOR 是在**惯性系**中定义的，STK 导出也必须在惯性系（如 J2000）中
- OCS 代码只计算离散姿态网格（yaw×pitch），不处理连续姿态变化
- 如果 STK 给出的相位角与已有 5 组不完全匹配，需要插值或新计算

## 6. 不使用 STK 的最小替代方案

### 6.1 方案描述

完全不使用 STK，仅用以下信息完成高轨场景：

| 信息 | 来源 | 值 |
|---|---|---|
| range_km | GEO 轨道高度 h≈35,786 km；slant range R 需由观测站-卫星几何计算 | 量级估算可取 R≈3.6×10⁷ m，标注为近似 |
| 相位角 | 已有 OBS_GEOMETRIES | 24°/45°/63°/90°/120° |
| 太阳方向 | config.py SUN_VECTOR 或解析计算 | [1.0, 0.0, 0.3] 归一化 |
| 观测方向 | config.py DET_VECTOR 或解析计算 | [0.5, -1.0, 0.1] 归一化 |
| 姿态扫描 | OCS 代码已有 | yaw 73×pitch 37 = 2701 点 |
| BRDF | config.py | GGX |
| STL | 建模/真实模型/ | 3 个部件 |

### 6.2 操作步骤

1. 从已有 phase63 OCS 结果提取 total OCS 和 per-part OCS
2. 对 5 个相位角分别提取 OCS（phase24/45/63/90/120 均已有结果）
3. 用 R ≈ 3.6×10⁷ m（或 range ≈ 3.6×10⁴ km）做量级换算（条件性，需标注假设）
4. 比较不同相位角下的最亮姿态和部件贡献
5. 输出相对星等差和部件贡献排序

### 6.3 最小方案的局限

| 局限 | 影响 | 可接受程度 |
|---|---|---|
| 5 组相位角离散采样 | 可能错过极窄的 specular peak 或 glint | 可接受作为粗筛，不能作为全局最亮证明 |
| 太阳方向固定 | 不能覆盖不同季节/时刻的相位角变化 | 可接受（5 组相位角已覆盖粗略范围） |
| 观测方向固定 | 不能反映不同地面站/不同星下点的几何差异 | 可接受（GEO 距离远，方向变化影响小） |
| roll 固定为 0 | 只搜索 yaw-pitch 二维姿态切片，可能错过三维空间中的 glint | 需在阶段5设计 roll 扫描 |
| 无地影分析 | 不知道卫星是否在地影中 | 可接受（地影期间 OCS=0，结论不变） |
| 无大气消光 | 绝对星等可能偏亮 | 需标注（GEO 仰角 30° 时约 0.3-0.6 mag） |
| 无时间序列 | 不能给出连续光变曲线 | 可接受（本项目不需要） |

### 6.4 判定

**最小替代方案可作为第一轮粗筛**，足以在已有离散相位角和 roll=0 的二维姿态切片中找最亮姿态。但不足以证明全局最亮条件；若需定位真实高轨可观测窗口下的最亮时间/相位角/距离，推荐引入 STK 或等效几何生成器。

## 6.5 最亮条件搜索分级方案

为弥补 P0 粗筛的覆盖不足，建议后续阶段5采用以下分级搜索流程：

```
Step 1: 粗筛
  用已有 5 相位角 × yaw-pitch 网格（roll=0），找已有数据中的最亮姿态。
  输出：每个相位角的 total OCS top-K 和 per-part top-K。

Step 2: 多相位角加密（P1）
  在 top-K 相位角附近加密采样（如每 5°），定位相位角峰值。
  输出：更精确的最亮相位角。

Step 3: Roll 扫描（P2）
  对 Step 1/2 的 top-K 姿态加入 roll 0-360° 扫描。
  输出：top-K 姿态附近的局部三维扩展搜索结果（非全局三维穷举）。

Step 4: 局部精扫（P2）
  对出现尖峰的区域做 yaw/pitch/roll 局部细化（如 1° 步长）。
  输出：精确最亮姿态和对应 OCS。

Step 5: STK 时间序列（P3，可选）
  用 STK 生成高轨时间序列，提取 phase/range/eclipse/elevation。
  输出：真实可观测窗口和对应几何参数。

Step 6: 映射与重算（P3，可选）
  将 STK 几何映射到 OCS 输入，必要时在新相位角附近新增 OCS scan。
  输出：时间序列视星等曲线。
```

### 解析 glint 候选条件

对于每个主要平板或部件，可先用解析条件生成候选 glint 姿态：

```
n_body(attitude) ≈ normalize(sun_direction + observer_direction)
```

用途：
- 检查 yaw-pitch-roll 网格是否覆盖镜面条件
- 指导 roll 扫描方向，而不是盲扫
- 解释"为什么这个姿态最亮"

对于金属主体（高 specular），glint 条件最严格；对于太阳能板（大面积漫反射），最亮条件更宽松。

## 8. 风险与待确认项

| 编号 | 风险/待确认 | 影响 | 缓解措施 |
|---|---|---|---|
| R1 | STK 不可用或用户无 STK 许可 | 无法做精确时间依赖几何 | 采用最小替代方案（已设计） |
| R2 | GEO 距离常数假设对低仰角不准确 | 仰角 <10° 时 range 偏差可达数百 km | 限定仰角 >20° 的观测 |

| R5 | 未考虑大气消光 | 绝对星等偏亮 0.3-0.6 mag | 标注未修正，或后续加 Δm_atm |

## 9. 审计结论

### 9.1 核心判断

1. **STK 不强制需要，但有明确价值**：简化 GEO 模型可作为第一轮粗筛；若需定位真实高轨可观测窗口下的最亮条件，STK 推荐。
2. **推荐 P0 粗筛 + P1-P3 分级扩展**：P0 用已有 5 组相位角 + roll=0 的 yaw-pitch 网格做第一轮筛查；P1 多相位角加密定位峰值；P2 roll 扫描补全三维姿态空间；P3 STK 时间序列对接真实观测。
3. **P0 的覆盖限制已明确**：5 组相位角不能保证覆盖 glint 峰值；roll=0 只是二维姿态切片；GEO 距离为量级近似而非严格 slant range。
4. **STK 接口已设计**：如果后续需要，导出字段和 OCS 映射关系已明确。

### 9.2 下一步建议

- **阶段3**：锁定观测波段和太阳星等 m_sun，调研 GEO 卫星典型视星等范围
