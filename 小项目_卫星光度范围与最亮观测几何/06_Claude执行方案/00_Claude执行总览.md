# Claude执行总览：高轨卫星光度与最亮观测几何

最后更新：2026-06-05

## 总原则

本方案用于把小项目一项项交给 Claude 执行，再由 Codex 审阅。Claude 的输出先保存到：

```text
06_Claude执行方案/Claude输出/
```

Codex 审阅意见保存到：

```text
06_Claude执行方案/Codex审阅/
```

## 原大项目保护规则

Claude 执行时必须遵守：

1. 不删除原大项目文件。
2. 不修改原大项目文件。
3. 不向原大项目既有目录添加新文件。
4. 不移动、重命名、覆盖原大项目文件。
5. 如需引用原大项目材料，只能读取、摘要，或复制到小项目文件夹作为只读备份。

## 阶段路线

| 阶段 | 名称 | 是否实施仿真 | 主要输出 | Codex审阅重点 |
|---|---|---:|---|---|
| 0 | 项目边界与术语锁定 | 否 | 边界/术语/红线清单 | 是否误称高轨结论 |
| 1 | OCS定义与星等公式审计 | 否 | 公式审计报告 | 是否把绝对公式写死 |
| 2 | 高轨/STK场景需求设计 | 否 | STK字段清单与场景方案 | 是否能导出必要几何量 |
| 3 | 卫星光度范围调研 | 否 | 文献调研表与可信度分级 | 是否有来源和条件 |
| 4 | 高轨几何-OCS接口设计 | 否 | 数据接口与坐标口径 | 是否能对接现有 OCS |
| 5 | STL最亮部件实验方案 | 否 | 实验矩阵与判定规则 | 是否能回答“哪里最亮” |
| 6 | 综合结论框架 | 否 | 结论模板与证据等级 | 是否过度外推 |

## 推荐执行顺序

严格按 0 -> 1 -> 2 -> 3 -> 4 -> 5 -> 6 执行。每阶段完成后先交给 Codex 审阅，通过后再进入下一阶段。

## 当前不做

- 不运行 OCS 仿真；
- 不运行 STK；
- 不新增轨道传播；
- 不做真实星等数值定稿；
- 不修改原大项目文件。

## 最终目标

形成一条严谨链路：

```text
高轨/STK几何 -> sun/observer/range/phase -> STL+BRDF+OCS -> Delta m -> calibrated apparent magnitude
```

其中：

- `Delta m` 可优先使用；
- `apparent magnitude` 必须等待 OCS定义审计和标定口径确认。
