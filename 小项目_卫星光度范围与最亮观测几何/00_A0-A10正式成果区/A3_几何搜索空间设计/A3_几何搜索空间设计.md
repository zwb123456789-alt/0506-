## 几何变量定义

### 1.1 核心几何变量

小项目第二任务要回答"什么太阳-目标-观测几何、什么卫星姿态、什么材料/部件朝向条件下观测最亮"。因此几何搜索空间必须定义以下变量：

| 变量 | 符号 | 类型 | 单位/约定 | 说明 |
|---|---|---|---|---|
| **相位角** | `phase_angle_deg` | float | 度 | 太阳-目标-观测者夹角（0°–180°） |
| **太阳方向** | `sun_direction_I` | array[3] | 无单位向量（惯性系 I） | **从卫星指向太阳**的单位向量 |
| **观测方向** | `det_direction_I` | array[3] | 无单位向量（惯性系 I） | **从卫星指向观测者**的单位向量 |
| **目标-观测者距离** | `range_km` | float | 千米 | 卫星到观测者的斜距（slant range） |

### 1.2 派生变量与元数据

| 变量 | 类型 | 说明 | 用途 |
|---|---|---|---|
| `geometry_label` | string | 几何标签（如 "phase15_az0" / "phase63_backscatter"） | 追溯和命名 |
| `orbit_context` | string | 轨道语境（如 "GEO_nominal" / "LEO_500km"） | 场景分类 |
| `scenario_label` | string | 场景标签（如 "zenith_observation" / "low_elevation"） | 实际观测场景映射 |
| `sun_azimuth_deg` | float | 太阳方位角（可选） | 多观测方位族设计 |
| `observer_azimuth_deg` | float | 观测方位角（可选） | 多观测方位族设计 |

### 1.3 与姿态变量的分工

**几何变量（A3 负责）**：定义外部观测条件（太阳在哪、观测者在哪、距离多远）

**姿态变量（A4 负责）**：定义卫星自身旋转状态（yaw/pitch/roll）

两者独立正交：
- 同一几何下，可以扫描不同姿态
- 同一姿态下，可以计算不同几何的 OCS

## 方向向量与相位角约定

### 2.1 方向向量物理含义（必须严格遵守）

**继承阶段4（`01_说明文档区/03_高轨几何问题说明/阶段4_高轨几何到OCS接口设计.md`）的锁定约定**：

```text
sun_direction_I = normalize(r_sun_I - r_sat_I)
```
表示**从卫星指向太阳**的单位向量。

```text
det_direction_I = normalize(r_obs_I - r_sat_I)
```
表示**从卫星指向观测者/探测器**的单位向量。

**理由**：现有代码 `ocs_core.py` 通过以下逻辑筛选可见面元：

```python
dot_sun = np.dot(normals_I, sun_norm)
dot_det = np.dot(normals_I, det_norm)
primary_idx = np.where((dot_sun > 0) & (dot_det > 0))[0]
```

若 `sun_norm` 和 `det_norm` 表示**从卫星/面元指向太阳和观测者**的出射方向，则 `dot > 0` 筛选出法向朝向太阳和观测者的面元（物理正确）。

若传入反向向量（如"太阳→卫星"或"观测者→卫星"），可见面筛选会整体错误，OCS 和最亮姿态均会偏离。

**从外部工具（如 STK）提取数据时**：必须在接口层完成上述转换，确保输入向量符合"卫星→太阳"和"卫星→观测者"约定。

### 2.2 相位角定义

相位角由太阳方向和观测方向的夹角确定：

```text
phase_angle_deg = arccos(dot(sun_direction_I, det_direction_I)) × 180/π
```

其中两向量均**以卫星为起点**（即"卫星→太阳"和"卫星→观测者"）。

**物理含义**：
- `phase_angle = 0°`：观测者与太阳同向（满相/后向散射，卫星受照面与可见面高度重合）
- `phase_angle = 90°`：观测者与太阳垂直
- `phase_angle = 180°`：观测者与太阳反向（背光/前向散射弱区，卫星受照面与可见面高度分离）

**相位角与亮度的一般规律**：
- **小相位角（< 30°，后向散射方向）**：通常较亮，因受照面与可见面重合度高
- **中相位角（30°–90°）**：亮度随材料 BRDF 和姿态变化
- **大相位角（> 120°，前向散射弱区）**：通常较暗，因受照面与可见面重合度低

### 2.3 坐标系定义（继承阶段4）

**惯性坐标系 I（Inertial Frame）**：
- 固定的参考坐标系，用于表达太阳方向、观测方向、卫星姿态
- 候选：ECI（地心惯性系，J2000）或用户自定义固定参考系
- `sun_direction_I` 和 `det_direction_I` 始终在 I 系表达

**本体坐标系 M（Body Frame）**：
- 固连于卫星 STL 模型的坐标系
- STL mesh 顶点、法向、三角形中心均在 M 系表达
- 代码中 mesh 始终保持在 M 系，不做复制或变换

**坐标系转换**：
```text
卫星姿态（yaw, pitch, roll）→ 旋转矩阵 R（M→I）
太阳/探测器方向（I 系）→ 反向变换到 M 系 → 射线查询
```

## range_km与星等后处理边界

### 3.1 核心原则（继承阶段4与A1）

**距离 `range_km` 仅用于星等换算后处理，不进入 OCS 积分。**

### 3.2 理由

现有 OCS 代码（`ocs_core.py`）计算的是：

```text
OCS = Σ_f  A_f · s² · f_r · (N·L) · (N·V)
```

这是一个与距离无关的**几何-材料属性**，量纲为面积（条件性，见 A1 §1.3）。

星等换算公式（A1 审计，候选公式 A）：

```text
m = m_sun - 2.5 log10(OCS / R²)
```

距离 `R` 只在星等换算时作为分母出现。

### 3.3 实施规则

1. **OCS 积分模块**（`ocs_core.compute_single_attitude`）**不接受** `range_km` 参数
2. **星等换算在 A9 后处理模块独立完成**：
   - 若采用太阳星等口径（候选公式 A）：`m = m_sun - 2.5 log10(OCS / R²)`
   - 若采用标定常数口径（候选公式 B）：`m = K_cal - 2.5 log10(OCS) + 5 log10(R)`
3. **几何矩阵中 `range_km` 字段**：作为元数据记录，不参与 OCS 搜索目标函数

### 3.4 典型距离量级

| 轨道类型 | 轨道高度 h | 典型 slant range R | 说明 |
|---|---|---|---|
| GEO | ≈ 35,786 km | ≈ 36,000 ~ 42,000 km | 实际 slant range 需由观测站-卫星几何计算 |
| LEO | ≈ 500 km | ≈ 500 ~ 2,000 km | 依赖观测站-卫星仰角 |

**GEO 场景量级估算**（阶段2复用）：
- 若不做精确轨道计算，可取 `R ≈ 36,000 km` 作为 GEO 近天顶观测的量级近似
- 必须标注为近似，实际 slant range 依赖观测站经纬度、卫星星下点和仰角

## 几何搜索空间粗扫设计

### 4.1 设计原则

采用"粗到细"的分级搜索策略：

1. **基础相位角粗扫（G1 集合）**：覆盖小/中/大相位角，定位亮度峰出现在哪些相位角族
2. **观测方位变体（可选扩展）**：在同一相位角下设置少量方位族，避免只在一个平面内搜索
3. **条件加密（G2 集合，预留）**：当 G1 某相位角显示强峰时，再在相邻相位角局部加密
4. **旧五几何对照标签**：保留 phase24/45/63/90/120 作为旧预实验对照，但不作为 G1 完整集合

### 4.2 G1 基础相位角粗扫集合

**目标**：用 10-15 个相位角点覆盖 0°–180° 范围，弥补旧五几何的采样缺陷。

**推荐采样方案 G1-A**（12 个相位角）：

| 编号 | 相位角 | 区间 | 覆盖意义 |
|---|---|---|---|
| g01 | 0° | 极小相位角 | 满相/后向散射峰值（文献常见最亮方向） |
| g02 | 15° | 小相位角 | 后向散射过渡 |
| g03 | 30° | 小-中过渡 | 补充旧五几何遗漏区间（24°-45° 之间） |
| g04 | 45° | 中相位角 | 旧五几何 phase45 对照点 |
| g05 | 63° | 中相位角 | 旧 phase63 对照点，保留当前已知预实验关键几何 |
| g06 | 75° | 中-大过渡 | 补充旧五几何遗漏区间（63°-90° 之间） |
| g07 | 90° | 垂直观测 | 旧五几何 phase90 对照点 |
| g08 | 105° | 大相位角 | 补充旧五几何遗漏区间（90°-120° 之间） |
| g09 | 120° | 大相位角 | 旧五几何 phase120 对照点 |

| g02 | 30° | 小-中过渡 |

| g05 | 90° | 旧 phase90 对照 |

**A3 推荐**：优先采用 G1-A（12 点），若计算预算不足再退化为 G1-B（8 点）。

### 4.3 观测方位变体设计（可选扩展，预留）

**问题**：旧五几何和 G1 集合只定义了相位角，但同一相位角下可以有多个太阳-观测方向组合（通过旋转观测方位实现）。

**示例**：phase = 63° 可对应：
- 太阳在 +X，观测者在 XY 平面内与太阳夹角 63°
- 太阳在 +X，观测者在 XZ 平面内与太阳夹角 63°
- 太阳在任意方向，观测者与太阳夹角保持 63° 但方位角不同

**是否需要方位变体**：
- 若卫星具有方位对称性（如圆柱体、球体），方位变体影响较小
- 若卫星具有强方位不对称性（如太阳能板只在 ±Y 方向伸出），方位变体可能导致 OCS 显著差异

**推荐处理**：
- **G1 阶段不引入方位变体**，每个相位角只设置一个代表方向组合（如太阳在 +X 方向，观测者在 XY 平面内）
- 若 A6/A7 发现某相位角下 OCS 对姿态（yaw/pitch/roll）极度敏感，怀疑是方位不对称导致，再在 A7 预留的"新几何实施计划"中考虑方位变体

### 4.4 太阳-观测方向的具体构造

**方案 A：固定太阳方向，旋转观测方向**（推荐）

固定太阳方向为惯性系 +X：
```text
sun_direction_I = [1.0, 0.0, 0.0]
```

观测方向在 XY 平面内旋转，相位角由 `det_direction_I` 与 `sun_direction_I` 的夹角确定：
```text
det_direction_I = [cos(phase), sin(phase), 0.0]
```

**优点**：
- 太阳方向固定，便于结果对比
- 观测方向参数化清晰
- 所有几何在同一平面内，便于可视化

**方案 B：太阳与观测方向对称分布**

太阳方向和观测方向关于 +X 轴对称：
```text
sun_direction_I = [cos(phase/2), sin(phase/2), 0.0]
det_direction_I = [cos(phase/2), -sin(phase/2), 0.0]
```

**优点**：
- 对称性好，适合理论分析
- 卫星姿态不变时，太阳和观测者的相对位置更均衡

**A3 推荐**：采用方案 A（固定太阳方向），因为简洁且便于与旧五几何对照。

### 4.5 G2 条件加密集合（预留，不在 A3 固化）

**触发条件**（由 A6/A7 判断）：
- G1 粗扫显示某相位角 α 处 OCS 显著高于相邻点
- 怀疑 α ± 15° 范围内存在更强的峰值
- 需要局部加密采样

**加密策略**：
- 在 α - 15° 到 α + 15° 之间，以 5° 或 3° 步长加密
- 或在 top-K 相位角附近各加 ±5°、±10° 四个点

**示例**：
- 若 G1 显示 phase = 63° 最亮，G2 加密为：48°, 53°, 58°, 63°, 68°, 73°, 78°
- 若 phase = 0° 显示强峰，G2 加密为：0°, 5°, 10°, 15°（单侧加密，因为 phase < 0° 无物理意义）

**决策权**：留给 A7"新几何/roll 实施计划"，不在 A3 固化具体数值。

## 几何矩阵字段规范

## 对A4姿态搜索的约束

### 7.1 A4 必须接受的几何字段

A4 设计姿态搜索方案时，必须能处理 A3 定义的几何字段：

| 字段 | A4 如何使用 |
|---|---|
| `phase_angle_deg` | 选择对应相位角的姿态扫描结果 |
| `sun_direction_I` | 传入 OCS 代码的 SUN_VECTOR 输入 |
| `det_direction_I` | 传入 OCS 代码的 DET_VECTOR 输入 |
| `range_km` | 传入 A9 星等换算公式（不进入 OCS 积分） |

### 7.2 几何与姿态的独立性

**A3 定义几何空间**：G1 集合（12 个相位角）

**A4 定义姿态搜索策略**：
- yaw/pitch 粗扫（继承旧 5° 网格）
- roll 扫描（0°–360°，步长由 A4 决定）
- 局部细化（top-K 附近 1°–2° 步长）

**组合爆炸控制**：
- **不要求**对每个 G1 几何都做全姿态扫描
- **推荐策略**：先在 1-2 个代表几何下做全姿态扫描（如 phase = 0°/63°），找到 top-K 候选；再在其他几何下只扫描 top-K 候选姿态附近的局部区域

**计算预算估算**：
- 若 G1 有 12 个几何，每个几何做 yaw73×pitch37×roll1 = 2701 点，总计 12×2701 = 32,412 次 OCS 计算
- 若每次 OCS 计算耗时 ~1 秒（fast 精度），总计约 9 小时
- 若加入 roll 扫描（36 个 roll），每个几何 2701×36 = 97,236 点，总计 12×97,236 = 1,166,832 次，约 324 小时（不可行）

**结论**：A4 必须设计分级搜索策略，不能对所有几何×所有姿态做笛卡尔积全扫描。

### 7.3 A3 不固化的内容（留给 A4）

以下内容**不在 A3 固化**，由 A4 根据计算预算和分析需求决定：

| 内容 | A3 态度 | A4 决策权 |
|---|---|---|
| 具体 roll 角度数量 | 不固定 | A4 可选 36/73/其他 |
| 具体 top-K 值 | 不固定 | A4 可选 K=10/20/50 |
| 局部加密步长 | 不固定 | A4 可选 0.5°/1°/2° |
| 哪些几何做全姿态扫描、哪些做局部扫描 | 不固定 | A4 根据 G1 初步结果决定 |

## 关键结论

### 8.1 几何搜索空间定义

**核心字段**（必需）：
- `phase_angle_deg`：太阳-目标-观测者夹角（0°–180°）
- `sun_direction_I`：从卫星指向太阳的单位向量（惯性系 I）
- `det_direction_I`：从卫星指向观测者的单位向量（惯性系 I）
- `range_km`：卫星到观测者斜距（仅用于星等换算，不进入 OCS 积分）

**方向向量物理含义锁定**（继承阶段4）：
```text
sun_direction_I = normalize(r_sun_I - r_sat_I)  # 卫星 → 太阳
det_direction_I = normalize(r_obs_I - r_sat_I)  # 卫星 → 观测者
```

### 8.2 G1 基础粗扫集合

**推荐方案 G1-A**（12 个相位角）：
- 0°, 15°, 30°, 45°, 63°, 75°, 90°, 105°, 120°, 135°, 150°, 165°
- 覆盖小/中/大相位角，弥补旧五几何遗漏区间
- 包含旧 phase45/63/90/120 对照点（不含 phase24，因 G1 已有 0°/15°/30° 覆盖小相位角）

**简化方案 G1-B**（8 个相位角）：
- 0°, 30°, 45°, 63°, 90°, 120°, 135°, 150°
- 若计算预算受限可采用

### 8.3 旧五几何定位

**角色**：对照基准，不是 G1 主集合

**证据边界**：
- ✅ face-center 口径相对排序预实验
- ❌ 不与 G1 新几何（若采用 pixel-level 口径）直接混表
- ❌ 不作为小项目最终结论的 OCS 数值来源

### 8.4 距离使用规则

- `range_km` **仅用于星等换算后处理**，不进入 OCS 积分
- GEO 量级近似：R ≈ 36,000 km（实际 slant range 需由观测站-卫星几何计算）

### 8.5 对 A4 的约束

- A4 必须能处理 A3 定义的几何字段（phase_angle, sun_direction_I, det_direction_I, range_km）
- A4 不能对所有几何×所有姿态做笛卡尔积全扫描（组合爆炸）
- A4 必须设计分级搜索策略（粗扫 → roll 扫描 → 局部细化）
