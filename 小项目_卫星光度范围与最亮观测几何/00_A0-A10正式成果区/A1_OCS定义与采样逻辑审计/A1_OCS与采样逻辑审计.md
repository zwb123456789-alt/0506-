## OCS定义与可用边界

### 1.1 OCS 的数学形式

根据原项目 `ocs_core.py` 第 78 行、第 101 行，OCS 积分的核心公式为：

```python
ocs = sum( areas_PI * scale_sq * brdf_vec * cos_i_vec * cos_r_vec )
```

展开为数学形式：

```
OCS = Σ_f  A_f · s² · f_r(N_f, L, V) · (N_f · L) · (N_f · V)
```

其中：
- `A_f`：面元 f 的面积（STL 原始单位，mm²）
- `s` = `UNIT_SCALE` = 1e-3（mm → m 转换因子）
- `s²` = 1e-6（面积从 mm² → m²）
- `f_r`：BRDF 值（单位 sr⁻¹）
- `N_f · L`：面元法向与太阳方向的余弦（cos_i）
- `N_f · V`：面元法向与观测方向的余弦（cos_r）
- 求和仅对满足 `(N·L > 0) & (N·V > 0)` 的面元（双面可见）

### 1.2 OCS 的物理含义

从辐射度学出发：

```
E_obs = Σ_f  E_sun · f_r(N_f, L, V) · cos_i_f · cos_r_f · (A_f / R²)
```

整理得：

```
E_obs / E_sun = [Σ_f  A_f · f_r · cos_i · cos_r] / R² = OCS_code / R²
```

因此代码计算的 `OCS_code` 在物理上对应：

```
OCS_code = E_obs · R² / E_sun
```

### 1.3 OCS 在小项目中的定义

**定义**：OCS 是模型计算得到的散射指标，表示在给定太阳方向、观测方向和卫星姿态下，目标对太阳光的有效散射能力。

**物理量纲**：按当前代码定义，具有面积量纲（条件性）

**可用边界**：

| 用途 | 可用性 | 条件 |
|---|---|---|
| **相对排序** | ✅ 可靠 | 同一代码、同一 BRDF、同一 `UNIT_SCALE` |
| **部件贡献比较** | ✅ 可靠 | per-part OCS 占比 |
| **相对星等差 Delta m** | ✅ 可靠 | 见 §2 |
| **带面积单位使用** | ⚠️ 谨慎 | 需确认：STL 单位确为 mm、BRDF 物理形式正确、mesh 精度足够 |
| **绝对视星等估算** | ❌ 推迟至 A9 | 需距离、K_cal/m_sun、波段口径、标定确认 |

**关键判定**：

根据原项目阶段1审计（`02_OCS_光度换算标准/阶段1_OCS定义与星等公式审计.md`），当前 GGX BRDF 实现采用标准 Cook-Torrance 镜面项和 Lambert 漫反射项，在 nominal 参数下可作为物理近似使用。但：

1. **严格能量守恒未做半球积分审计**（例如电介质 diffuse 项未乘 `(1-F)`）
2. **STL 单位是否确实是 mm 未经独立验证**
3. **BRDF 参数（F0、roughness、ior）为名义值，未经真实材料标定**
4. **遮挡语义**：原模块 A 使用 face-center 采样，与图像 pixel-level 采样口径不统一

**结论**：OCS 可作为方向性散射指标使用，具有明确的相对排序能力和部件贡献分辨能力。是否可直接带面积单位 m²，需在标注上述条件的前提下谨慎使用。绝对标定必须推迟到 A9 情景估计。

### 1.4 OCS 不是什么

| 误解 | 澄清 |
|---|---|
| "OCS 等于真实卫星 RCS" | RCS 通常指雷达截面；OCS 是光学散射截面，概念不同 |
| "OCS 单位已确认为 m²" | 单位正确依赖于 STL 比例尺和 BRDF 参数，两者均未独立验证 |
| "OCS 可直接换算真实卫星绝对星等" | 绝对星等需要距离、波段、太阳星等、标定常数，当前均未确定 |
| "不需要标定即可给出绝对星等" | 即使公式正确，BRDF 参数和 STL 比例尺仍需验证 |

## Delta m相对星等差审计

### 2.1 公式形式

```text
Delta m = -2.5 log10(OCS_2 / OCS_1)
```

### 2.2 适用条件

**必须满足**：

1. **同一代码**：两个 OCS 来自同一 OCS 计算链路（同一 `ocs_core.py`、同一 `UNIT_SCALE`）
2. **同一 BRDF**：两个 OCS 使用同一 BRDF 模型和参数（如均为 GGX）
3. **同一口径**：两个 OCS 使用同一采样口径（均为 face-center 或均为 pixel-level）

**物理依据**：

```
Delta m = m_2 - m_1 
        = -2.5 log10(E_obs_2 / E_obs_1)
        = -2.5 log10((OCS_2/R_2²) / (OCS_1/R_1²))
```

若两观测距离相同（R_2 = R_1），则：

```
Delta m = -2.5 log10(OCS_2 / OCS_1)
```

距离、太阳星等 m_sun、波段响应、标定常数 K_cal 全部约掉。

**若比较高轨时间序列（不同时间、不同距离）**：

```
Delta m_obs = -2.5 log10(OCS_2 / OCS_1) + 5 log10(R_2 / R_1)
```

### 2.3 不能跨口径混算

**关键约束**：旧五几何（phase24/45/63/90/120）的 OCS 数据来自原模块 A 的 face-center 采样，与后续 pixel-level 口径不统一。

**禁止操作**：
- ❌ 不能把 face-center 口径的 OCS 与 pixel-level 口径的 OCS 直接比较
- ❌ 不能把旧五几何的 OCS 最大值与新几何/roll 扫描的 OCS 直接排序
- ❌ 不能把旧五几何的 Delta m 与新几何的 Delta m 混入同一表格

**允许操作**：
- ✅ 在旧五几何内部做相对排序（同一口径）
- ✅ 在新几何/roll 扫描内部做相对排序（同一口径）
- ✅ 分别标注口径，做定性趋势对比（但不做定量混表）

**原因**：face-center 采样将每个三角形面的可见性简化为面心可见性，pixel-level 采样则对每个像素做精确光线追踪，二者的遮挡语义和采样精度不同，导致 OCS 数值可能存在系统性偏差。

### 2.4 可信度判定

**相对星等差 Delta m 的可信度：✅ 可靠**

前提：同一代码/BRDF/UNIT_SCALE/口径。

已有结果示例（旧 phase63，face-center 口径，仅作预实验）：
- Delta m(最亮/中位) = -7.948 mag（最亮姿态比中位姿态亮约 7.948 mag）
- Delta m(最亮/最暗) = -9.559 mag（最亮姿态比最暗姿态亮约 9.559 mag）

**注意**：上述数值来自旧口径预实验，不能直接作为小项目最终结论。

## 绝对视星等与A9情景估计边界

### 3.1 为什么绝对视星等必须推迟到 A9

**候选公式 A**：

```
m = m_sun - 2.5 log10(OCS / R²)
```

**需要确认的前提条件**：

| 编号 | 待确认内容 | 当前状态 | 阻塞哪些阶段 |
|---|---|---|---|
| C1 | STL 模型是否为 1:1 真实卫星尺寸 | ❌ 未确认 | A9 |
| C2 | GGX BRDF 参数（F0、roughness、ior）是否匹配真实材料 | ❌ 未确认 | A9 |
| C3 | 观测波段确定（V/R/宽带？） | ❌ 未确认 | A2/A9 |
| C4 | 太阳星等 m_sun 口径 | ❌ 未确认 | A2/A9 |
| C5 | 是否需要大气消光修正 | ❌ 未确认 | A9 |
| C6 | 是否确认 OCS 物理定义满足 `E_obs / E_sun = OCS / R²` | ⚠️ 条件性 | A9 |

**C1-C6 均不阻塞相对星等差（Delta m）的使用和部件贡献排序。**

**候选公式 B**（最保守形式）：

```
m = K_cal - 2.5 log10(OCS) + 5 log10(R)
```

其中 `K_cal` 为标定常数，吸收 m_sun 和其他未知因子。需要通过文献中已知卫星在已知距离/相位角下的星等来标定。

### 3.2 A9 情景估计的定位

A9 阶段将在相对结果闭合后，给定 R 与 K_cal/m_sun 口径做**情景估计**：

- 明确标注"情景估计"，不冒充实测
- 必须声明假设：STL 为真实尺寸、GGX 参数为名义值、未做真实标定
- 仅作量级参考，用于与 A2 调研的常规卫星光度范围（11-15 mag）做 sanity check
- 不作为小项目最终结论的核心证据

### 3.3 绝对视星等公式不适用形式

| 禁止公式 | 原因 |
|---|---|
| `m = m_sun - 2.5 log10(OCS / (4πR²))` | 本代码 directional OCS 不应额外除以 `4π`；但与外部文献对接时需核查其 OCS/相位函数定义 |
| `m = -2.5 log10(OCS)` （无距离项） | 缺少距离 R，不能给出视星等 |
| `m = K_cal - 2.5 log10(OCS / R)` （R 的幂次错误） | 应为 `5 log10(R)` 而非 `2.5 log10(R)` |

## 旧采样逻辑问题

### 4.1 姿态采样问题

**问题 1：yaw/pitch 欧拉网格不是均匀三维姿态采样**

当前姿态网格：
- yaw: 0°–360°，步长 5°，共 73 个点
- pitch: -90°–90°，步长 5°，共 37 个点
- roll: 固定为 0°

这是欧拉角的笛卡尔网格，不等价于三维旋转空间（SO(3)）的均匀采样。具体问题：

| 问题 | 影响 |
|---|---|
| pitch 接近 ±90° 时，yaw 变化对姿态的实际影响趋近于零（万向节死锁效应） | pitch = ±90° 附近的 73 个 yaw 值几乎对应同一姿态，导致采样冗余 |
| pitch = 0° 附近，yaw 步长对应的姿态变化较大 | 可能遗漏 pitch = 0° 附近的精细结构 |
| 不同 pitch 下，相同 yaw 步长对应的姿态空间覆盖密度不同 | 采样密度不均匀，无法保证"每 N° 覆盖一次姿态球" |

**结论**：yaw×pitch 网格可用于粗筛，但不能声称"均匀覆盖三维姿态空间"。

**问题 2：yaw=0° 与 yaw=360° 重复**

当前 yaw 网格：0, 5, 10, ..., 355, 360（共 73 个点）

yaw=0° 与 yaw=360° 对应同一姿态，导致重复计算。正确做法应为 yaw: 0, 5, 10, ..., 355（共 72 个点，不含 360°）。

**影响**：
- 计算浪费（yaw=0° 与 yaw=360° 的 OCS 完全相同）
- 统计分析时可能重复计数（如做 yaw 方向平均时）

**问题 3：roll 固定为 0，不能覆盖三自由度姿态**

roll 维度完全缺失，导致：

| 遗漏场景 | 示例 |
|---|---|
| 太阳能板法向需要通过 roll 旋转才能对齐太阳-观测角平分方向 | 太阳能板 glint 可能只在特定 roll 值触发 |
| 金属主体的某些曲面需要通过 roll 旋转才能实现镜面反射条件 | 金属主体 specular 峰可能在 roll≠0 处更强 |
| 三自由度姿态搜索的全局最亮点可能在 roll≠0 | 当前 roll=0 的最亮姿态不能保证是三维空间的全局最亮 |

**结论**：roll=0 的二维姿态切片只能作为预实验，不能回答"三维姿态空间的最亮条件"。A4 必须设计 roll 扫描。

### 4.2 几何采样问题

**问题 4：五个旧几何不是完整太阳-目标-观测几何空间**

旧五几何（phase24/45/63/90/120）是代表性抽象方向，不是连续相位角采样：

| 旧几何 | 相位角 | 覆盖不足 |
|---|---|---|
| phase24 | 24° | 缺少后向散射方向（phase < 24°），可能遗漏小相位角最亮条件 |
| phase45 | 45° | |
| phase63 | 63° | 缺少 phase45–phase90 之间的中间角度 |
| phase90 | 90° | |
| phase120 | 120° | 缺少前向散射方向（phase > 120°） |

**影响**：
- 最亮相位角可能出现在五几何之间的某个中间值
- 极窄的 glint 或 specular 峰（FWHM < 15°）可能被离散采样跳过
- 不能回答"什么相位角下最亮"，只能回答"五几何中哪个最亮"

**问题 5：五几何不能自然对应真实高轨观测**

五几何只定义了抽象的太阳方向和观测方向（惯性系单位向量），缺少：

| 缺失字段 | 影响 |
|---|---|
| `range_km`（卫星到观测者的斜距） | 无法做绝对星等换算（即使有公式也缺距离输入） |
| 观测站经纬度、卫星星下点 | 不能映射到真实观测场景 |
| 太阳历时刻、轨道时间 | 不能对应真实高轨时间序列 |
| 地影标记 | 不知道卫星是否在地影中（地影期间 OCS=0） |

**结论**：五几何只能作为预实验几何抽象，不能直接声称"GEO 卫星在某观测条件下最亮"。A3 必须设计包含 `range_km`、相位角、太阳方向、观测方向的完整几何搜索空间。

### 4.3 口径问题

**问题 6：五几何 face-center 旧口径不能与后续 pixel-level 结果直接混表**

根据 v0.4 项目定位，旧模块 A 的 OCS 数据使用 face-center 采样（将每个三角形面的可见性简化为面心可见性），与图像 pixel-level 采样口径不统一。

**具体差异**：

| 采样口径 | 可见性判断 | 遮挡语义 | 数据来源 |
|---|---|---|---|
| face-center（旧） | 以三角形面心为采样点 | 面心可见 = 整个面可见 | 旧模块 A 扫描表 |
| pixel-level（新） | 每个像素做精确光线追踪 | 像素级遮挡，一个面可能部分可见 | Blender-derived OCS（v0.4 方法） |

**影响**：
- face-center 可能高估或低估遮挡率（取决于面的大小和遮挡边缘位置）
- 两种口径的 OCS 数值可能存在系统性偏差
- 不能把旧五几何的 OCS 最大值与新几何/roll 扫描的 OCS 直接排序

**A6 预实验复核的定位**：
- 旧五几何只能作为 face-center 口径的相对排序预实验
- 可以做旧五几何内部的相对比较（同一口径）
- 可以做定性趋势对比（哪个相位角更亮、哪个部件主导）
- 不能与后续新几何/roll 的 pixel-level 结果直接混表

## face-center旧口径与pixel-level口径边界

### 5.1 两种口径的技术差异

**face-center 口径**（旧模块 A）：
- 遮挡判断：以三角形面心为采样点，做一次射线查询
- 若面心可见，则整个面的 OCS 贡献计入；若面心被遮挡，则整个面的 OCS 贡献为 0
- 优点：计算快，适合大规模姿态扫描
- 缺点：遮挡边缘处理粗糙，可能高估或低估可见面积

**pixel-level 口径**（新方法，v0.4）：
- 遮挡判断：对每个像素做精确光线追踪（depth pass + visibility pass）
- 一个三角形面可能部分可见、部分被遮挡
- 优点：遮挡语义精确，与图像成像通道共享同一物理前向模型
- 缺点：计算慢，不适合超大规模姿态扫描

### 5.2 A6 预实验复核的使用原则

**允许操作**：
- ✅ 在旧五几何内部做相对排序（phase24/45/63/90/120 中哪个最亮）
- ✅ 分析旧五几何的部件贡献趋势（金属主体 vs 太阳能板在不同相位角的占比）
- ✅ 验证旧脚本的正确性（能否复现旧结果）
- ✅ 作为 A4 姿态搜索方案的启发（哪些姿态区间值得细扫）

**禁止操作**：
- ❌ 把旧五几何的 OCS 最大值作为小项目最终结论
- ❌ 把旧五几何的绝对星等估算作为小项目最终结论
- ❌ 把旧五几何的 OCS 与新几何/roll 的 OCS 直接混入同一排序表
- ❌ 声称"旧五几何的最亮姿态即为全局最亮"

### 5.3 口径统一的长期方向

小项目当前不强制要求口径统一（A6 可以只读旧数据做预实验复核），但如果后续需要口径统一的 OCS 数据：

**方案 A**：用 Blender-derived 方法重跑旧五几何（pixel-level 口径）
**方案 B**：只用新几何/roll 的 pixel-level 数据，旧五几何只作历史参考

决策留给作者确认，不在 A1 阶段固化。

|---|---|---|---|
| `phase_angle_deg` | float | 太阳-目标-观测者夹角 | 选择对应相位角的 OCS 结果 |
| `sun_direction_I` | array[3] | 惯性系下**从卫星指向太阳**的单位向量 | OCS 代码的 SUN_VECTOR 输入 |
| `det_direction_I` | array[3] | 惯性系下**从卫星指向观测者**的单位向量 | OCS 代码的 DET_VECTOR 输入 |
| `range_km` | float | 卫星到观测者的斜距（千米） | **仅用于星等换算**，不进入 OCS 积分 |

**方向向量物理含义锁定**（继承阶段4）：

```
sun_direction_I = normalize(r_sun_I - r_sat_I)  # 卫星 → 太阳
det_direction_I = normalize(r_obs_I - r_sat_I)  # 卫星 → 观测者
```

**理由**：现有代码 `ocs_core.py` 通过 `dot(normals_I, sun_norm) > 0` 筛选可见面元，若传入反向向量会导致可见面筛选整体错误。

**距离使用规则**（继承阶段4）：

- 距离 `range_km` **仅用于星等换算后处理**，不进入 OCS 积分
- OCS 积分模块不接受 `range_km` 参数
- 星等换算在后处理模块独立完成：A9 若采用太阳星等口径，可在前提满足时使用 `m = m_sun - 2.5 log10(OCS / R²)`；否则采用 `m = K_cal - 2.5 log10(OCS) + 5 log10(R)` 的标定常数形式。

**相位角覆盖要求**：

- A3 不能只沿用旧五几何（24°/45°/63°/90°/120°）
- 应设计多相位角粗扫（如每 15° 一个点）或条件加密策略
- 至少补充后向散射方向（phase < 24°）和前向散射方向（phase > 120°）的代表点

### 6.2 对 A4 三维姿态搜索方案的约束

**必须处理的维度**：

1. **yaw/pitch 粗扫**：继承旧网格（5° 步长）作为第一轮粗筛
2. **roll 扫描**：必须引入 roll 维度，覆盖 0°–360°
3. **局部细化**：对 top-K 候选做局部加密（1°–2° 步长）

**不在 A1 固化的内容**：

- **具体 roll 角度数量**：不固定为 73 个，由 A4 根据计算预算决定（可以是 36 个、73 个或其他）
- **具体 top-K 值**：不固定 K=10 或 K=20，由 A4 根据存储和分析能力决定
- **局部加密步长**：不固定为 1°，可以是 0.5°、1° 或 2°，由 A4 决定

**A1 只约束逻辑结构**：

```
Step 1: 粗筛（yaw×pitch，roll=0）
Step 2: roll 扫描（对 top-K 候选，扫描 roll 0°–360°）
Step 3: 局部加密（对 roll 扫描后仍保持 top-K' 的姿态，做三维局部加密）
```

**避免遗漏的设计原则**：

A4 的 roll 扫描候选集不能只从"总 OCS top-K"出发，必须从**多来源候选并集**出发：

| 候选来源 | 理由 |
|---|---|
| 总 OCS top-K | 保证全局最亮候选 |
| 金属主体 OCS top-K | 保证金属主体最亮点不被遗漏 |
| 太阳能板 OCS top-K | 保证太阳能板最亮点不被遗漏（可能在 roll=0 时不亮但 roll≠0 时 glint） |
| 太阳能板占比 top-K | 保证太阳能板主导的姿态不被遗漏 |

**理由**：roll=0 时总 OCS 最高的姿态，可能在 roll≠0 时不再最亮；但某个部件在 roll=0 时 OCS 不高的姿态，可能在 roll≠0 时因 glint 而成为该部件的最亮点。

## 不能支持的结论

基于当前 OCS 定义与采样逻辑审计，以下结论**不能支持**：

| 编号 | 不可下的结论 | 原因 |
|---|---|---|
| N1 | "OCS 输出单位已确认为 m²" | 单位正确依赖于 STL 比例尺和 BRDF 参数，两者均未独立验证 |
| N2 | "绝对视星等公式已确定" | 需要距离、波段、太阳星等、标定常数，当前均未确定 |
| N3 | "旧五几何的最亮姿态即为全局最亮" | 五几何是离散采样，roll=0 是二维切片，不保证全局最亮 |
| N4 | "旧五几何的 OCS 可与新几何/roll 的 OCS 直接混表" | face-center 口径与 pixel-level 口径不统一 |
| N5 | "yaw×pitch 5° 网格均匀覆盖三维姿态空间" | 欧拉角笛卡尔网格不等价于 SO(3) 均匀采样，且 roll=0 缺失 |
| N6 | "不需要标定即可给出绝对星等" | 即使公式正确，BRDF 参数和 STL 比例尺仍需验证 |
| N7 | "五几何足以回答'什么相位角最亮'" | 只能回答"五几何中哪个最亮"，不能回答连续相位角的全局最亮 |
| N8 | "当前三材料足以覆盖所有真实卫星表面" | OSR 散热面、天线反射面、MLI 的 BRDF 超出当前覆盖范围 |
