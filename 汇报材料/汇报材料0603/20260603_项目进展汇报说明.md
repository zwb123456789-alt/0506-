## 4. 关键口径

- clean rendered image 是理想图像上界，不代表真实外场性能。
- OCS 不是 clean image 条件下的性能上限来源；其价值在于低维、可解释、多观测几何和对图像像素退化不敏感。
- fusion 是条件性互补：干净图像下主要体现为边际和尾部增益，退化观测下价值更明显。
- 当前工作没有真实光学望远镜验证，应表述为 physically consistent simulation and controlled inversion study。
- `all_raw` 只能作为 semi-oracle diagnostic representation，不能写成实际可操作特征。

### 7.5 研究价值与关键创新页

建议标题：

```text
研究价值：从“能反演”到“知道何时可信”
```

建议副标题：

```text
建立 OCS-光度图像联合姿态反演的可验证评估框架
```

前沿现状与问题口径：

```text
已有多源融合研究说明，不同观测信息结合可以提升空间目标状态估计能力。
常见融合形式包括光变 + 测角、光变 + 动力学滤波、图像 + 惯性/星敏感器、图像 + 深度/点云/LiDAR 等。

这些工作说明“多源融合”本身已有研究基础，但它们通常不是在同一套光学散射物理模型下，同时生成 OCS 和光度图像，再比较两者对姿态反演的贡献。
```

本项目解决的核心问题：

```text
本项目不是只追求一个最低误差结果，而是回答一个更接近实际应用的问题：
在不同观测质量下，OCS、光度图像和二者融合分别什么时候可靠。
```

主要创新点：

```text
可信前向模型：
将 OCS 和光度图像放入同一套 STL 几何、材料、GGX BRDF 和自遮挡模型中，保证两类观测来自同一个物理目标，而不是两套彼此独立的仿真假设。
意义：让后续 OCS 与图像对比具有公平基础。

可验证闭环：
通过三端闭合、EXR 几何缓冲和采样差异分析，验证仿真链路不是“能出图”，而是具有可追溯的物理一致性。
意义：提高仿真结果作为姿态反演基准的可信度。

条件性互补结论：
证明融合不是永远最优。理想干净图像下，图像模型给出性能上界；图像退化时，OCS 提供更稳定的约束；某一模态不可靠时，另一模态可提供补偿。
意义：为真实观测中如何选择 OCS、图像或融合策略提供依据。
```

页底总结：

```text
最终目标是让姿态反演结果不仅“算得出来”，而且“知道什么时候可信”。
```

### 7.6 物理一致前向模型必要性页

建议标题：

```text
物理一致前向模型的必要性
```

建议副标题：

```text
为了公平比较 OCS 与图像，而不是比较两套仿真误差
```

不统一模型时的问题：

```text
如果 OCS 和图像分别由两套前向模型生成：

OCS 端可能使用自定义 BRDF、面元中心采样、解析遮挡和一套材料参数；
图像端可能使用 Blender 默认材质、像素级可见性、Cycles 内部反射模型和另一套渲染假设。

这时仍然可以做姿态反演，但很难判断性能差异来自观测信息本身，还是来自仿真假设不同。
```

一致性的作用：

```text
物理一致前向模型本质上是控制变量：

保持一致：
STL 几何、姿态、太阳/探测器几何、材料分区、GGX BRDF、自遮挡模型。

只改变：
观测表达形式——OCS 标量特征或光度图像像素。
```

本项目做法：

```text
剥离 Blender 默认 BRDF，不让黑箱材质决定亮度；
Python 显式计算 GGX BRDF；
OCS 端和图像后处理端调用同一个 BRDF 函数；
Blender 只负责几何可见性和像素级采样；
OCS 端负责多姿态、多观测几何的大规模扫描。
```

强调句：

```text
Blender 负责“看见哪里”，Python 负责“如何反光”，OCS 模块负责“大规模姿态扫描”。
```

页底总结：

```text
先保证 OCS 和图像来自同一个物理世界，后面的反演对比和融合结论才站得住。
```

### 7.7 Blender 几何采样与自定义 BRDF 技术路线页

建议标题：

```text
Blender 几何采样与自定义 BRDF 的技术路线
```

建议副标题：

```text
将 Blender 从“黑箱渲染器”改造成“几何采样器”
```

直接使用 Blender 内置材质的问题：

```text
Blender 内置材质主要服务于视觉真实感渲染，目标是“看起来真实”；
本项目需要的是光学姿态反演，目标是“亮度从哪里来、能否用于姿态估计、误差能否解释”。

仅靠 Blender 内置渲染无法同时输出 OCS 数值、部件贡献、遮挡率、像素级亮度、姿态反演特征和参数敏感性结果。
```

重要表述边界：

```text
不要写“本文 GGX 比 Blender 的 BRDF 更先进”。
更准确的说法是：
Blender Principled BSDF 本身也包含 GGX / 多重散射 GGX 等物理渲染思想，技术上并不落后；
但它是面向视觉渲染和艺术控制的综合材质模型，不适合作为本文 OCS 定量积分和图像亮度后处理的共同物理底座。

本文选择自定义 GGX 的优势不是“绝对更先进”，而是“更适合本文任务”：
公式显式、两端共享、参数可控、可验证、可替换、可做敏感性分析。
```

自定义 BRDF 的技术优势：

```text
公式显式：
GGX/Cook-Torrance 的 D、G、F 三项可逐项说明，可写入论文方法部分。

两端共享：
OCS 端和图像后处理端调用同一个 BRDF 函数，避免两套公式。

参数可控：
金属主体、太阳能板、遮光板使用统一材料参数库，便于敏感性分析。

可更新：
后续可扩展各向异性 BRDF、多光谱 BRDF、材料老化模型，而不被 Blender 当前材质系统固定。

计算高效：
同一批 EXR 几何缓冲可反复用于不同 BRDF、不同材料参数和不同敏感性实验，不需要每次重新渲染。
```

文献支撑口径：

```text
Cook-Torrance / microfacet 模型是粗糙表面反射建模的经典物理框架；
GGX / Trowbridge-Reitz 分布是常用的微表面法线分布形式，适合表达长尾镜面反射；
Disney Principled BSDF 的设计目标强调物理合理性、简单性、鲁棒性和艺术控制。

因此，本文不是否定 Blender 内置材质，而是将其从“最终亮度计算黑箱”中剥离出来，
改用显式 GGX/Cook-Torrance 作为 OCS 与图像共同的、可审计的散射模型。
```

可引用文献/资料：

```text
Cook and Torrance, 1982, A Reflectance Model for Computer Graphics.
Walter et al., 2007, Microfacet Models for Refraction through Rough Surfaces. 该文系统讨论 microfacet theory，并引入 GGX 分布。
Burley, 2012, Physically-Based Shading at Disney. 该文说明 Disney/Principled 类模型面向生产渲染，在物理合理性与艺术控制之间折中。
Blender Manual, Principled BSDF. 用于说明 Blender 内置材质是综合型 shader，而非本文可直接共享到 OCS 积分中的显式公式模块。
```

OCS 借鉴 Blender 像素级采样逻辑的原因：

```text
传统 OCS 面元中心采样速度快，适合大规模姿态扫描；
但对于 GGX 金属窄镜面峰和复杂几何，一个面元中心点可能错过局部高光。

Blender 的像素级光栅化和深度测试可以提供更细的可见区域采样，
帮助分析 face-center 与 pixel-level 采样差异。
```

页底总结：

```text
直接用 Blender 能生成图像；拆解 Blender 并自定义 BRDF，才能生成可验证、可解释、可用于姿态反演的物理观测数据。
```

### 7.8 面元中心采样与像素级采样差异诊断页

面元中心采样与像素级采样的差异诊断
```

建议副标题：

真实卫星复杂几何下，面元中心采样会低估窄镜面峰
```

页面目的：

```text
解释为什么 OCS 端需要关注 Blender 的像素级采样逻辑，而不是只依赖传统面元中心积分。
```

结果展示口径：

```text
在真实三件套卫星模型上，模块 A 的面元中心 OCS 与 Blender EXR 像素级后处理 OCS 曾出现明显差异。

最典型姿态：
yaw = 150°, pitch = -80°

模块 A 面元中心采样：
OCS_A_with_occ ≈ 0.0163
OCS_A_no_occ ≈ 0.0766

两者相差不是由 BRDF 公式错误、法线坐标错误或网格精度不足导致。
```

关键诊断：

```text
1. 几何精度假说被排除
   A_fast 与 A_full 的 no_occ 结果差异仅约 0.2%，说明增加面元数量没有解决问题。

2. 窄镜面峰采样问题被确认
   A 端面元中心采样在该姿态下镜面贡献约为 0；
   B 端像素级采样捕获到强镜面峰，镜面贡献约占 87%。

3. 可见性语义存在差异
   diffuse-only 下 A/B 仍有约 26% 差异，说明复杂几何中 ray-cast face-center 与 camera rasterization 的可见性判定并不完全等价。
```
