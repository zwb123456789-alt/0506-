# 文件夹管理规则

最后更新：2026-06-08

## 1. 总原则

旧版本只封存，不删除、不移动、不覆盖。新版本新增独立目录，并通过总控文件记录入口。

当前 v0.4 项目与论文定位已经冻结，根目录只主动保留两份主线文件：

```text
24_v0.4项目论文主线最终冻结稿_OCS口径形态与mismatch账面对齐版.md
25_v0.4主线冻结原因备案_为什么采用24号.md
```

其中 24 号是当前项目与论文主线 source-of-truth，25 号是原因备案与来源索引。15-23 号历史定位稿已经归档到：

```text
99_归档索引/03_v0.4定位历史稿归档_15-23/
```

后续新对话默认不读取 15-23；只有追溯旧定位、口径/形态论证或复审过程时才按需打开归档文件。

## 2. 当前建议结构

```text
项目根目录/
├── 论文改进/论文写作/                  # 旧论文写作链，保留并封存 v0.3
├── 结果/                               # 旧结果目录，保留
├── ocs_project/                        # 旧代码与可复用模块，保留
└── 项目重启_v0.4_BlenderOCS/           # 当前新主线，从根目录重启
    ├── 24_v0.4项目论文主线最终冻结稿_OCS口径形态与mismatch账面对齐版.md
    ├── 25_v0.4主线冻结原因备案_为什么采用24号.md
    └── 99_归档索引/03_v0.4定位历史稿归档_15-23/
```

## 3. 新结果命名建议

```text
结果/模块A_v0.4_BlenderOCS/
结果/模块C_v0.4_反演/
论文改进/补充实验/结果_v0.4_BlenderOCS/
项目重启_v0.4_BlenderOCS/
```

## 4. 禁止事项

- 不要把 v0.4 结果写回旧 `结果/模块A_重构/multi_geom_ggx_yaw73_pitch37`。
- 不要覆盖旧 `论文改进/补充实验/结果` 中的 summary。
- 不要把旧 source data 改名伪装成新 source data。
- 不要在 v0.4 稿件中引用旧 OCS 数值，除非明确作为“旧方法对比/分支原因”。
- 不要把新主线再嵌回旧 `论文改进/论文写作/` 阶段目录。
- 不要把 15-23 号历史定位稿重新搬回项目根目录作为主动主线文件。
- 不要跳过 24/25，直接依据旧 15-23 或旧代码准备文档启动全量重跑。

## 5. 推荐做法

- 每个新 run 都写 `config_used.json`。
- 每个新实验都写 `summary.json` 和 `summary.md`。
- 每个新图都写 source data CSV。
- 每个阶段更新 v0.4 总控，而不是修改旧 v0.3 稿件记录。
- 当前下一步优先冻结“v0.4 信息量与置信指标实现规范”，再进入代码实施与重跑。

## 6. Claude/Codex 交互记录管理

后续 Claude 草稿、Codex 复审意见、阶段提示词、中间候选稿统一放入：

```text
97_交互审阅记录/
```

阶段目录只保留最终通过、当前有效、会被后续执行引用的项目文件。

当前项目定位阶段只保留：

```text
24_v0.4项目论文主线最终冻结稿_OCS口径形态与mismatch账面对齐版.md
25_v0.4主线冻结原因备案_为什么采用24号.md
```

15-23 号定位历史稿统一保留在：

```text
99_归档索引/03_v0.4定位历史稿归档_15-23/
```

例如方法冻结阶段当前只保留最终冻结规范：


交互过程保留在：
