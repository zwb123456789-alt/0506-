# 上下文读取与提示词维护规范

最后更新：2026-06-08

## 1. 目的

本文件用于控制 v0.4 项目在 Claude / Codex / GPT 新对话中的上下文读取范围，避免每次打开文件夹时默认读取过多文件。

## 2. 默认启动最小集

任何新对话默认只读：

```text
CLAUDE.md
00_只打开本文件夹时的启动说明.md
00_v0.4总控流程.md
```

这 3 个文件只负责恢复项目状态、红线、当前阶段和下一步。它们不应要求模型开局全文读取所有阶段文件。

## 3. 阶段提示词负责扩展上下文

每个阶段必须有专门提示词或阶段说明文件，明确：

| 项目 | 要求 |
|---|---|
| 本阶段目标 | 本次只完成什么，不做什么 |
| 本阶段必读 | 必须全文读取的少量文件 |
| 按需检查 | 只在需要证据时读取的文件或目录 |
| 禁止范围 | 不允许修改、删除、移动或复用的内容 |
| 输出文件 | 本阶段必须生成或更新的文件 |
| Codex 复审点 | 需要审阅判断的风险点 |

如果某个文件不是本阶段完成任务所必需，不要列为“必读”，最多列入“按需检查”。

## 4. 备份材料读取规则

`98_外部材料备份/` 是证据库，不是默认上下文。

读取顺序：

```text
先读 98_外部材料备份/00_备份清单.md
-> 根据当前任务关键词定位具体文件
-> 只读取相关文件或相关片段
-> 在输出中记录证据路径
```

文献与引用材料的固定入口：

```text
98_外部材料备份/06_文献与引用材料/
```

论文接入阶段若需要引用，先读该目录下的 `references.bib`、`文献清单.md` 和 `论文必读文献阅读清单.md`。PDF 不默认全量读取或复制，按论文阶段需要逐篇补入。

禁止做法：

- 不要开局扫描整个 `98_外部材料备份/`。
- 不要把旧代码快照全部读入上下文后再判断任务。
- 不要把旧结果文件当成 v0.4 当前结果。
- 不要为了“完整”而读取与本阶段无关的旧写作材料。

## 5. 指导文件更新规则

当项目阶段、红线、默认读取规则或输出目录变化时，至少同步检查：

```text
CLAUDE.md
00_只打开本文件夹时的启动说明.md
00_v0.4总控流程.md
当前阶段提示词
99_归档索引/01_上下文读取与提示词维护规范.md
```

同步原则：

- `CLAUDE.md` 只保留最小启动规则和最高优先级红线。
- `00_只打开本文件夹时的启动说明.md` 只说明如何恢复上下文，不展开阶段细节。
- `00_v0.4总控流程.md` 只作为阶段导航，不替代阶段提示词。
- 阶段细节放在对应阶段文件夹或提示词中。
- 备份材料清单变化时，更新 `98_外部材料备份/00_备份清单.md`。

### 5.1 Codex 阶段通过后的自动同步硬约束

以后任何阶段只要 Codex 复审结论为：

```text
通过
可进入下一阶段
需小修但小修后已确认通过
```

**只能由 Codex 审阅端**在同一轮收尾中主动同步相关进度文档，不得等待作者提醒。这里的“自动同步”是项目流程硬约束，含义是：Codex 审阅端在宣布阶段闭环前必须主动完成同步检查和必要修改。

Claude 执行端的职责边界：

```text
Claude 只负责按提示词在对应阶段目录输出方案、候选稿、修订稿或执行计划。
Claude 不负责更新 CLAUDE.md、00_只打开本文件夹时的启动说明.md、00_v0.4总控流程.md 或 99_归档索引。
```

必须同步检查的文件：

```text
CLAUDE.md
00_只打开本文件夹时的启动说明.md
00_v0.4总控流程.md
当前阶段入口文件或总表
下一阶段入口文件或提示词
99_归档索引/01_上下文读取与提示词维护规范.md
99_归档索引/02_项目文件夹职能规范.md
```

如果该阶段涉及交互记录或 Codex 复审归档，还必须检查：

```text
97_交互审阅记录/00_交互审阅记录说明.md
97_交互审阅记录/03_Codex审阅/对应阶段/
```

同步内容至少包括：

- 当前阶段是否已通过。
- 有效 source-of-truth 文件路径。
- Codex 复审文件路径。
- 当前下一步是什么。
- 明确禁止事项，例如不要直接全量重跑、不要训练模型、不要修改外部旧目录。
- 如果只是“文档确认完成”而非“代码/实验完成”，必须写清楚边界。

硬性判定：

```text
未同步上述相关进度文档，不得在最终回复中宣称阶段已闭环。
```

若因为作者明确要求“不修改文件”而不能同步，最终回复必须显式说明“阶段判断已通过，但启动集/进度文件尚未更新”，并列出应更新的文件。

## 6. Codex 复审文件格式

以后 Codex 复审 Claude 输出时，只生成一个复审意见 `.md` 文件，不再另行生成独立提示词文件。

复审意见文件必须包含：

```text
1. 复审对象
2. 总体判断
3. 主要问题 / Codex CR 编号
4. 哪些内容可以采纳
5. 哪些内容必须修正
6. 是否可以进入下一阶段
7. 下一步 Claude 提示词
```

其中“下一步 Claude 提示词”必须可以直接复制给 Claude 执行，或直接让 Claude 打开该复审意见文件执行。

也就是说，后续工作流固定为：

```text
Claude 生成阶段输出
-> Codex 生成一个复审意见 md
-> 该复审意见 md 末尾内嵌下一步 Claude 提示词
-> 作者把同一个复审意见 md 给 Claude
```

除非作者特别要求，不再单独创建 `Claude提示词/*.md`。

## 7. 交互记录归档规则

Claude 草稿、GPT 草稿、Codex 复审意见、阶段提示词和中间候选稿统一归入：

```text
97_交互审阅记录/01_Claude输出/
97_交互审阅记录/02_GPT输出/
97_交互审阅记录/03_Codex审阅/
```

阶段目录只保留最终通过、当前有效、会被后续代码/实验/论文直接引用的项目文件。

归档后，新对话默认不要读取 `97_交互审阅记录/`。只有需要追溯 Claude/GPT/Codex 往返过程、复审理由或旧提示词时，才按来源和阶段读取对应子目录。
