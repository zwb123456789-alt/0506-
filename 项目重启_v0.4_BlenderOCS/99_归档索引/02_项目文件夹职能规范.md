# 项目文件夹职能规范

最后更新：2026-06-09

## 1. 总原则

v0.4 文件夹按“项目进程文件”和“交互审阅记录”分离管理。

```text
项目进程文件 = 最终通过、当前有效、会指导后续代码/实验/论文的文件
交互审阅记录 = Claude 草稿、GPT 草稿、Codex 复审、提示词、中间候选稿
```

阶段目录不再长期堆放 Claude/GPT/Codex 往返文件。阶段目录应像“项目档案柜”，而不是聊天记录堆。

## 3. 阶段目录保留什么

阶段目录只保留：

- 最终通过的规范文件。
- 当前阶段真正需要执行或引用的计划文件。
- 经过 Codex 审阅后确认进入项目进程的总结表。
- 后续代码、实验、论文会直接引用的 source-of-truth 文件。

阶段目录不保留：

- Claude 初稿。
- Claude 修订稿。
- Codex 复审意见。
- Codex 内嵌提示词。
- 未通过的最终候选稿。
- 仅用于说明交互过程的文件。

这些文件统一按来源移入：

```text
97_交互审阅记录/01_Claude输出/对应阶段/
97_交互审阅记录/02_GPT输出/对应阶段/
97_交互审阅记录/03_Codex审阅/对应阶段/
```

## 4. Codex/Claude 工作流

后续固定为：

```text
Claude 生成阶段输出
-> Codex 复审
-> Claude 输出归入 97_交互审阅记录/01_Claude输出/对应阶段/
-> Codex 复审归入 97_交互审阅记录/03_Codex审阅/对应阶段/
-> 若未通过：Claude 继续修订，修订稿继续归入 Claude 输出
-> 若通过：最终通过文件留在阶段目录
-> 阶段目录只保留最终文件
```

### 4.1 阶段通过后的进度同步硬约束

Codex 复审判定某阶段通过、可进入下一阶段，或小修后确认通过时，**只能由 Codex 审阅端**同步更新相关进度文件，才能视为阶段真正闭环。Claude 执行端只负责在对应阶段目录输出方案、候选稿、修订稿或执行计划，不负责更新启动集、总控或归档索引。

必须同步检查：

```text
CLAUDE.md
00_只打开本文件夹时的启动说明.md
00_v0.4总控流程.md
当前阶段目录中的入口/总表/任务清单
下一阶段目录中的入口/提示词
99_归档索引/01_上下文读取与提示词维护规范.md
99_归档索引/02_项目文件夹职能规范.md
97_交互审阅记录/00_交互审阅记录说明.md（若交互归档状态变化）
```

同步必须写明：

- 哪个阶段已通过。
- 哪些文件是当前 source-of-truth。
- Codex 复审归档路径。
- 下一步是否进入新阶段，还是停在文档确认状态。
- 明确禁止事项。

硬约束：

```text
未完成相关进度文件同步，不得宣称阶段已完成或进入下一阶段。
```
