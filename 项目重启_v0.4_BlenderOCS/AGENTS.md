## 3. Claude 与 Codex 职能

```text
Codex：设计、审阅、规划、技术裁决、阶段门判断、文件分流、Claude 提示词生成。
Claude：只执行 Codex 明确给出的任务，产出执行报告、脚本、日志、CSV/JSON/NPZ/图表等候选材料。
```

Claude 不得自行放行、扩展路线设计、技术裁决、阶段门判断或改写成果区。发现冲突时只列证据路径和待裁决问题，交回 Codex/作者。

作者将 Claude 输出路径交给 Codex 后，Codex 必须审阅。若不通过、需返工、存在阻塞或只形成问题清单，Codex 必须直接在对应路线 `04_Codex审阅/` 生成 Markdown 审阅/返工文件，不能只在聊天中口头说不通过。

从 R106 起，给 Claude 的任务应尽量是长程执行任务：

```text
读取上下文 -> 定位代码/数据 -> 副本实施 -> smoke/正式实验 -> 产出脚本/配置/日志/CSV/JSON/NPZ/图表 -> 写执行报告 -> Codex 一次性审阅。
```

硬性效率要求：

```text
1. Codex 不应反复让 Claude 做只有叙事、盘点、方案、口径说明的小任务。
2. 除非任务本身就是审阅、裁决或纯记忆整理，否则 Codex 给 Claude 的提示词应规划为能产出可检查结果的长程任务。
3. 长程任务必须包含：读取哪些文件、定位哪些代码/数据、允许改哪些副本、运行哪些 smoke/正式实验、产出哪些 CSV/JSON/NPZ/图表/日志、报告写到哪里。
4. Claude 完整交付后，再由 Codex 一次性审阅通过/不通过/FIX/技术阻塞，避免在小任务上互相审阅浪费效率。
5. Codex 审阅不通过时，应直接生成可交给 Claude 继续执行的 Markdown 返工单，而不是只在对话中总结。
6. 已由 Codex 明确接收且不改变阶段门的材料，不重复做全文审阅；只在成果区归档、阶段门放行、CLAUDE.md 同步或论文 claim 使用时做针对性核查。
```

输出篇幅限制：

```text
D 类只读诊断/路径核验/补齐类 Claude 报告：原则上 1500-3000 字，只列输入、脚本、输出、关键数值、缺口和红线自查。
D 类 Codex 审阅：原则上 800-1500 字，只写接收/不接收、关键缺口、下一步，不复述原报告。
A 类成果材料审阅：可适度展开，但应避免超过 3000 字。
C 类训练、split、模型、主 claim 改写等阶段门：可写完整审阅，但仍应围绕证据、风险和下一步。
Claude 报告不得复述大段上游历史；只引用路径和本轮用到的结论。
Codex 审阅文件只写阶段裁决、关键证据、必须修正的问题、下一步执行指令和红线，避免大段历史复述。
```

## 4. 文件管理规则

路线目录统一含义：

```text
00_路线冻结文件区/：路线指导思想、主线说明和冻结判断。
01_成果区/：只存已通过 Codex 审阅、可作为后续依据的稳定成果本体。
02_Claude输出/：只存 Claude 执行报告、候选材料和 Claude 自检记录。
03_GPT输出/：只存 GPT 候选方案、候选文本和辅助构思。
04_Codex审阅/：只存 Codex 审阅、阶段门判断、返工单、执行规划和给 Claude 的提示词。
```

Claude 报告必须写入对应路线 `02_Claude输出/`，不得写入 `04_Codex审阅/`。Claude 不得生成以 `Codex`、`Rxx_Codex`、`验收`、`最终放行` 为名义的审阅裁决文件。

Codex 审阅/返工/阶段门/Claude 提示词属于 Codex 审阅端产物，可直接写入对应路线 `04_Codex审阅/`。除这些审阅端产物外，若要更改 `CLAUDE.md`、冻结文件、成果区、代码、数据结果、论文正文、总览或其他非审阅文件，应说明修改目的和范围；除非作者已明确要求进行入口修补或同步，否则不得擅自修改。
