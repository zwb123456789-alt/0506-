## 2. 方法对比：书中 vs v0.3 vs v0.4

### 2.1 三种方法的关系

| 维度 | **书中仿真方法** | **v0.3 face-center** | **v0.4 Blender pixel-level** |
|------|-----------------|---------------------|----------------------------|
| **物理原理** | ✅ 面元BRDF积分 | ✅ 面元BRDF积分 | ✅ 面元BRDF积分 |
| **几何采样** | 面元离散化 | **face-center 单点采样** | **pixel-level 多点采样** |
| **可见性判定** | 每面元判定 | **face-center 射线** | **逐像素 depth pass** |
| **BRDF模型** | 五参数冯模型 | 五参数冯模型 | **Disney BSDF（Blender内置）或 GGX（Python显式）** |
| **积分方法** | 显式求和 | 显式求和 | **蒙特卡洛（Blender）或逐像素求和（Python）** |
| **与真实对比** | ✅ 书中有真实数据对比 | ❓ 未验证 | ❓ 未验证 |

### 2.2 关键澄清：到底哪种才是"对的"？

**答案：三种方法在物理原理层面都是对的，但实现精度不同。**

```text
物理原理层面：三种都对，都基于面元BRDF积分
实现精度层面：v0.4 > 书中方法 ≈ v0.3（取决于面元密度）
OCS与图像同源性：v0.4 ✅ 同源；v0.3 ❌ 不同源
能否当作"真实OCS"：书中方法 ✅ 有真实验证；v0.4 ⚠️ 更接近但未真实验证
你的主线用哪个：v0.4 Blender pixel-level
```

### 2.3 v0.3 → v0.4 的改进动机

**v0.3的问题**（从审计表确认）：
```
模块A：face-center 采样
问题：每个三角面只用中心点代表整张面
      → 斜面投影面积处理粗糙
      → 边界裁剪和局部可见区域不敏感
      → 对GGX金属窄镜面峰可能漏采样
      → 与图像端像素级可见性不同源
```

**v0.4的改进**：
```
Blender pixel-level sampling
优势：更接近真实成像中的projected visible surface
      → 斜面由多个像素覆盖，而不是一个面中心点
      → 边界、遮挡和局部几何可见性由depth/normal/object pass给出
      → OCS可解释为clean image linear response的积分
      → 核心价值：OCS与图像同源
```

**结论**：v0.4选择Blender pixel-level方法 比 v0.3的face-center方法 **更接近"真实OCS"**，这个判断是对的。

## 3. 收尾报告"并非严格等价"的真正含义

### 3.1 容易造成的误解

书籍知识库收尾报告修正的"过强表述"：

**❌ 过强表述（已修正）**：
> "Blender内部实现的就是本公式的离散化求和"

**✅ 审慎表述（正确）**：
> "Blender渲染流程在工程上可近似对应面元散射积分思想，但其**材质模型（Disney BRDF）、单位链路**与书中显式OCS公式并非严格一一等价。"

### 3.2 "并非严格等价"指的是什么

**不是说物理原理错了**，而是指：

1. **材质模型不同**：Disney BSDF ≠ 五参数冯模型
2. **单位链路不同**：Blender输出的是渲染辐射量，需要转换为OCS单位
3. **实现细节不同**：蒙特卡洛采样 vs 显式求和

**但物理原理是一致的**：都是对目标表面的BRDF散射进行面元积分。

### 3.3 正确的理解

```text
物理原理层面：Blender 与书中方法 ✅ 一致（都是面元BRDF积分）
实现路径层面：Blender 与书中方法 ⚠️ 不同（材质模型、积分方法、单位链路）
工程价值层面：v0.4 ✅ 优势在于OCS与图像同源、可审计
```

## 4. GGX vs 五参数冯模型：技术选择合理性

### 4.1 为什么用GGX而不是书中的五参数冯模型？

**不是因为"更新更好"，而是工程架构需要**：

根据审计表，v0.4的技术选择逻辑是：

```
v0.3问题：模块A face-center采样 + 模块B Blender pixel-level
         → OCS与图像不同源

v0.4方案：统一前向模型
         → Blender负责"看见哪里"（几何采样）
         → Python/公式负责"如何反光"（BRDF计算）
         → 反演代码负责"如何使用观测量"
```

**选择GGX的原因**：
1. **Blender Principled BSDF是黑箱**：内部细节、能量归一、版本实现不可审计
2. **需要OCS与图像调用同一BRDF函数**：确保两个通道完全同源
3. **需要显式公式写入Method**：D/G/F项可以在论文中说明

### 4.2 五参数冯模型 vs GGX

| 维度 | 五参数冯模型 | GGX/Cook-Torrance |
|------|-------------|-------------------|
| **物理准确性** | ⚠️ 经验模型，窄镜面峰不准 | ✅ 微表面理论，物理更准确 |
| **年代** | 1970s-1980s | 2000s+ |
| **是否"过时"** | ⚠️ 对金属粗糙表面不准，但仍广泛使用 | ✅ 当前主流（PBR标准） |
| **书中为什么用** | ✅ 航天器材料多为漫反射主导，五参数够用 | - |
| **你为什么用GGX** | - | ✅ Blender内置GGX，工程解耦需要 |

**关键点**：
- 书中用五参数冯模型不是因为"老"，而是**对航天器典型材料（多层隔热膜、太阳能板、涂层）够用**
- 你用GGX不是因为"新"，而是**Blender几何采样与Python BRDF分离的工程需要**

### 4.3 GGX会不会"反而出错"？

**不会**，只要你明确说明：
- GGX是当前PBR标准，物理基础更扎实
- 与书中五参数冯模型在漫反射主导材料上差异不大
- **关键是OCS与图像调用同一个BRDF函数**（无论是GGX还是五参数冯）

## 5. 核心风险：与真实场景匹配不上

### 5.1 风险是真实存在的

**书中方法有真实验证 → v0.4没有 → 可能与真实场景匹配不上**

这是一个**真实存在的风险**，不是过度担心。

### 5.2 可能不匹配的来源

| 差异来源 | 书中方法 | 你的v0.4方法 | 风险等级 |
|---------|---------|------------|---------|
| **BRDF模型** | 五参数冯（已真实验证） | GGX/Cook-Torrance（未真实验证） | ⚠️ 中 |
| **几何采样** | 面元离散化 | Blender pixel-level | ⚠️ 中 |
| **积分方法** | 显式求和 | 蒙特卡洛/逐像素求和 | ⚠️ 低 |
| **材质参数** | 书中典型材料表 | 需要映射到GGX参数 | ⚠️ 高 |
| **单位链路** | 书中完整链路 | 简化链路（未实现探测器） | ⚠️ 高 |

**核心风险点**：
1. **材质参数映射**：书中五参数冯系数 → GGX参数，映射关系可能不准
2. **BRDF模型差异**：GGX对金属粗糙表面与五参数冯有差异
3. **未真实验证**：你的整套流程没有与真实测量数据对比

## 6. 应对策略：你的项目设计已经考虑了这个风险

### 6.1 策略一：明确边界（路线一）

**不声称与真实匹配，而是研究仿真内部一致性**：

```text
路线一定位：
model-known条件下，OCS光度通道与图像通道
共享同一物理前向模型时的可观测性、互补性与置信一致性研究

红线：
- 不声称"真实未知目标完整姿态反演系统"
- 不声称"field-proven"或"operational-ready"
- 只研究仿真内部一致条件下的信息结构
```

**论文中应该这样写**：
> 本研究在model-known受控条件下，建立OCS与图像共享同一物理前向模型的仿真框架。**研究目标不是验证该前向模型与真实场景的数值匹配度**，而是在该前向模型下，探究OCS光度向量与图像通道在姿态信息表达上的可观测性、互补性与置信一致性。

**这是合法的研究定位**：
- 你研究的是"信息结构"，不是"数值精度"
- 类比：研究"RGB三通道与灰度图的互补性"，不需要证明相机与人眼颜色匹配

### 6.2 策略二：真实数据锚点（路线二）

**用GEO真实光度数据验证趋势一致性**：

```text
路线二定位：
GEO真实光度数据库（有光度、有几何、有型号、无姿态真值）
→ sim-to-real光度保真度锚点
→ 验证仿真光度变化规律与真实趋势的一致性

不声称：
❌ 数值精确匹配
❌ 姿态真值监督反演
❌ 完整链路验证

只声称：
✅ 统计/趋势/分布级光度锚定
✅ 同一型号卫星，仿真与真实的光度变化规律趋势一致
✅ 破解"多几何不现实"质疑（真实数据有多帧多几何）
```

**这给了你一个缓冲**：
- 不要求你的仿真数值完全匹配真实
- 只要求趋势一致：亮的姿态仍然亮，暗的姿态仍然暗
- **这是可以做到的**，因为你的物理原理是对的

### 6.3 策略三：暗室真值闭环（路线三）

**在受控环境下验证姿态一致性**：

```text
路线三定位：
暗室缩比系统内真实光度 + 姿态真值闭环
→ 受控条件下验证"同一前向模型下光度与图像的姿态一致性"

不声称：
❌ GEO/在轨反演验证
❌ 外推到真实轨道环境

只声称：
✅ 暗室系统内，物理散射是真实的
✅ 姿态真值是已知的，可以闭环验证
✅ 证明"OCS与图像对同一姿态变化的响应一致性"
```

## 9. 技术术语澄清

### 9.1 你现在采用的是不是光线追踪？

**是的，但不完全是。**

**你的v0.4方法本质**：

```
第1步：Blender Cycles渲染引擎（光线追踪/路径追踪）
      → 输出：depth、normal、object ID、world position pass
      → 作用：告诉你"哪些像素可见、每个像素的几何信息"

第2步：Python显式计算（不是光线追踪）
      → 读取第1步的几何信息
      → 对每个可见像素计算GGX BRDF值
      → 求和得到OCS，保留空间分布得到image
```

**技术术语**：
- **Blender部分**：蒙特卡洛路径追踪（Monte Carlo Path Tracing）
- **Python部分**：显式BRDF积分（Explicit BRDF Integration）

**与书中方法对比**：

| 维度 | 书中方法 | v0.4方法 |
|------|---------|---------|
| 几何可见性 | 显式光线求交 | **Blender路径追踪** |
| BRDF计算 | 显式五参数冯公式 | **Python显式GGX公式** |
| 积分方式 | 面元离散求和 | **像素离散求和** |
