## 2. 总路线一句话

项目最初是 **OCS-only 姿态反演**：希望用低维光度响应反推目标 yaw/pitch。随后发现 OCS 缺少空间结构信息，于是加入 **光度图像反演**。为了让 OCS 与图像的比较不是“两套仿真链路的误差比较”，项目提出 **统一前向模型**：Blender 负责几何可见性和像素级采样，Python 负责显式 BRDF、OCS 积分和图像线性响应。之后，材料模型从简化 BRDF 更新到 **GGX/Cook-Torrance**，主反演却发现 **clean image-only 有时比 fusion 更好或已经接近上界**，于是叙事从“融合永远最优”改为“条件性互补”。为支撑这个新叙事，又补了图像退化、OCS 噪声、phase63 公平消融、random split、BRDF 敏感性、自遮挡、roll、beta sweep 等实验。再往后发现 **OCS 托不住全部主结论**：它有价值，但必须放在退化条件、低维约束、融合机制解释中讲。最后重新审计时发现主反演和补充实验仍使用旧模块 A 的 face-center OCS，而不是 Blender-derived pixel-level OCS，因此 v0.3 封存，v0.4 从统一前向模型重新生成数据和重跑实验。

## 4. 分支 B0：从 OCS 姿态反演起步

**起点问题**

```text
给定 STL 几何、材料、太阳方向和探测器方向，
能否用 OCS / 光度响应反推目标姿态？
```

**当时路线**

- 建立模块 A：Python / trimesh / face-level OCS 扫描。
- 对 yaw / pitch 姿态网格生成 `ocs_scan.csv`。
- 用 total OCS、per-part OCS、多观测几何 concat 特征训练 OCS-only 反演模型。
- 目标是先证明“OCS 能作为姿态反演观测量跑通”。

**为什么当时合理**

- OCS 是低维光度量，物理含义清楚。
- 多观测几何 OCS 可以累积姿态约束。
- face-center 采样计算快，适合早期大规模扫描。
- 项目早期的主要风险是“反演链路能不能跑通”，不是“OCS 与图像是否同一采样口径”。

**当时埋下的风险**

face-center 采样用每个三角面中心代表整张面。对以下场景不够敏感：

- 斜面投影面积变化。
- 边缘和局部可见性。
- 部件遮挡造成的像素级可见差异。
- GGX 金属窄镜面峰。

这个风险在 OCS-only 阶段没有立刻变成阻塞项，因为还没有把 OCS 与图像作为同源观测来比较。

## 5. 分支 B1：加入光度图像反演

**触发原因**

OCS 是低维观测，能提供光度约束，但缺少空间结构。实际光学观测中，除了总亮度或光变，也可能获得目标光度图像。图像包含投影形状、阴影、亮度分布和部件结构，这些信息正好补足 OCS。

**当时路线**

- 建立模块 B：Blender 渲染光度图像、EXR、PNG。
- 建立 image-only 反演：TinyCNN / ResNet 等网络。
- 保留 OCS-only，同时新增 image-only 和 fusion。

**当时判断**

```text
OCS 解决低维稳定约束；
图像解决空间结构辨识；
融合应当利用两者互补。
```

**关键隐患**

这一步之后，工程上形成两条链：

```text
模块 A：Python face-level / face-center OCS
模块 B：Blender pixel-level image
```

它们都能跑，但物理口径并不完全一样。早期这看起来像工程分工；后期当论文要强调“同源物理观测”和“公平比较”时，它变成了核心风险。

---

## 6. 分支 B2：提出统一前向模型

**触发原因**

如果 OCS 和图像分别来自两套前向模型，那么性能差异可能来自：

```text
观测模态本身的信息差异；
或两套仿真链路的采样、遮挡、材料、亮度定义差异。
```

这会削弱论文主张。因此项目开始转向统一前向模型。

**统一前向模型的核心思想**

```text
同一 STL 几何
同一姿态 yaw/pitch
同一 sun/det 方向
同一材料参数
同一 BRDF
同一可见性定义
        ↓
OCS   = 对同一线性响应做积分读出
image = 对同一线性响应保留空间分布
```

**Python 负责什么**

- GGX/Cook-Torrance BRDF 显式公式。
- NoL / NoV / NoH 等几何项。
- 材料参数库。
- `V_sun_macro` 的使用逻辑。
- OCS 积分与 per-part OCS。
- 图像线性响应 `I_linear = f_r · NoL · V_sun_macro`。
- log1p PNG 编码。
- manifest / source_data 记录。

**Blender 负责什么**

- STL 导入与姿态变换。
- 正交投影相机。
- depth、normal、IndexOB、Position/WorldCoord。
- camera visibility。
- sun-view depth pass / geometry sampling。
- 像素级可见表面采样。

**为什么这样分工**

```text
Blender 负责“看见哪里”；
Python 负责“如何反光”；
反演代码只负责“如何使用观测量”。
```

这样做不是因为 Blender 材质不行，也不是因为自定义 GGX 一定比 Blender Principled BSDF 更先进，而是因为本项目需要公式显式、两端共享、可审计、可复现、可做敏感性分析。Blender 的价值在于几何可见性和像素级采样，不在于让它用黑箱材质直接决定最终亮度。

**当时没有完全做到的地方**

虽然统一前向模型的叙事已经形成，但主反演链路仍主要使用旧模块 A 的 face-center OCS。Blender-derived pixel-level OCS 更多出现在诊断、对比、EXR 后处理或方法说明中，没有成为主反演和补充实验的 canonical OCS 数据源。

这就是后来“为什么之前有记录但没有立刻改”的关键原因：当时统一模型是叙事与方法方向，主数据链还没有完全切换。

## 7. 分支 B3：从简化 BRDF 更新到 GGX

**触发原因**

空间目标材料不是简单漫反射。金属主体、太阳能板、暗涂层具有不同粗糙度和镜面反射特征。为了让光度仿真更贴近光学散射物理，需要显式 microfacet BRDF。

**当时路线**

- 从 LegacyPhong / 简化 BRDF 切换到 GGX/Cook-Torrance。
- 显式定义 D/G/F 项。
- 三类材料使用统一 `_GGX_DB` 参数。
- OCS 与图像后处理调用同一 Python BRDF 函数。
- Blender 不直接用 Principled BSDF 作为最终亮度模型。

**带来的好处**

- 方法部分可以写清公式。
- OCS 和 image 共享同一散射定义。
- 材料敏感性可以系统分析。
- 审稿时能解释亮度贡献来源。

**同时放大的风险**

GGX 的窄镜面峰对采样很敏感。face-center 采样可能漏掉局部高光，而 Blender pixel-level 采样能更细地覆盖投影可见区域。因此，GGX 更新不是只增强了物理性，也让旧采样口径问题更容易暴露。

## 8. 分支 B4：主反演发现 clean image 有时比 fusion 更好

**主反演阶段**

项目跑通了：

- OCS-only。
- image-only。
- late fusion。
- feature fusion。
- TinyCNN / ResNet 主线。

**关键发现**

0603 汇报中已经出现明确结果：

- ResNet-18 clean image mean 约 1.69°，Hit@5° 约 97.6%。
- OCS-only 明显弱于 clean image。
- feature fusion 可改善 worst-case，例如把 worst-case 从约 9.9° 压到约 6.6°。
- 但 clean image-only 有时已经非常强，甚至在部分口径下比 fusion 更好。

**这推翻了什么**

旧叙事：

```text
OCS + 图像融合永远最优。
```

不能再这样写。因为如果 clean image 已经接近上界，强行说 fusion 必然最优，会被结果反驳。

**新叙事**

```text
clean image 是理想合成图像上界；
OCS 是低维、稳定、可多几何积累的光度约束；
真实观测退化时，OCS 可能比图像更稳；
fusion 的价值是条件性互补，不是永远最优。
```

**这一步的意义**

项目从“追求一个最低误差”转向“判断什么条件下该信哪种观测”。这是论文价值从纯性能指标转向实际观测策略的关键分支。

## 9. 分支 B5：第一轮补充实验支撑条件性互补

**为什么必须补实验**

clean image 太强，会让 OCS 价值显得弱。如果论文只停在主反演结果，会被问：

```text
既然图像这么强，为什么还需要 OCS？
融合为什么不是多余？
OCS 的现实价值在哪里？
```

因此补充实验的目标变成：证明 clean image 是理想条件上界，而真实观测退化时 OCS 有鲁棒支撑价值。

**第一轮补充方向**

- 图像噪声：验证 clean image 对像素噪声的脆弱性。
- 图像模糊 / 降采样：模拟低分辨率、PSF、成像退化。
- 背景 / 星场：模拟真实观测环境干扰。
- OCS noise robustness：验证 OCS 噪声下融合价值。
- phase63 公平消融：保证单几何图像与单几何 OCS 的比较更公平。
- random split：检查结论是否依赖某一划分方式。
- BRDF 参数敏感性：回应材料参数假设风险。
- 自遮挡 with / without：证明遮挡不是装饰项。
- roll 敏感性：明确固定 roll 的论文边界。
- outlier gallery / failure case：解释失败模式。

**当时形成的判断**

```text
clean image 不等于真实外场；
图像退化时 OCS 可以作为低维鲁棒约束；
fusion 的价值随观测条件变化。
```

**新风险**

补充实验越多，越依赖 OCS 底层定义。如果 OCS 采样口径不稳，则以下实验都会受影响：

- OCS-only。
- fusion。
- OCS noise。
- beta sweep。
- phase63 OCS 消融。
- branch masking / fallback isolation。
- 12b / 12c / 12f / 12g 等 OCS 相关补充实验。

## 10. 分支 B6：发现“OCS 托不住”后继续补机制

**这里的“OCS 托不住”含义**

不是说 OCS 没用，而是说：

```text
OCS 不能单独承担全部主结论；
OCS 的价值必须放在特定退化条件、特定融合机制、特定观测资源限制下说明。
```

**为什么会有这个判断**

- clean image-only 在理想仿真条件下太强。
- OCS-only 误差明显大于 clean image。
- late fusion 若权重偏向 OCS，可能拉低结果。
- OCS 的低维性导致姿态简并，不能替代图像空间结构。
- fusion 提升不总是来自 OCS 的“更准”，而可能来自两个模态错误模式不同。

**第二轮补充和机制解释方向**

这一阶段补实验的重点不是再证明“OCS 更强”，而是解释“OCS 什么时候有用、怎么用才合理”：

- **fallback isolation**：检查当图像失败时，OCS 是否能提供可用后盾。
- **branch masking**：分析融合网络是否真的使用 OCS 分支，而不是只靠图像分支。
- **late fusion beta sweep**：确定 OCS 权重变化对误差的影响，避免把融合写成无条件最优。
- **OCS 简并 / 错误模式分析**：说明 OCS 为什么在某些姿态不够。
- **退化强度曲线**：说明图像从 clean 到 degraded 的性能崩塌过程，以及 OCS 在其中的角色。
- **worst-case / outlier 分析**：把 fusion 改善定位为极端样本修正，而不是所有样本平均提升。

**叙事收缩**

旧写法：

```text
融合最好，OCS 和图像都强。
```

修正写法：

```text
理想 clean 图像给出上界；
OCS 不能替代 clean 图像；
但 OCS 在图像退化、低维观测、错误模式互补和可信度判断中有价值；
fusion 是条件性策略。
```

**对后续的影响**

这一步让论文更真实，也让 OCS 数据源变得更关键。因为 OCS 不再只是一个附属特征，而是退化场景和可信度判断的关键支点。一旦 OCS 本身采样口径不一致，整条“条件性互补”叙事都会被削弱。

## 11. 分支 B7：v0.3 收束与隐藏风险

**v0.3 当时状态**

- OCS-only / image-only / fusion 主实验已经跑通。
- ResNet clean image 上界结果明确。
- 补充实验体系已经形成。
- 论文 v0.1 / v0.2 / v0.3 逐步收束。
- Acta/ASR 主投优先稿进入工程化准备。

**为什么当时看起来可以推进**

```text
主线结果完整；
补充实验能解释 clean image 与 OCS/fusion 的关系；
统一前向模型叙事已经形成；
论文结构已经能闭合。
```

**隐藏风险**

统一前向模型叙事很强，但主 OCS 数据源仍来自旧模块 A：

```text
结果/模块A_重构/multi_geom_ggx_yaw73_pitch37/.../ocs_scan.csv
```

也就是说：

```text
论文在往“统一前向模型”方向写，
但主反演和补充实验没有完全使用 Blender-derived pixel-level OCS。
```

这不是简单文字问题，而是数据源定义问题。

## 12. 分支 B8：重新审计发现 OCS 采样口径问题

**触发问题**

作者重新追问：

```text
旧 OCS 扫描方法使用的采样方法，
是否会导致斜面上的 OCS 计算失误？
后续反演是不是已经使用 Blender 的采样？
如果没有，会不会影响反演和补充实验？
```

**审计结论**

主反演与大量补充实验使用的是旧模块 A OCS：

```text
face-level / face-center sampling
```

而不是方法冻结后要求的：

```text
Blender-derived pixel-level sampling
```

**为什么之前没有立刻改**

这个问题不是完全没有记录。之前已经有：

- Blender EXR / geometry pass。
- A/B OCS 差异诊断。
- 三端闭合验证。
- face-center vs pixel-level 的差异讨论。

但当时没有改入主链路，原因是：

- 早期目标是快速跑通 OCS-only。
- 中期主要压力在图像反演、ResNet、fusion、补充实验和论文收束。
- Blender-derived OCS 当时更多作为诊断和方法论支撑，而不是主反演数据源。
- 在论文尚未强力主张“统一前向模型”之前，A/B 分离像工程权宜方案；当论文主张升级后，它才变成定义级风险。

**影响范围**

受影响的不只是一个 CSV，而是所有依赖 OCS 的主结果和补充实验：

- OCS-only 反演。
- image + OCS fusion。
- OCS noise robustness。
- phase63 OCS 公平消融。
- beta sweep。
- branch masking / fallback isolation。
- BRDF、自遮挡、roll 中涉及 OCS 的部分。
- 12b / 12c / 12f / 12g 等 OCS 相关补充实验。
- 论文中关于 OCS 与 image 同源、公平比较、条件性互补的叙事。

## 13. v0.4 决策：完整重启而非局部替换

**为什么不只把采样模型换一下**

如果只替换 OCS CSV，但继续沿用旧图像、旧 fusion、旧 robustness 数字、旧 manifest 或旧 split，很容易形成新一轮混用：

```text
新 OCS + 旧 image
新 OCS + 旧 fusion 结果
新 OCS + 旧补充实验
新采样 + 旧可见性定义
新方法叙事 + 旧数据源记录
```

这种方式工程上省事，但论文上站不住。因为 v0.4 的核心目标不是“把一个脚本修掉”，而是把 OCS/image/fusion 的观测定义统一到同一条前向物理链路上。

**v0.4 正式决策**

```text
v0.3 封存；
旧结果不作为 v0.4 主结果复用；
以 Blender-derived pixel-level OCS 作为 canonical OCS；
OCS 和 image 来自同一统一前向模型；
所有 OCS 相关主实验和补充实验重跑。
```

**v0.4 前向物理统一模型**

```text
Blender 负责：
STL、姿态、正交投影、depth、normal、IndexOB、Position/WorldCoord、
camera visibility、sun-view depth pass / geometry sampling。

Python 负责：
GGX/Cook-Torrance BRDF、NoL/NoV、V_sun_macro、OCS 积分、
per-part OCS、I_linear、log1p PNG、manifest/source_data。

反演负责：
显式读取 manifest、构建 OCS/image/fusion 特征、训练、评估和汇总。
```

**最终目的**

v0.4 不是为了让所有指标必然变好，而是为了让指标可信：

```text
OCS 和 image 的比较公平；
fusion 的解释不混入两套仿真链路误差；
退化实验能说明真实观测条件下的可靠性；
论文方法部分能被审计、复现和防守。
```

## 14. 分支 B9：v0.4 后继现实差距与仿真保真度路线

**新增位置**

本分支从 v0.4 定位冻结之后开始，不回头改写 B0-B8。B8 解释的是为什么旧 v0.3 必须封存并以 Blender-derived pixel-level OCS 重启；B9 解释的是，即使 v0.4 修复了同源采样、OCS 口径、OCS 形态和项目定位，距离真实世界仍然还有哪些 gap。

因此，B9 不是 v0.4 的前置条件，也不是本轮主线的一部分。它是 24/25 已经点明、但被明确放到 19 号保真度路线、Discussion 或 Future Work 中的后续路线。

**触发原因**

24/25 已经把 v0.4 收束为：

```text
model-known 条件下，
独立 OCS 光度通道与图像成像通道共享同一物理前向模型时，
跨几何 OCS 多观测光度向量与图像通道对姿态信息的可观测性、
互补性和置信一致性研究。
```

这个定位解决了旧主线的过度宣称、旧 OCS/image 采样口径不一致、OCS 口径 A/B 混用、单点 OCS 信息不足等问题。但它没有声称解决真实外场部署问题。24/25 同时明确：真实 OCS 不能默认等于仿真 OCS；偏差来自材料、几何、观测链、定标、背景、phase 分布和真实光照环境。

**需要补的现实差距**

1. **材料 / BRDF gap**

   名义 GGX/Cook-Torrance 参数不等于真实材料反射。真实航天器材料可能存在涂层老化、污染、各向异性、波段依赖和未知粗糙度。材料 roughness、F0、albedo 和 glint 峰形会直接改变 OCS/image 姿态 signature。

2. **几何 / 模型 gap**

   model-known 不等于真实几何完全准确。STL/CAD 可能缺少细小部件、热控膜、天线、支架、展开状态误差、尺度误差或部件姿态误差。几何近似会同时影响遮挡、投影轮廓、局部高光和积分光度。

3. **观测链 gap**

   v0.4 的 clean image / controlled degradation 不是完整真实观测链。真实图像会受到大气 seeing、PSF、跟踪误差、运动模糊、读噪、暗电流、背景、星场、饱和、压缩、动态范围和探测器非线性影响。

4. **光度定标 gap**

   真实观测拿到的是 counts / magnitude，不是仿真 OCS。若要把真实光度与仿真 OCS 对齐，需要孔径测光、背景扣除、标准星、gain/offset、波段响应、大气消光和绝对/相对定标策略。能否绕过绝对定标、改用归一化形状或相对特征，是后续路线的重要问题。

5. **观测几何 / phase gap**

   v0.4 的 L1 跨几何 OCS 是受控 sun/view 几何下的多观测光度向量。真实观测中 sun/view/phase 随轨道和时间变化，不是任意可控采样。后续必须说明 L1 在真实场景中对应短时间准静态窗口、观测规划、跨夜重访还是由轨道先验约束的采样序列。

6. **L2 时域光变 gap**

   24 号已将 L2 时域光变曲线放入 Future Work。若进入真实观测路线，就必须考虑自转动力学、曝光积分、运动模糊、时变几何、时间戳同步和轨道/姿态先验，而不能把 L1 跨几何向量直接写成真实时域光变。

7. **真实 / 半真实锚点 gap**

   没有真实望远镜图像、实验室缩比目标、实测 BRDF 或探测器标定数据时，v0.4 只能声明受控仿真内的可观测性与置信一致性。若要升级为 calibrated capability claim，需要至少一个真实或半真实锚点。

**为什么不并入本轮 v0.4 主线**

若把上述 gap 全部并入本轮 v0.4，论文会从可审计的 model-known 信息结构研究，膨胀成完整 sim-to-real 工程系统。这样会带来三类风险：

- 目标过大：BRDF 实测、探测器标定、真实外场和时域轨道几何都会拖慢当前重跑主线。
- 证据不足：没有真实锚点时，无法把仿真结果写成 field-ready 或 operational-ready。
- 主线变散：v0.4 的核心三问 what can be known / when complementary / when trustworthy 会被完整观测链工程淹没。

因此本轮 v0.4 只负责把统一前向模型、OCS 口径/形态、可观测性、互补性和置信一致性做可信；现实差距路线作为后继分支保存。

**后续可形成的分层路线**

| 层级 | 条件 | 可做内容 | 可宣称边界 |
|---|---|---|---|
| Level 1 | 几何已知、材料名义、观测链受控 | v0.4 主线：OCS/image 信息量、互补性、置信一致性 | 受控仿真与 model-known 可观测性 |
| Level 2 | 几何已知、材料近似、观测链可校准 | 材料/BRDF mismatch、gain/offset、PSF、背景、phase shift 稳定性 | 给出结论对 mismatch 的量化边界 |
| Level 3 | 几何近似、材料/观测链估计 | 候选几何库、参数扰动、归一化光度特征、拒识机制 | 近似模型条件下的可用范围 |
| Level 4 | 有真实或半真实锚点 | 实测 BRDF、实验室缩比目标、真实望远镜图像、探测器标定 | calibrated capability claim，仍不等于任意未知目标 |
| Level 5 | 完全未知目标 | 几何、材料、姿态、尺度、观测链同时未知 | 当前路线不成立，只能作为远期问题 |

**与 B8 / v0.4 的关系**

```text
B8 解决：旧 v0.3 为什么必须封存，为什么不能只替换 OCS CSV。
B9 解决：v0.4 即使成立，距离真实世界还差哪些物理链路与验证锚点。
```

写作时应保持两条边界：

- v0.4 主文不写真实外场性能，不写真实未知目标可部署系统。
- B9 可作为 Discussion / Future Work / 后续项目路线，说明需要补哪些模型、哪些标定、哪些真实或半真实数据。

## 15. 分支 B10：三路线逐步推进

**新增位置**

本分支发生在 24/25 主线冻结、13/14 方法冻结、路线一/二/三候选稿形成之后。它不是对 B8 v0.4 重启的否定，也不是对 24 号主线的推翻，而是对后续执行方式的重新分层。

B8 解决的是：

```text
为什么旧 v0.3 必须封存，为什么必须用 Blender-derived pixel-level OCS 重启 v0.4。
```

B9 解决的是：

```text
v0.4 即使内部统一，距离真实世界还差哪些保真度、定标、材料和真实锚点。
```

B10 解决的是：

```text
在专家质疑“前向模型—仿真—反演铺得过大”之后，
如何把项目拆成可逐步完成、可审阅、可发刊的大论文路线。
```

**触发原因**

专家指出，当前项目同时包含三件事：

```text
前向模型统一
仿真可信性
姿态反演
```

若三者被写成一个不分层的大系统，会遇到三类风险：

- 前向模型若不能与真实光度对齐，仿真结论会被质疑。
- 纯仿真若不能说明真实环境，反演结果会被质疑。
- 反演若没有真实姿态真值闭环，无法判断失败来自仿真还是反演方法。

同时，专家提供的 GEO 真实光度数据又带来一个关键事实：该数据有光度、有几何、有型号、有时间序列，但没有目标三轴姿态真值。因此它能支撑 sim-to-real 光度锚定和多几何现实性，却不能支撑监督式姿态反演成功率。暗室缩比实验则相反：它可以有姿态真值、能做反演闭环，但与 GEO 数据库互不连通，不能外推为在轨目标反演验证。

**最终选择**

项目改为三路线逐步推进：

```text
路线一：fixed-roll yaw-pitch 纯仿真主干
路线二：GEO 真实光度锚点升级层
路线三：暗室缩比独立验证条件增强层
```

当前工作假设为：

```text
路线一 = 必选主干
路线二 = 优先增强层
路线三 = 条件触发增强层
```

该假设需要 Codex 审阅通过后才能冻结。

**为什么这样判断合理**

1. 路线一保证硕士论文主干可闭合。它继承 24 号主线，研究 model-known 条件下 OCS/image 的可观测性、互补性和置信一致性，不声称真实未知目标完整反演。
2. 路线二正好回应专家对“仿真真实性”和“多几何现实性”的质疑，但因为 GEO 数据无姿态真值，只能作为真实光度锚点和 sim-to-real 边界，不能作为监督反演路线。
3. 路线三补上真实姿态可控反演闭环，但它是独立暗室系统，不能向 GEO 或在轨目标传递结论，因此只能作为条件增强腿。
4. 三路线是并联增强，而不是串联外推。任何路线的 claim 都必须限制在自身证据能支撑的范围内。
