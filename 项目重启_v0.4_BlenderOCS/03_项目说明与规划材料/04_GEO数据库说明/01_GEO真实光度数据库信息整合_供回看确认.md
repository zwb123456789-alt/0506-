## 一、一句话定性

```text
这是一份真实在轨 GEO（同步带）目标光学监测数据库，
有光度、有几何、有型号、有时间序列，但没有目标三轴姿态真值。
因此它是"保真度校准级"数据，不是"监督反演级"数据。
```

## 二、观测系统与数据规模

| 项 | 内容 |
|---|---|
| 设备 | 12 台 15cm 口径相机组成的计算光学阵列 |
| 转台 | **无自动控制**（手动调整指向） |
| 覆盖区域 | 东经 60°~175° 同步带（GEO 带） |
| 覆盖特点 | 手动指向、精度不高、对同步带覆盖不均匀、**局部多重覆盖** |
| 成像格式 | FITS |
| 量化位数 | 16 bit |
| 分辨率 | 4K |
| 计算成像 | 5 秒内成像数据，计算生成一帧 FITS |
| 帧率 | **1 帧/分钟/台**（受存储/网络限制压低） |
| 视场角 | 14°×14°（对角线 18°） |
| 采集图像 | 221005 帧 |
| 有效图像 | 214005 帧 |
| 光度范围 | -0.382（最亮）至 16.784（最暗）视星等 |
| 处理软件 | GEOIMAR（高轨成像增强现实原型软件），批处理 FITS 和 IPD 数据 |

**对项目的含义**：
- 真实工程系统（手动转台、覆盖不均），非理想实验台 → 真实性强，但噪声/不规则采样多。
- 1 帧/分钟时序稀疏 → 可做"多帧多几何"，但不构成密集光变曲线（不滑向 L2）。
- 光度跨度大、含暗目标 → 覆盖真实可观测性的高低区。

## 三、五张数据表逐表拆解

### 3.1 OMM 编目轨道数据表

| 字段 | 单位 | 类型 |
|---|---|---|
| 目标编号 | — | 标识 |
| 历元时刻 | UTC | 时间 |
| 半长轴 | 公里 | 轨道根数 |
| 倾角 | 度 | 轨道根数 |
| 偏心率 | 无量纲 | 轨道根数 |
| 与下一相邻轨道历元时刻的时间间隔 | 分钟 | 轨道变化 |
| 与下一相邻轨道根数半长轴的差 | 公里 | 轨道变化 |
| 与下一相邻轨道根数倾角的差 | 度 | 轨道变化 |
| 与下一相邻轨道根数偏心率的差 | 无量纲 | 轨道变化 |

**性质**：轨道根数。**对项目用途**：定位目标轨道、辅助几何反算。**注意：轨道 ≠ 姿态**。

### 3.2 PRE 轨道预报数据（★ 几何反算关键表）

| 字段 | 单位 | 类型 |
|---|---|---|
| 站名 | — | 标识 |
| 相机名 | — | 标识 |
| 成像时间 | — | 时间 |
| 目标编号 | — | 标识 |
| 目标图像坐标系预报坐标 PX、PY | 像素 | 图像几何 |
| 目标 J2000 坐标系预报坐标 X_J2000、Y_J2000、Z_J2000 | 公里 | **惯性系几何** |
| 传感器在目标轨道坐标系预报坐标 X_SNS、Y_SNS、Z_SNS | 公里 | **观测几何** |

**性质**：位置/几何预报。**对项目用途（最重要）**：
- X/Y/Z_J2000 + X/Y/Z_SNS → **可反算每帧的 sun/view 相对几何**（作者已确认几何可反算）。
- 这是破法 C（真实数据坐实多几何）的技术地基。
- 同一目标多帧 → 多个 sun/view 几何 → 天然"多几何光度向量"。

**注意：位置/几何 ≠ 姿态**。这给的是"目标在哪、传感器从哪看"，不是"目标本体朝哪"。

### 3.3 DET IPD 测角测光检测数据（★ 真实光度来源表）

| 字段 | 单位 | 类型 |
|---|---|---|
| 站名 | — | 标识 |
| 相机名 | — | 标识 |
| 成像时间 | — | 时间 |
| 目标流水号 | — | 标识 |
| IPD 定位图像坐标 X、Y | 像素 | 图像几何 |
| 灰度 | — | 像素值 |
| IPD 测角方位 | 度 | **天球方位** |
| 俯仰 | 度 | **天球方位** |
| 赤经 | 度 | **天球方位** |
| 赤纬 | 度 | **天球方位** |
| **IPD 测光光度** | **视星等** | **★ 真实光度** |
| 计算成像标识 | — | 标识 |

**性质**：测角 + 测光。**对项目用途（最重要）**：
- **IPD 测光光度（视星等）= 真实光度数据本体**，用于 sim-to-real 保真度校准。
- 取已知型号卫星帧 → 仿真其光度 → 与此实测视星等比分布/量级/趋势。

**关键区分（路线生死线）**：
```text
测角方位/俯仰/赤经/赤纬 = 目标相对观测站在天球上的角位置（它在天上哪个点）。
这不是姿态。姿态是目标本体坐标系相对惯性系的三轴朝向（帆板朝哪、本体转多少）。
天球方位 ≠ 本体姿态。测角再准也推不出本体姿态。
```

**性质**：身份识别。**对项目用途**：

**注意：身份 ≠ 姿态**。型号告诉你"这是什么卫星"，不告诉你"它当时朝哪"。

| DN 均值/方差/拟合 K 值/拟合误差 | 像素（K: 像素/分钟） | 径向统计 |
| **光度均值** | **视星等** | **★ 光度统计** |

**注意：机动/统计 ≠ 姿态**。这给的是"轨道/光度有没有变化"，不是"姿态是多少"。

## 五、命门重申（一句话）

```text
全库五张表逐字段确认：有光度、有几何、有型号、有时序，
唯独没有任何字段是目标三轴姿态 / yaw / pitch / roll。
轨道根数 ≠ 姿态；天球测角 ≠ 本体姿态；身份 ≠ 姿态；机动统计 ≠ 姿态。
所以：监督式"光度/图像 → 姿态"反演在这份真实数据上无法训练、无法验证。
这不是数据质量问题，是非合作目标真实姿态本就不可得（可得就不叫非合作）。
```

## 六、待你后续确认/补充的事实点

以下点影响路线二落地，建议你后续核实并在本文补注：

1. **几何反算精度**：PRE 表能算 sun/view 几何（已确认可反算），但太阳位置是否需额外星历、反算精度如何，待 pilot 验证。
2. **型号→几何覆盖率**：数据库里有多少 NORAD/CODE 能对到可建模 STL？并非所有型号都有公开几何。
3. **光度定标口径**：IPD 测光视星等的定标方式（绝对/相对、零点、大气改正）是否可得，影响校准能不能对到绝对量级，还是只能比相对趋势。
4. **同目标多帧密度**：单个目标平均有多少帧、覆盖多少不同几何，决定"多几何向量"在真实数据上有多丰富。
5. **是否有配套 FITS 图像**：DET 是测光表，REG 有图像文件名——真实 FITS 图像能否取到，决定能否做"真实图像 vs 仿真图像"对照（而不仅是光度对照）。
