## 5. 方法说明摘要：公式、Blender、反演各负责什么

v0.4 统一前向模型采用以下分工：

```text
Blender 负责“看见哪里”；
Python/公式负责“如何反光”；
反演代码负责“如何使用观测量”。
```

| 部分 | 负责内容 | 不负责内容 | 原因 |
|---|---|---|---|
| Blender | STL、姿态、正交投影、depth、normal、IndexOB、Position/WorldCoord、camera visibility、sun-view depth pass、像素级几何采样 | 不用 Principled BSDF 作为最终亮度黑箱 | Blender 的价值是几何可见性和投影采样 |
| Python 公式 | GGX/Cook-Torrance BRDF、材料参数、NoL/NoV、`V_sun_macro`、OCS 积分、per-part OCS、`I_linear`、log1p PNG | 不做几何可见表面采样 | 公式显式、可审计、OCS/image 同源 |
| 反演代码 | 读取 manifest、组织 OCS/image/fusion 特征、训练、评估、汇总 | 不重新定义物理模型 | 避免训练脚本隐式改变数据口径 |

## 6. 为什么不用 Blender 内置材料黑箱

不使用 Blender Principled BSDF 作为最终亮度模型，不是因为它“不好”。Blender Principled BSDF 本身包含复杂 GGX/多重散射实现，但它面向视觉渲染，内部细节、能量归一、版本实现和采样策略不适合作为本文 OCS 与图像共同的可审计公式。

v0.4 选择：

```text
Blender only for geometry sampling
Python explicit GGX/Cook-Torrance for scattering
```

好处：

- OCS 与图像调用同一 BRDF 函数。
- 三材料参数库统一。
- D/G/F 项可以写入方法部分。
- 材料敏感性分析可控。
- 同一批 geometry pass 可用于不同 BRDF/参数实验。
- 审稿时可以说明每一项亮度贡献来自哪里。

## 7. 模块 A/B 分离 vs 统一前向模型

旧路线：

```text
模块 A：Python / trimesh face-level OCS
模块 B：Blender pixel-level photometric image
```

优点是工程分离清楚、早期跑得快；缺点是 OCS 与图像采样口径不同，遮挡、斜面、边缘、投影面积和窄镜面峰处理不同。这样仍可做反演，但很难判断性能差异来自观测模态本身，还是来自两套仿真链路差异。

v0.4 路线：

```text
同一 STL、同一姿态、同一 sun/det、同一材料、同一 BRDF、同一可见性定义
        ↓
OCS = 积分读出
image = 空间分布读出
```

v0.4 采用统一前向模型的理由：

- 模态比较更公平。
- fusion 提升可解释为同源低维光度量与空间图像结构互补。
- 图像退化实验有清楚基准：退化前 clean image 与 OCS 同源。
- 论文可以写成 observation-consistent synthetic forward model。
- manifest/source_data 能防止新旧结果混用。

统一模型不保证所有误差数字必然下降。它的首要价值是让结果更能代表修正后的观测定义，而不是旧采样误差下的偶然优势。

## 8. 为什么采用 Blender pixel-level sampling

旧 face-center 采样的问题：

- 每个三角面只用中心点代表整张面。
- 对斜面投影面积处理粗糙。
- 对边界裁剪和局部可见区域不敏感。
- 对 GGX 金属窄镜面峰可能漏采样。
- 与图像端像素级可见性不同源。

Blender pixel-level sampling 的好处：

- 更接近真实成像中的 projected visible surface。
- 斜面由多个像素覆盖，而不是一个面中心点代表。
- 边界、遮挡和局部几何可见性由 depth/normal/object pass 给出。
- OCS 可解释为 clean image linear response 的积分。

精确表述边界：

```text
Blender-derived pixel-level sampling provides a more observation-consistent synthetic forward model,
not real-telescope validation.
```

也就是说，它比旧 face-center OCS 更贴近真实图像形成逻辑，但仍不是实测望远镜链路，不能声称真实大气、探测器或 field-proven robustness。

## 9. 旧结果与文件管理规则

旧结果用途仅限：

1. 解释为什么 v0.3 封存。
2. 作为诊断材料，帮助发现类似坑。
3. 作为代码结构参考，不能作为 v0.4 主结果。

禁止：

```text
新 OCS + 旧 image
新 OCS + 旧 fusion
新 OCS + 旧 robustness
新采样 + 旧 source_data
新论文叙事 + 旧数据源记录
```

v0.4 新结果必须通过 manifest/source_data 追踪：

- geometry version。
- BRDF version。
- visibility version。
- OCS integration version。
- image preprocess version。
- dataset/split version。
