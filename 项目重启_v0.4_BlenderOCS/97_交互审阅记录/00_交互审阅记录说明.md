# 交互审阅记录说明

最后更新：2026-06-08

## 1. 目的

本目录专门保存 Claude 输出、GPT 输出、Codex 复审意见、阶段提示词和中间候选稿。

这些文件用于恢复交互过程、追踪为什么修改、谁审阅过、下一步提示词是什么；它们不是项目主流程的最终依据。

## 2. 三类来源目录

```text
97_交互审阅记录/
├── 00_交互审阅记录说明.md
├── 01_Claude输出/
├── 02_GPT输出/
└── 03_Codex审阅/
```

| 类型 | 放置位置 | 用途 |
|---|---|---|
| Claude 输出/草稿/候选稿 | `97_交互审阅记录/01_Claude输出/对应阶段/` | 保留 Claude 生成过程 |
| GPT 输出/草稿 | `97_交互审阅记录/02_GPT输出/对应阶段/` | 保留 GPT 生成过程，当前尚未启用 |
| Codex 复审/总结/提示词 | `97_交互审阅记录/03_Codex审阅/对应阶段/` | 保留 Codex 审阅、判断和下一步提示词 |
| 最终通过的项目文件 | 对应阶段目录，如 `04_BlenderOCS方法重建/`、`05_全链路重跑/` | 作为当前项目进程依据 |

## 4. 后续规则

1. Claude/GPT/Codex 交互文件不要长期堆在阶段目录中。
2. 阶段目录只保留最终通过、当前有效、会被后续执行引用的文件。
3. Codex 复审通过后，应把最终通过版本写入项目进程目录；复审意见本身归入 `03_Codex审阅/`。
4. Claude 生成但未通过的版本归入 `01_Claude输出/`；通过后的最终文件保留在主阶段目录。
5. GPT 输出当前未启用；启用后放入 `02_GPT输出/`。
6. 新阶段开始时，如果需要 Claude 提示词，优先放在 Codex 复审文件末尾；执行完毕后该复审文件归入 `03_Codex审阅/`。
7. 新对话默认不要读取本目录，除非需要追溯历史判断。

### 4.1 Codex 复审通过后的同步要求

Codex 复审意见归档后，如果结论为“通过”或“小修后确认通过”，不得只归档复审文件。**只能由 Codex 审阅端**同步更新相关项目进度文件，至少包括：

```text
CLAUDE.md
00_只打开本文件夹时的启动说明.md
00_v0.4总控流程.md
当前阶段入口文件
99_归档索引/01_上下文读取与提示词维护规范.md
99_归档索引/02_项目文件夹职能规范.md
```

同步完成前，不能把阶段称为“已闭环”。如果作者明确要求只审阅不改文件，必须在最终回复中说明哪些启动集或索引尚未更新。

Claude 执行端不负责更新上述启动集、总控或索引；Claude 只负责按 Codex 提示词在对应阶段目录输出方案、候选稿、修订稿或执行计划。

## 5. 命名规则

交互记录统一采用：

```text
Rxx_来源_类型_主题.md
```

字段说明：

| 字段 | 示例 | 说明 |
|---|---|---|
| `Rxx` | `R01` | 当前阶段内交互轮次，不跨阶段连续 |
| 来源 | `Claude` / `GPT` / `Codex` | 生成者 |
| 类型 | `输出` / `复审` / `总结` / `提示词` | 文件职能 |
| 主题 | `前向模型冻结规范初版` | 简短说明 |

示例：

```text
97_交互审阅记录/01_Claude输出/04_BlenderOCS方法重建/R06_Claude_输出_前向模型冻结规范最终冻结候选.md
97_交互审阅记录/03_Codex审阅/04_BlenderOCS方法重建/R04_Codex_复审_方法冻结通过.md
```
