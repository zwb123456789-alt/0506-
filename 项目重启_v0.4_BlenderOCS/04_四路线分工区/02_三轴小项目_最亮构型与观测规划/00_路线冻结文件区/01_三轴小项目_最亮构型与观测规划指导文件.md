# 三轴小项目：最亮构型与光路解释指导文件

最后更新：2026-07-06

## 1. 文件性质

本文是路线一 C 之后、路线二/三之前必须执行的小项目指导文件。它不替代路线一 C，也不把当前论文改写成真实未知目标三轴姿态反演系统；它的唯一且最高目标是：在已知卫星模型和前向光学模型下，找出卫星在哪个 yaw / pitch / roll 姿态、哪个太阳入射几何和哪个探测器观测几何下最亮，并解释这束光从哪里入射、照到卫星哪个部位/材料/表面，再沿哪个方向进入探测器。

说明：部分目录名、历史文件名和结果包名仍保留“观测规划 / observation planning”字样以维持路径稳定；这些名称不再定义小项目主目标。当前语义一律以本文件的“最亮构型与光路解释”为准。

## 2. 一句话主线

```text
基于路线一 C 的 v0.4 pixel-level 同源前向模型、B0 工程 baseline 与 B1 书中改进冯模型待确认主线，
在 yaw / pitch / roll 三轴姿态空间与 sun/view 观测几何中搜索最亮构型，
并解释最亮构型对应的太阳入射路径、卫星受光部位、材料/表面响应和探测器接收路径。
```

## 3. 它要解决的问题

本小项目首先且必须回答一个主问题：

```text
卫星在什么 yaw / pitch / roll 姿态、什么太阳入射几何、什么探测器观测几何下最亮；
此时光从哪个方向进入，照到卫星哪个部位、哪种材料或表面，
又以什么反射/散射路径进入探测器。
```

所有其它指标只服务于这个主问题：

1. **亮度层面**：先找出 single-pose top-1 最亮 yaw / pitch / roll / sun / view 组合，明确是否由 glint 或饱和主导。
2. **物理解释层面**：定位 top-1 最亮光度来自哪个受光部位、材料/表面和入射-出射路径。
3. **机制普遍性层面**：在 top-1 已确认后，检验共享同类入射-表面/材料-探测器光路的邻近姿态或候选簇是否普遍高亮；若不是，必须说明 top-1 是否只是局部 glint、饱和、遮挡边界或数值偶然峰。
4. **辅助标注层面**：高信息、低信息、易混淆、不值得观测等只作为最亮构型解释和风险标注，不得替代“找最亮”主目标。

## 4. 输入与继承

必须继承路线一 C 的以下内容：

```text
v0.4 pixel-level OCS-image 同源架构；
B0 工程 baseline；
B1 书中改进冯模型待确认 Method 目标；
GGX / Cook-Torrance 对照与 mismatch 分支；
OCS-only / image-only / fusion / consistency 指标；
candidate distribution、top-k、entropy、margin、JS、overlap、reject/conflict 输出。
```

不得继承旧 v0.3 face-center OCS 作为主结果链。

## 5. 推荐实验结构

### 5.1 姿态空间设计

先做可控规模三轴搜索，不直接全量爆炸：

```text
阶段 A：从路线一 fixed-roll 高亮代表姿态中选种子点，并保留高混淆/高信息样本作为辅助对照。
阶段 B：围绕种子点扫描 roll，观察最亮点和混淆结构是否迁移。
阶段 C：做稀疏三轴随机/网格采样，建立三轴高亮候选集和光路解释候选集。
阶段 D：对候选集做局部加密，输出 single-pose 最亮构型及其入射-表面-探测器光路解释。
```

### 5.2 指标

最少应输出：

| 指标 | 用途 |
|---|---|
| brightness / OCS magnitude | 最高优先级：找 single-pose 最亮 yaw/pitch/roll/sun/view 构型 |
| illuminated part / material / surface trace | 解释最亮光从哪里入射、照到哪里、经什么材料/表面响应 |
| detector path / view trace | 解释最亮光沿哪个方向进入探测器 |
| bright-mechanism generality | 检验同类入射-表面/材料-探测器光路是否对应一片高亮候选簇 |
| saturation / glint flag | 判断最亮是否由 glint 或饱和主导 |
| local contrast | 辅助判断最亮附近是否稳定或易混淆 |
| entropy / margin | 辅助判断候选分布集中程度 |
| top-k stability | 辅助判断最亮构型是否稳定 |
| JS / overlap | 辅助判断 OCS 与 image 是否一致或冲突 |
| geometry utility score | 辅助判断该几何是否值得后续观测 |

### 5.3 关键区分

```text
本小项目的最高标准是找最亮构型及其物理来源。
顺序必须是先确认 top-1 最亮点，再检验该光路机制是否能解释一类高亮构型。
最亮姿态不必等于最有信息姿态；
高信息、低信息、易混淆、观测规划只作为最亮构型的辅助解释和风险标注。
```

## 6. 与路线二/三的接口

### 6.1 路线二接口

路线二提供 GEO 真实光度趋势和多几何现实性锚点。三轴小项目不能要求路线二提供姿态真值，只能使用它验证：

```text
真实光度中是否存在与仿真高亮/低亮预测相符的趋势；
真实 GEO 数据是否覆盖小项目认为有价值的几何区域；
仿真最亮几何是否在真实多帧监测中具有现实出现条件；高信息几何只作为辅助参考。
```

### 6.2 路线三接口

路线三暗室可提供小规模真实光度 + 姿态真值验证。优先验证：

```text
仿真预测最亮姿态是否在暗室实测中仍然高亮；
roll-aware 最亮点是否相对 fixed-roll 发生迁移；
辅助高信息/低信息标注是否能帮助解释最亮构型的稳定性和风险。
```

## 7. 写作定位

本小项目的价值表述应是：

```text
从“光度能否反演姿态”转为“已知模型下，卫星在什么姿态和观测几何下最亮，以及这束最亮光来自哪条入射-表面-探测器路径”。
```

可用表述：

```text
The proposed three-axis search identifies the brightest attitude-geometry configuration and traces the corresponding illumination, material-surface response, and detector-view path under a shared forward optical model.
```

禁用表述：

```text
本文解决了真实未知目标三轴姿态反演。
最亮姿态就是最优反演姿态。
高信息姿态可以替代最亮构型作为主目标。
GEO 数据验证了三轴姿态真值。
暗室三轴结果可直接外推在轨目标。
```

## 8. 最低完成标准

1. 完成 yaw / pitch / roll / sun / view 搜索流程设计。
2. 输出 single-pose 最亮构型清单或图，并明确 roll 是否改变最亮点。
3. 解释最亮构型对应的入射光方向、受光部位、材料/表面响应和探测器接收路径。
4. 检验与 top-1 共享同类光路机制的姿态/几何候选是否普遍高亮，并说明该机制是否形成高亮区域。
5. 标注最亮构型是否伴随 glint、饱和、低信息或不稳定风险。
6. 高信息、低信息和观测规划建议只作为辅助结果，不能替代最亮构型主结论。
