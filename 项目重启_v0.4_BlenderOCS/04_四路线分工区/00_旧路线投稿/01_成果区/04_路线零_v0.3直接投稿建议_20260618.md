# 路线零 v0.3 直接投稿建议

最后更新：2026-06-18

> 性质：路线零投稿策略建议，供作者决定是否推进 v0.3 成稿工程化投稿。
> 本文件不修改 v0.3 正文，不构成投稿决定；正式投稿前仍需作者确认 Q12-Q14、图表、补充材料、期刊格式与投稿系统要求。

## 1. 基本判断

作者计划将 v0.3 成稿作为独立旧版本直接投稿，不带入 v0.4 项目主线。该思路可以成立，但必须严格限定：

```text
路线零 = 独立 v0.3 legacy paper / controlled synthetic benchmark
路线一/二/三 = v0.4 新主线与后续增强层
```

v0.3 的 face-center OCS 逻辑如果在旧稿自身前向模型链条内自洽，可以作为该稿的近似建模口径投稿；它的问题不是“绝对不能发表”，而是不能冒充 v0.4 Blender-derived pixel-level OCS，也不能与路线一的新结果混为同一证据链。

## 2. 推荐投稿档位

推荐定位：

```text
二类 B / 基本 SCI 保底稿
```

推荐顺序：

1. `Acta Astronautica`：主投优先。适合空间目标、受控仿真 benchmark、姿态反演与融合机制诊断。
2. `Advances in Space Research`：备选。适合 SSA、空间目标光学表征、受控仿真与保守边界论文。

暂不建议路线零冲刺：

- `TAES / JGCD`：路线零缺少真实闭环、动态系统、控制/估计系统级证据。
- `Aerospace Science and Technology / CJA`：可作为第二轮考虑，但不应在保底稿工程化前优先冲刺。
- `TGRS / Remote Sensing`：容易被要求真实遥感数据或更强 sim-to-real 证据。

## 3. 直接投稿的最小修改建议

如果作者选择“基本不重写、不重跑，直接推进投稿工程化”，建议至少完成以下低成本调整：

1. 在 Methods 或 Limitations 中明确 OCS 是 v0.3 face-center / facet-level approximation。
2. 在 Limitations 中说明本文未使用 v0.4 Blender-derived pixel-level OCS，不代表后续 v0.4 结果链。
3. 摘要、结论、Discussion 继续保持 synthetic benchmark / no real telescope validation / no operational claim。
4. 不把路线零结果写成真实未知目标完整姿态反演系统。
5. 不在路线零稿件中引用路线一/二/三未完成结果。
6. 补齐 Q12-Q14：Data/Code Availability、Author Contributions、Funding / Conflict of Interest。
7. 完成正式 caption、参考文献编译、补充材料与 source data 编号一致性检查。

## 4. 风险说明

可接受风险：

- 审稿人可能追问 face-center OCS 近似的物理精度。
- OCS / fusion 结果只能代表 v0.3 旧模型链条下的 controlled benchmark，不应被写成 v0.4 结论。

不可接受风险：

- 将 face-center OCS 与 v0.4 Blender-derived OCS 混成同一方法。
- 暗示 v0.3 已完成真实望远镜验证或真实在轨姿态反演。
- 将路线零作为路线一/二/三的前置证据或替代证据。

## 5. 推荐执行路径

```text
1. 作者确认路线零按 Acta / ASR 保底稿推进。
2. 补齐 Q12-Q14 与投稿格式。
3. 对摘要、Methods、Limitations 做一次 face-center OCS 口径声明小修。
4. 做最终红线复查与参考文献 / 图表 / Supplementary 一致性检查。
5. 进入 Acta Astronautica 投稿工程化；若不合适，再切 ASR。
```

路线零投稿不阻塞路线一/二/三；路线一仍按 v0.4 主干继续推进。
