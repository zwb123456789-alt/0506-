## 一、为什么 v0.4 选择完整统一前向模型，而不是只替换 OCS 采样（CR5-001 新增）

### 1.1 两条可选路线

| 路线 | 做法 | 结果 |
|---|---|---|
| **最小替换路线** | 仅把旧模块 A 的 face-center OCS 换成 Blender pixel-level OCS，图像响应链、遮挡定义、数据记录、fusion 输入尽量沿用旧流程 | 工程上能跑，但跑完后解释会变弱 |
| **统一前向模型路线（v0.4 采用）** | OCS 与图像由同一 STL 几何、同一姿态、同一 sun/det 方向、同一 BRDF、同一 camera visibility 与同一 `V_sun_macro` 生成；OCS 是积分读出，image 是空间分布读出 | OCS/image/fusion/退化实验全部可追踪、可复审、不可混用 |

最小替换路线的根本问题不是"不能跑"，而是：OCS 的数据源被修正了，但图像响应链、sun-side visibility、数据记录和 fusion 输入是否同步修正并不清楚。一旦 OCS 与图像不是同源生成，反演性能差异就可能来自两套仿真链路误差，而不是来自两种观测表达本身——这恰恰摧毁了本项目要回答的核心问题。

### 1.2 八角度立论

v0.4 选择完整统一前向模型，不是"为复杂而复杂"，而是为了让"更贴近现实、反演证据更可信、统一前向模型"这三句话站得住脚。

| 角度 | 只换采样的风险 | 统一前向模型的好处 |
|---|---|---|
| **现实观测贴近性** | face-center 三角面中心采样不对应真实成像 | 真实光学观测是对可见投影表面成像，Blender pixel-level geometry pass 更接近 projected image formation |
| **物理一致性** | OCS 和图像可能使用不同遮挡/亮度定义 | 同一表面点的 `f_r`、`NoL`、camera visibility、`V_sun_macro` 同时决定 OCS 积分和图像亮度；OCS 是同一 clean image linear response 的积分，image 是其空间分布 |
| **反演准确性** | 反演误差可能被旧采样误差或链路差异污染 | 不承诺误差必然下降，但让反演结果更可信地反映修正后的观测定义；若误差下降可解释为 corrected OCS signature 更稳定，若不下降也代表更严格物理定义下的结果 |
| **模态公平性** | 误差差异可能来自两套模拟链 | OCS 是积分读出，image 是空间分布读出，二者来自同一前向模型下的不同读出方式，比较才公平 |
| **fusion 可解释性** | fusion 提升可能来自混合两套仿真误差 | fusion 提升可解释为同源低维光度约束与空间图像结构的互补，而非两套链路误差混合 |
| **退化实验可信度** | clean/degraded image 与 OCS 的关系不稳 | 退化只作用在同源 clean image 上，OCS 作为同源低维观测保持不变 |
| **论文防守性** | 易被问"为什么 OCS 和图像来自不同前向模型" | 可写成 observation-consistent synthetic forward model，所有主结果来自同一统一模型 |
| **工程可追踪性** | latest-run 与旧结果易混用 | manifest/source_data 记录 geometry/BRDF/visibility/OCS integration/image preprocess/dataset 六个子版本，杜绝混用 |

### 1.3 结论

v0.4 的"采样更换"不是目的本身，而是重建统一前向模型的入口。统一模型不保证所有指标数值一定更小，但它的首要价值是把观测定义纠正到更一致、更可审计的物理链路上；评价标准不只看误差是否下降，而是看：数据源是否一致、观测定义是否可信、模态比较是否公平、退化条件下的互补解释是否成立。

## 二、v0.4 前向模型总图（CR4-001 已修正）

```text

           同一太阳/观测方向向量 (sun_dir, det_dir)
                          │
         ┌────────────────┴────────────────┐
         │                                 │
    Blender Cycles                    Python 公式
    (geometry pass only)              (explicit BRDF + OCS)
         │                                 │

    depth / normal / IndexOB           f_r(N, L, V; material_params)
    Position / WorldCoord                    │
    pixel-level visibility            ┌─────┴─────┐
         │                            │           │
    Sun Shadow Pass               OCS 积分      图像线性响应
    (shadow_mapping_method)   Σ A_pix·f_r·NoL·  I_linear(p) = f_r(p)·
         │                     V_sun_macro      NoL(p)·V_sun_macro(p)
         │                    per-part + total   (per pixel)
         │                         │           │
         └─────────┬───────────────┘           │
                   │                    log1p 变换 + 8-bit PNG
           Blender-derived                     │
           OCS manifest                  训练输入
           (canonical OCS)              (image-only / fusion)
                   │
        ┌──────────┼──────────┐
        │          │          │

```

**一句话总结**（CR4-001 修正）：OCS 和图像线性响应均含 `V_sun_macro`，来自同一统一前向物理模型。若 visibility 降级为 `camera_visible_nol`，则 `V_sun_macro ≡ 1`（即 `v_sun_macro_mode = "identity"`），自然退化回旧公式。

**与旧版（07_Claude修订版）的关键差异**：
- 总图中图像线性响应从 `I_linear = f_r·NoL` 改为 `I_linear = f_r·NoL·V_sun_macro`
- Blender 分工新增 Position/WorldCoord pass 和 Sun Shadow Pass

## 三、Blender / Python / 反演代码分工

### 3.1 Blender 负责（geometry pass + sun shadow pass）

| 职责 | 说明 |
|---|---|
| STL 导入与姿态变换 | 三部件（jinshuzhuti / taiyangnengban / yinshenban）统一管理 |

| depth pass | 像素级相机可见性判定（depth < 1e9 → object pixel） |
| normal pass | 逐像素世界坐标法线（N_world，未归一化，需 Python 端归一化） |
| IndexOB pass | 部件分区：0=背景, 1=jinshuzhuti, 2=taiyangnengban, 3=yinshenban |
| **Position/WorldCoord pass**（CR4-002 新增） | 逐像素世界坐标（用于 sun shadow reprojection） |
| **Sun Shadow Pass**（CR4-002 新增） | 见 §7 可执行定义 |
| 视角可见性（camera visibility） | 光栅化 depth-buffer 自然处理：被其他部件或自身背面遮挡的面元不出现在像素中 |

**Blender 不做的事**：
- 不使用 Blender Principled BSDF / Combined pass 作为最终亮度模型
- 不依赖 Blender shading normal 的自动翻转行为
- 不使用 Backfacing AOV 作为 OCS 积分判据

### 3.2 Python 公式负责

| 职责 | 说明 |
|---|---|
| GGX/Cook-Torrance BRDF | `f_r = f_diffuse + f_specular`，参数来自 `materials.py` 的 `_GGX_DB` |
| NoL / NoV / NoH 几何项 | 显式计算，`NoL = max(dot(N, L), 0)`, `NoV = max(dot(N, V), 0)` |

| per-part OCS | 按 IndexOB 分区累计 |

| log1p 变换与 PNG 输出 | 见 §8 |
| 退化模型 | noise/blur/downsample/background/starfield 均为后处理压力测试 |

## 四、坐标系与姿态定义

### 4.1 世界坐标系

- 右手系
- Blender 默认：+Z 为 up，+Y 为 front
- Python 端与 Blender 端使用同一世界坐标系

### 4.2 姿态定义

- **姿态参数**：(yaw, pitch)，roll ≡ 0
- **旋转顺序**：Z-Y-X 内旋：`R = Rz(yaw) · Ry(pitch) · Rx(0)`

**Yaw 网格**：

| 用途 | 网格 | 数量 | 说明 |
|---|---|---|---|
| **训练/反演/OCS manifest** | yaw ∈ [0°, 355°]，步长 5° | **72 个唯一值** | 0° 和 360° 是同一姿态，不在训练集中重复 |
| **绘图 heatmap seam** | yaw ∈ [0°, 360°]，步长 5° | 73 个值（0° 复制为 360°） | 仅用于可视化，使 heatmap 在 0°/360° 处自然闭合 |

**Pitch 网格**：[-90°, 90°]，步长 5°，共 37 个值。

**总训练姿态数**：72 × 37 = **2664**（不含 360° 重复）。

**姿态正方向**：
- yaw：从 +Z（up）轴向原点看，逆时针为正
- pitch：从 +Y（front）轴向原点看，绕 +X 旋转，目标"抬头"为正

### 4.3 太阳/观测方向

- `sun_dir` 和 `det_dir` 在世界坐标中定义，使用前归一化为单位向量
- 多观测几何（multi-geom）：5 组 sun/det 配置，相位角覆盖 24°~120°
- 单观测几何（single-geom/phase63）：1 组 sun/det，相位角 63°

**归一化要求**：所有方向向量在 BRDF 计算前均须归一化为单位向量。

### 4.4 法线坐标系

- Blender EXR Normal pass 输出**世界坐标法线**
- Python 端读取后显式归一化：`N_world = N_world / ||N_world||`

## 六、OCS 积分定义

### 6.1 连续形式

```
OCS = ∫_{S_visible} f_r(ω_i, ω_o, N(x)) · cos(θ_i) · V_sun_macro(x) · dA_projected
```

其中：
- `S_visible`：相机可见的目标表面（camera-visible pixels）
- `f_r`：GGX/Cook-Torrance BRDF（见 §9）
- `cos(θ_i) = NoL = max(n·sun, 0)`
- `V_sun_macro(x)`：宏观太阳方向可见性乘子 ∈ {0, 1}
- `dA_projected`：面元在像平面上的投影面积（正交投影下为常数 pixel_area）

### 6.2 像素离散形式（正交投影）—— CR4-001 联动，图像同步

**OCS 离散公式**：

```
OCS = Σ_{p ∈ visible} A_pix · f_r(p) · NoL(p) · V_sun_macro(p)
```

**图像线性响应**（CR4-001 修正——与 OCS 同源）：

```
I_linear(p) = f_r(p) · NoL(p) · V_sun_macro(p)
```

**一致性声明**（CR4-001 关）：OCS 积分和图像线性响应使用完全相同的 `f_r(p)`、`NoL(p)`、`V_sun_macro(p)`。若 visibility 降级为 `camera_visible_nol`，则 `V_sun_macro ≡ 1`（`v_sun_macro_mode = "identity"`），两者同步退化。

其中：
- `A_pix = (ortho_scale / resolution)²`（常数，正交换算，单位 m²）
- `f_r(p)` = GGX/Cook-Torrance BRDF 值（标量）
- `NoL(p) = max(N(p) · L, 0)`
- `V_sun_macro(p) ∈ {0, 1}` 见 §7

### 6.3 NoV 抵消的成立条件

1. **正交投影**：所有像素的 `A_pix` 为同一常数
2. **NoV > 0**：NoV ≤ 0 的像素 OCS 贡献显式为 0（见 §6.4）
3. **无 fractional coverage**：假设像素全部覆盖目标（边缘像素见 §6.5）

### 6.4 NoL/NoV 边界条件

| 条件 | 处置 | 原因 |
|---|---|---|
| NoV ≤ 0 | 像素 f_r = 0, I_linear = 0, OCS contribution = 0 | 该像素为背面/切面，BRDF 分母含 NoV |
| NoL ≤ 0 | 像素 f_r = 0, I_linear = 0, OCS contribution = 0 | 太阳在表面背后，该处不被照亮 |

### 6.5 A_pix 定义与边缘像素处理

```
A_pix = (ortho_scale / resolution)²
```

其中 `ortho_scale = 2.2 × r_max`。

**边缘像素 fractional coverage**：
- 目标边缘的像素仅部分覆盖目标表面，其余为背景
- v0.4 不做 fractional coverage 修正，接受为已知舍入误差
- 方法文件中记录此简化假设

## 七、Sun-Side Visibility / Self-Shadow（CR4-002 可执行定义；CR5-002/003 矩阵与 depth 修正）

### 7.1 导航：三种可见性层次

| 层次 | 名称 | enum 值 | 含义 |
|---|---|---|---|
| Level 1 | Camera-visible + NoL | `camera_visible_nol` | 像素对相机可见，且 `NoL > 0` 时有贡献（`NoL ≤ 0` 贡献归零）。`V_sun_macro ≡ 1`（mode=identity） |
| Level 2 | + Blender sun shadow reprojection | `camera_visible_nol_plus_sun_shadow_pass` | Level 1 + camera-view pixel → world point → sun-view depth comparison → V_sun_macro ∈ {0,1}（mode=shadow_mask） |
| Level 3 | + Python ray-cast | `camera_visible_nol_plus_python_raycast` | Level 1 + Python trimesh+Embree ray-cast 逐像素判定 sun-ray 遮挡 |

### 7.2 冻结决策：主线使用 Level 2

**v0.4 主线优先实现 `camera_visible_nol_plus_sun_shadow_pass`**。

**降级预案**：
1. 先用 20 个代表姿态做小规模验证（见 §12.6）
2. 如果 Blender sun shadow reprojection 在技术上不可行，降级为 `camera_visible_nol`
3. 降级时必须：论文写作边界显式声明未实现 sun-side self-shadow

### 7.3 Sun Shadow Pass 可执行数据流（CR4-002 落地；CR5-002 矩阵方向修正）

#### 7.3.1 矩阵约定（CR5-002 关键修正）

**首先冻结矩阵方向约定，杜绝方向写反：**

```text
camera_matrix_world        : camera local  -> world   （Blender 相机世界矩阵）
sun_camera_matrix_world    : sun camera local -> world （sun-view 相机世界矩阵）
world_to_camera_matrix     = inverse(camera_matrix_world)      : world -> camera local
world_to_sun_camera_matrix = inverse(sun_camera_matrix_world)  : world -> sun camera local
```

齐次坐标点的正确变换方向：

```text
P_world      = camera_matrix_world @ P_camera_local
P_camera_local = world_to_camera_matrix @ P_world
P_sun_local  = world_to_sun_camera_matrix @ P_world
             = inverse(sun_camera_matrix_world) @ P_world
```

> **禁止再写** `P_sun_cam = sun_camera_matrix_world · P_world`。
> **禁止再写** `P_world = camera_matrix_world.inverse() · P_cam`。
> 把世界点变换到某相机 local 必须用该相机世界矩阵的**逆**；把相机 local 点变换到世界才用该相机世界矩阵本身。

#### 7.3.2 推荐主线方案 A：camera-view Position + sun-view depth reprojection

```text
Step 1：Blender camera-view 渲染
  输出：depth (H×W), normal (H×W×3), IndexOB (H×W),
        world_position (H×W×3, 优先 Position AOV；否则由 depth + camera 矩阵重建，见 §7.4)
  已知：camera_matrix_world (camera local -> world)
         ortho_scale_m, resolution

Step 2：Blender sun-view 渲染（同一姿态、同一几何、同一 ortho_scale）
  相机旋转矩阵替换为 look_at(sun_dir)，正交投影参数不变
  输出：sun_depth (H×W)
  已知：sun_camera_matrix_world (sun camera local -> world)

Step 3：Python 端 sun shadow reprojection（CR5-002 矩阵方向已修正）
  world_to_sun_camera = inverse(sun_camera_matrix_world)
  FOR each camera-visible pixel p:
    P_world = world_position[p]                              ← camera-view 3D 世界点
    P_sun_local = world_to_sun_camera @ P_world             ← 世界点 → sun camera local（用逆矩阵）
    (u_sun, v_sun) = project_ortho(P_sun_local, ortho_scale, resolution)
    sun_depth_reproj = depth_along_view(P_sun_local)        ← 沿 sun-view 视线方向的深度，
                                                              符号/轴向以 Blender depth 定义为准（见 §7.4）
    sun_depth_actual = nearest_sample(sun_depth, u_sun, v_sun)  ← CR 改进：最近邻采样，
                                                                  避免轮廓边缘双线性插值产生中间深度误判
    V_sun_macro[p] = (sun_depth_reproj <= sun_depth_actual + depth_epsilon_m)
  END FOR

Step 4：输出
  V_sun_macro_mask (H×W, uint8, 0/1)，与 camera-view 像素对齐
  写入 manifest 的 sun_visibility_mask_path
```

> **深度采样说明（改进）**：sun-view depth 比较使用**最近邻采样**而非双线性。双线性在物体轮廓/部件边界处会把前景深度和背景 1e10 插值出中间值，导致 sun-side 遮挡误判。最近邻配合 `depth_epsilon_m` 容差是更稳的做法。

#### 7.3.3 备选方案 B：Blender 同相机视角 Shadow AOV

如果 Blender 支持同一 camera-view 渲染时直接输出 Shadow AOV（在 camera-view 相机内部计算 sun light shadow），则不需要 reprojection。但需要验证：
- Blender Cycles Shadow AOV 是否与 camera-view 像素对齐
- 阴影判断是否与几何可见性一致（非材质光照）

**方案选择**：先尝试方案 A（reprojection），因为已有 `brdf_postprocess.py` 的 EXR 读取基础设施。如果 Sun Shadow AOV 更简单可靠，改为方案 B。

**实现优先级顺序**：
1. 先在 camera-view 渲染中尝试输出 Position/WorldCoord pass（Blender AOV 支持）
2. 如果 Blender 不支持 Position AOV，在 Python 端由 depth + camera 矩阵反投影（§7.4）
3. Sun-view 渲染 depth EXR（与 camera-view 相同 ortho_scale/resolution）
4. Python reprojection 生成 V_sun_macro_mask

### 7.4 反投影与 depth 定义（CR5-002/003 修正——不写未验证公式）

#### 7.4.1 世界坐标重建（当 Blender 不输出 Position AOV）

正交投影下，像素 (u, v) + depth 反投影到相机 local，再变换到世界：

```text
# 像素 → 相机 local 的横向坐标（正交投影，ortho_scale 为视口物理宽度）
x_cam_local = (2 * u / resolution - 1) * ortho_scale / 2     # u ∈ [0, resolution-1]
y_cam_local = (2 * v / resolution - 1) * ortho_scale / 2

# 相机 local 的视线方向坐标 z_cam_local 由 depth 给出：
#   Blender 相机 local 视线通常沿 -Z，depth 为沿视线的正向距离。
#   因此 z_cam_local 的符号（depth 还是 -depth）必须以 Blender 实际导出为准，
#   严禁在本规范中预写 z_ndc = 2*depth/ortho_scale 之类未验证编码。
z_cam_local = <由 §7.4.2 round-trip 校验确定的 depth→local-z 映射>

P_camera_local = (x_cam_local, y_cam_local, z_cam_local, 1)
P_world = camera_matrix_world @ P_camera_local              # camera local -> world（不取逆）
```

> **CR5-003 要求**：正交投影 depth 的符号、单位、相机 local z 方向**必须以 Blender 导出的 depth 定义为准**，先做 round-trip 校验确认映射，再写进实现常量。不得把 `z_ndc = 2*depth/ortho_scale` 或 `sun_depth_reproj = P_sun_cam.z` 当作既定事实写入。

#### 7.4.2 Depth round-trip sanity check（CR5-003 新增，代码阶段必做）

进入正式重投影前，先用 **3 个已知世界点**做两条 round-trip 校验，确认 depth 符号与坐标映射：

```text
检查 1（camera-view round-trip）：
  camera pixel (u,v) + depth
    → P_camera_local（用 §7.4.1 映射）
    → P_world = camera_matrix_world @ P_camera_local
    → P_camera_local' = world_to_camera_matrix @ P_world
    → 重投影 pixel (u',v') 与 depth'
  断言：(u',v') ≈ (u,v) 且 depth' ≈ 原 EXR depth（在数值容差内）

检查 2（sun-view round-trip）：
  已知 sun-view 世界点 P_world
    → P_sun_local = world_to_sun_camera_matrix @ P_world
    → 重投影 (u_sun, v_sun) 与 sun_depth_reproj
    → 与 sun-view EXR 在 (u_sun, v_sun) 处的 depth 比较
  断言：sun_depth_reproj 与 EXR depth 的符号、量级一致
```

只有两条 round-trip 全部通过，才允许把对应的 depth→local-z 映射常量写入实现，并继续 §12.6 的 20 姿态验证。

### 7.5 Depth Epsilon 设定（CR5-006 修正——初始/校准两段）

- `depth_epsilon_m_initial = 1e-3` m（**初始候选值**，量级约为模型尺度的小量；不是最终物理常数）
- `depth_epsilon_m_final`：由 §12.6 的 20 姿态 shadow validation 校准后确定，并写入 manifest 字段 `depth_epsilon_m`
- 校准目标：在与模型尺度、depth pass 精度、边缘误差绑定的前提下，确保 V_sun_macro 既不因数值精度误判遮挡，也不因容差过大漏判遮挡
- manifest 中 `depth_epsilon_m` 记录的是**校准后的最终值**（见文件 14 §2.1）

### 7.6 OCS 公式中的 V_sun_macro

在 baseline（未实现 sun shadow，mode=identity）下所有像素 `V_sun_macro ≡ 1`，公式退化为 `OCS = Σ A_pix · f_r · NoL`。sun shadow 实现后（mode=shadow_mask），`V_sun_macro` 从 sun shadow reprojection 得到。

## 八、Clean Image 线性响应与 log1p/PNG/训练输入（CR4-001 联动修正）

### 8.1 旧链问题确认

旧链存在编码不一致：写入端 gamma 2.2 PNG，读取端 /255 后叠加 log1p，实际经历了 gamma 2.2 + log1p 双重非线性。

### 8.2 v0.4 统一图像响应链（CR4-001 修正——加入 V_sun_macro）

**Step 1：线性辐亮度生成**
```
I_linear(p) = f_r(p) · NoL(p) · V_sun_macro(p)    [per pixel]
```
若 visibility 降级为 `camera_visible_nol`，则 `V_sun_macro(p) ≡ 1`（mode=identity）。

**Step 2：全局归一化**
```
I_norm(p) = I_linear(p) / I_scale
```
- `I_scale` = v0.4 clean corpus 全局最大 I_linear 值
- `I_norm ∈ [0, 1]`

**Step 3：log1p 变换**
```
I_log(p) = log1p(α · I_norm(p)) / log1p(α)
```
- `α = 10.0` 作为初始默认值
- 正式全链路重跑前做 quick ablation（候选 α ∈ {5, 10, 20} + raw）

**Step 4：8-bit PNG 存储（训练输入）**
```
PNG(p) = clip(round(I_log(p) · 255), 0, 255)
```

**Step 5：训练时加载**
```python
arr = np.asarray(img, dtype=np.float32) / 255.0    # → I_log ∈ [0, 1]
```

**Step 6：退化实验的作用域**
- 噪声/模糊等退化在**线性空间**（I_linear）施加

### 8.3 原始线性辐亮度数据保留

- **保留 linear EXR（float32）作为 canonical raw data**
- 每次 brdf_postprocess 输出：
  - `{key}_linear.exr`：I_linear per pixel（浮点，lossless）
  - `{key}_brdf.png`：I_log 8-bit PNG（训练输入）

## 九、GGX/Cook-Torrance BRDF 主模型（CR4-004 数值 eps 规则）

### 9.1 模型公式

```
f_r(N, L, V) = f_diffuse + f_specular

f_diffuse = (base_color / π) · (1 - metallic) · (1 - F0)

f_specular = D_GGX(N, H, roughness) · G_Smith(N, L, V, roughness) · F_Schlick(H, V, F0)
             ─────────────────────────────────────────────────────────────────────────
                                        4 · NoL · NoV
```

### 9.2 有效像素判定规则（CR4-004 修正——防除零/NaN）

**有效像素必须同时满足**：
```
NoV > eps   AND   NoL > eps
```

其中 `eps = 1e-6`（写入 `brdf_version` 说明）。

**无效像素处置**：
```
f_r = 0
I_linear = 0
OCS contribution = 0
```

**计算顺序**：
1. 先判定 `NoV > eps` 且 `NoL > eps`，过滤有效像素
2. 对有效像素计算 `f_r = f_diffuse + f_specular`
3. 再计算 `I_linear = f_r · NoL · V_sun_macro`
4. OCS = Σ A_pix · I_linear

**禁止**：先计算 `f_specular` 再检查 `NoL > eps`（分母 `4·NoL·NoV` 会在 NoL=0 或 NoV=0 时产生 inf/NaN）。

### 9.3 材料参数（与 `_GGX_DB` 一致）

| 参数 | jinshuzhuti | taiyangnengban | yinshenban |
|---|---|---|---|
| base_color | 0.91 | 0.15 | 0.08 |
| metallic | 1.0 | 0.0 | 0.0 |
| roughness | 0.20 | 0.40 | 0.90 |
| F0 | 0.91 | — | — |
| ior | — | 1.5 | 1.5 |

`base_color` 为标量（灰度 BRDF）。以上为 nominal synthetic parameters。

### 9.4 LegacyPhong 的处理

- LegacyPhong **不作为** v0.4 主线 BRDF
- 不作为 v0.4 主线必做项
- 保留 `eval_legacy_phong()` 函数

## 十一、Single-Geom 主线与 Multi-Geom 扩展的可见性一致性（CR4-005 修正）

### 11.1 一致性要求

**主线 single-geom（phase63）**：
- camera geometry pass → sun shadow pass → BRDF 后处理 → OCS/integration → manifest
- image 线性响应同样使用 `V_sun_macro(phase63)`
- 公平基线

**扩展 multi-geom（concat5, 其余 4 组 sun/det）**：
- **每个 geom** 都必须生成完整的 camera geometry pass + sun shadow pass + BRDF/OCS 后处理（CR4-005 修正——不能只给 phase63 做 shadow）
- image 侧仍只用 phase63（固定观测几何，作为 fusion 多几何增强的设定）
- 如果 multi-geom 采用 Level 2 visibility，则 5 组 geom 各有一致的 sun shadow 产物

### 11.2 禁止的不一致

- ❌ single-geom 使用 Level 2，某 multi-geom 使用 Level 1
- ❌ multi-geom 中只有 phase63 有 sun shadow pass，其余 4 组没有
- ❌ OCS concat5 混合使用不同 visibility 层级的 per-geom OCS

## 十三、写作边界

1. **Synthetic forward model only**：无真实望远镜图像、无真实大气链路、无真实探测器标定。
2. **No real telescope validation**：不声称 field-proven robustness。

4. **Sun-side visibility 声明**：
   - 如果 sun shadow pass 实现成功：写 "sun-side self-shadowing is explicitly modeled via Blender shadow pass reprojection"
   - 如果降级：写 "visibility is defined by camera-viewer-side depth-buffer; sun-side self-shadowing is not explicitly modeled and is left for future work"
5. **Observation-consistent, not observation**。
6. **No inter-satellite occlusion**：仅建模单目标自身遮挡。
7. **OCS 与图像必须同源**：论文中 OCS 和图像数据必须来自同一 `V_sun_macro` 层级（同一 `sun_visibility` + `shadow_mapping_method` + `v_sun_macro_mode`）。
