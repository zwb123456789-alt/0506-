# 013 专家问答二：工作流审阅与八项改进建议

生成时间：2026-07-06
性质：作者与 Claude（资深专家学者角色）问答存档。本文为专家审阅意见，不是路线裁决，不改任何冻结文件与成果区；采纳与否由作者/Codex 裁决。
配套文件：`016_工作流改进方案_八项建议落地.md`（作者已采纳全部建议后的落地方案）。

---

## 一、作者问题原文

> 对于我的工作流你有没有什么建议

---

## 二、总体判断

作者的工作流（Codex 设计/审阅/阶段门 + Claude 长程执行 + 成果区分流 + 红线自查 + 数值一致性核验）本质上是一个微型同行评审系统，这在研究生个人项目里是罕见的纪律水平，也是论文防线的真实来源——审稿人问任何一个数字都能溯源。骨架不要动。

但当前有五个问题在积累：**阶段门碎片化、入口文件膨胀、评审回音室、写作债务、术语私有化**。最直接的后果：三轴小项目这种"论文里一节"的内容消耗了 R130→R157 共 28 份审阅文件的流程成本，而真正决定投稿档位的事（真实数据锚点、论文成形）反而排不上队。

---

## 三、要保持的（优化时不要误伤）

1. **成果区 / Claude输出 / Codex审阅的物理分流**——防止"候选材料混入结论"的核心机制。
2. **红线自查表 + 数值一致性核验 + manifest 审计**——可直接转化为论文 reproducibility statement 和 SI，审稿加分项。
3. **负结果归档并归因**（而不是删掉重跑）——P-EXT 坍缩、joint 无增益的完整归因链是诚实性证据。
4. **预注册习惯的雏形**（R126 先定范围再执行）——建议 5 将其正式化。

---

## 四、八项改进建议（按优先级）

### 建议 1：给局部搜索类任务定"收敛判据"，停止一次一个角落的微阶段门（最紧迫）

三轴小项目 P4-PHYS-A→A2→B→C→D→E→F 的推进方式是：每轮小矩阵 → 发现新角落 → 再开一轮。C_R3 之后还会有新角落，该模式没有自然终点。每轮流程成本（任务单 + 执行报告 + 审阅 + CLAUDE.md 同步）约等于甚至超过实验本身。

改法：对所有"局部加密/边界追加"性质的任务，在任务单里预先写死停机规则：

```text
停机条件（满足其一即收口）：
a) 新 top 相对当前 top 的增量 < 1%，且不在采样边界；
b) 累计渲染预算耗尽（如 ≤200 单元）；
c) 已完成两轮加密仍出现新角落 → 直接接受"采样包络内局部最优"表述收口。
```

科学上完全站得住：论文只需要"在受控采样包络内的最亮构型及其机制"，不需要全局最优。P4-PHYS-F 建议按此规则执行，F 完无论结果如何都收口。

### 建议 2：CLAUDE.md 瘦身 + 修复 AGENTS.md 失步（零成本高回报）

现状：CLAUDE.md 的 1.2 节、4 节、6 节、7 节把同一批 ~30 个 R 文件路径重复列了三四遍，第 7 段一个自然段塞了整个项目史；AGENTS.md 停在 2026-06-30 的"等待 B6-FIX01"状态，与 CLAUDE.md（R157）差了一整个阶段。每个新会话都在为膨胀的入口文件付上下文税，失步文件是新会话误判状态的直接风险源。

改法：
- CLAUDE.md 只保留一张状态表（每条路线一行：当前阶段 / 最近裁决 / 下一步 / 入口文件），R 链全表移入独立的 `00_审阅链索引.md`，按需读取；
- 同步规则从"追加"改为"替换"——每次 Codex 通过后重写状态表那一节，不往第 7 段续写；
- 立即修 AGENTS.md 第 2 节（或让它不再承载阶段状态，只写职能分工，状态一律指向 CLAUDE.md——单一事实源原则）。

### 建议 3：打破评审回音室——引入"冷启动外审"机制（对顶刊目标最关键）

当前闭环是 Codex 设计 → Claude 执行 → Codex 审阅 → 作者仲裁。三方共享全部项目记忆和术语体系，系统性盲区是：内部一致性会被误认为外部说服力。"头B""L1-G1""23A包""PARTIAL_GENERALITY"这套私有语言内部运转良好，但真实审稿人没有任何这些上下文。

改法：在关键节点（三轴收口后、投稿前）插入"冷启动外审门"——用一个不加载任何项目记忆的新会话，只给它论文形态的材料（图 + 图注 + 摘要 + Methods 骨架），让它以目标期刊审稿人身份攻击。它读不懂的地方就是真实审稿人读不懂的地方；它问出的"这不就是 XX 吗"，就是 Introduction 要提前拆的雷。成本极低，是当前工作流里唯一缺失的"外部性"。

### 建议 4：现在就开始建"论文骨架"资产，停止把写作排在所有实验之后

当前流程把写作放在"全部收口之后"，对顶刊目标是错误顺序——图先行（figure-first）才能暴露证据链的真实缺口。R121/R123 的 Results/SI 准备包是"证据包"不是"论文"。

改法：新建一个持续维护的骨架文件，内容只有一张表：

```text
主图编号 | 一句话 claim | 当前最佳版本路径 | 证据强度（够/不够/缺） | 缺口对应哪个未完成任务
```

每次阶段门通过就更新一行。这张表会立刻告诉作者：哪些实验是给论文服务的、哪些是流程惯性；也会让"GEO 锚点两图"这类高杠杆任务的优先级变得无法忽视。维护成本每周十分钟。

### 建议 5：把预注册正式化为一种文件类型

即将启动的新路线二（退化参数、判定阈值）最容易被指控"调参造增益"。已有预注册实践雏形（R126），升级为正式机制：

```text
00_路线冻结文件区/ 下新增 preregistration 类文件：
执行前冻结退化参数、主指标、判定阈值、停机规则，标注日期；
执行报告必须声明"与预注册的偏离项及原因"。
```

该文件将来直接作为 SI 附件——"我们先定了标准再看结果"是对审稿人最有力的一句话。

### 建议 6：利用好 D/A/C 风险分级——D 类任务打包执行

AGENTS.md 已写 D 类（只读诊断/重聚合/核验）用短流程，但实践中 D 类任务仍走"一任务一门"的完整仪式。改法：允许一张任务单打包 3–5 个 D 类子任务（例如"GEO 两图 + 术语映射表 + 图表清单更新"一次下发、一次审阅），Codex 一次性审。C 类（新训练、split 变更、主 claim）维持完整阶段门不动。

### 建议 7：git 提交与阶段门对齐

当前提交是大批量打包（一个 commit 覆盖几十个文件、多个阶段）。改为每个阶段门通过后提交一次，commit message 带 R 编号。"某个结论在哪个版本产生、当时代码什么状态"可精确回溯——投稿后被要求补实验时，这是救命的。

### 建议 8：建一张"私有术语 → 论文术语"映射表

写作阶段要把 头B/B6-FIX01/L1-G1/P-INT/P-EXT/P-DB/23A包 这套语言整体翻译成期刊语言。翻译越晚做，扭曲和遗漏越多。现在就建一张两列表（内部名 | 论文名 + 一句定义），每个新概念产生时顺手登记。同时服务建议 3 的冷启动外审和建议 4 的论文骨架。

---

## 五、总的判断

当前工作流在"防错"维度上已经过度武装，在"产出牵引"维度上装备不足——它能保证做出来的每一块都可信，但不能保证做的是对投稿最重要的那块。八条里，建议 1（停机规则）、2（入口瘦身）、4（论文骨架）是给流程减负和转向；建议 3（冷启动外审）、5（预注册）是把已有纪律转化为审稿人可见的防线。整体精神一句话：

> **让流程为论文服务，而不是让实验为流程服务。**
