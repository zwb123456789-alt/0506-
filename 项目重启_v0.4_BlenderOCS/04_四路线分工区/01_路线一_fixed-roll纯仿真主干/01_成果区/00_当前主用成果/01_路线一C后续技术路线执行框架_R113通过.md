## 1. 当前路线复位

路线一 C 后续不再把 yaw-block single-frame CNN 外推成败作为唯一主线。后续回到 24 号冻结定义：

```text
model-known 条件下，
独立 OCS 光度通道与图像成像通道共享同一物理前向模型时，
跨几何 OCS 多观测光度向量与图像通道对姿态信息的可观测性、互补性和置信一致性研究。
```

现有 C2/C3/B6 负结果作为留存对照和边界诊断，不再继续扩展 single-frame 判据轴。头B旧负结果追因阶段在 R113 后阶段性收束；后续不再围绕旧 single-frame 负结果追加小实验，而是转入 L1(M2) 多几何 OCS 主线。

## 2. 三轴矩阵

### 2.1 观测方式轴

```text
F1: 单几何总光通量标量，信息下界 baseline，必做。
L1: G1/G3/G5 跨 sun/view 几何的多观测总光度向量，主线 OCS，必做。
L2: 时域光变/稀疏光度时序，条件触发分支，不阻塞路线一 C 主干闭口。
F2: per-part OCS，只作 semi-oracle / diagnostic，不作为现实主线输入。
```

L1 的核心是：

```text
同一姿态，在多个已知 sun/view 几何下分别获得总光度标量，
拼成长度为 G 的多观测光度向量。
```

这不是几何外推，也不是路线二真实跨时间多几何；它是 simulated multi-view geometry。

预注册默认几何集合（复用 config_v0_4.py 已预留 OBS_GEOMETRIES G0~G4，嵌套设计）：

```text
G1 = {phase63}                          ← 复用现有，与 C2/C3 负结果同几何，可直接对照、免重渲
G3 = {phase63, G_低相位, G_高相位}        ← 在 G5 内拉开相位角跨度
G5 = {G0,G1,G2,G3,G4} 全 5 组            ← 已预留完整集
约束：G1⊂G3⊂G5（嵌套）→ "加几何=单调加信息"，增益曲线无混淆、可解释。
```

### 2.2 反演协议轴

```text
P-EXT: yaw-block strict extrapolation，降级为 stress test / 边界诊断。
P-INT: 多数据训练 + 未训练精确姿态插值/局部泛化，作为主任务。
P-DB: template/database/posterior-like 候选分布，只输出 top-k 与置信，不写真实反演成功率。
```

后续主线采用 P-INT；P-EXT 保留用于边界，不再独占路线一 C。

P-DB 预注册默认设计：

```text
库     : 训练姿态网格(72×37)对应的 OCS/特征模板（多观测光度向量）
相似度 : L2 / cosine on 多观测光度向量
输出   : top-k 候选姿态 + 置信分布（不输出唯一姿态、不写"成功率"）
```

### 2.3 真实性轴

```text
clean: 受控干净仿真上界。
degraded: 物理合理退化，用于真实感、鲁棒性和防 inverse crime。
```

degraded 不复用 B6 的粗增广包作为正式噪声模型。后续应优先采用：

```text
PSF/模糊；
Poisson/read noise；
背景与梯度；
曝光/低分辨率；
测光误差；
必要时再考虑运动拖影。
```

预注册默认参数范围（物理合理、可做 ablation）：

```text
PSF      : 高斯 σ ∈ {0.5, 1.0, 1.5} px
噪声     : Poisson(shot) + Gaussian(read)，SNR ∈ {30, 20, 10} dB
背景     : 均匀天光 + 线性梯度
分辨率   : 下采样 ×{1, 2}
明确避开 : B6 那组 σ=0.01+亮度±10%+整数平移（已证 fold0 有害，不复用）
```

## 3. 分析维

后续结果不以单张误差表为中心，应保存和分析：

```text
D1 per-part OCS 归因：只作 semi-oracle 诊断。
D2 互补性：image vs OCS vs joint 的 top-k overlap / disagreement。
D3 置信一致性：entropy、margin、JS divergence、overlap 与 error 的关系。
D4 可观测性地图：姿态空间中哪些区域可观测、不可观测、易混淆。
```

训练或后处理必须保存 per-attitude 结果和候选分布所需中间量，否则无法支撑 24 号三问。

## 5. L1(M2) 执行原则

L1(M2) 下一轮应作为长程执行任务，而不是方案盘点。

最低要求：

```text
1. 读取 R113 与本文件。
2. 定位现有 phase63/G1 数据、config 中 OBS_GEOMETRIES、渲染与训练入口。
3. 预注册 G1/G3/G5 几何集合，优先嵌套设计 G1⊂G3⊂G5。
4. 如 G3/G5 数据缺失，按阶段门允许执行必要新渲染或特征生成。
5. 建立 F1 与 L1 多几何总光度向量输入，不把 per-part 当现实主线输入。
6. 以 P-INT 为主协议，P-EXT 作为 stress test 对照。
7. 输出 OCS-only、image_only、joint 的可审计结果。
8. 保存 top-k、posterior-like score、entropy、margin、overlap/JS、per-attitude error 等后续置信一致性所需文件。
9. 写执行报告、日志、CSV/JSON/NPZ/图表，交 Codex 审阅。
```

若 G3/G5 几何配置与代码预留不一致，Claude 只能报告阻塞和证据路径，不得自行改路线定义。

## 6. roll 与三轴小项目边界

路线一 C 主跑仍是：

```text
fixed-roll yaw-pitch controlled benchmark
```

但必须保留 M-roll：

```text
roll sensitivity 探针用于验证 fixed-roll 结论是否被有限 roll 扰动推翻。
```

M-roll 预注册默认取值：

```text
roll ∈ {0°(基准), +15°, −15°, +30°, −30°}
仅在 1 个代表几何(G3) × {image_only, joint} 两通道上重跑（小探针量级，不铺满全矩阵）。
```

M-roll 不是三轴小项目替代品。三轴小项目后续才负责：

```text
yaw / pitch / roll 三轴姿态空间中的最亮构型、高信息姿态、低信息区域和观测规划。
```

## 7. L2 与路线二边界

L2 光变或稀疏光度时序是条件触发分支：

```text
若 L1/M2 失败，或作者确认真实数据主来源必须以时序形态进入，
再单独设计 T3/L2 阶段门。
```

路线二 GEO 数据可作为 sim-to-real 光度趋势、分布和多帧多几何现实性锚点，但它：

```text
没有 yaw/pitch/roll 三轴姿态真值；
不能写成监督姿态反演数据集；
不能计算真实 GEO 姿态反演成功率。
```
