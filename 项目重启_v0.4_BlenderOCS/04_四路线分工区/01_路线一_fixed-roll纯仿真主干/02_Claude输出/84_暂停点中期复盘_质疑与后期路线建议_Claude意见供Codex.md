## 1. 基于代码的事实核查（关键，先于一切判断）

核查文件：
```text
06_v0.4_code/07_training/train_baseline.py
06_v0.4_code/07_training/enhanced_ocs_dataset.py
```

| 维度 | 当前实现（代码事实） | 行号 |
|---|---|---|
| 任务形式 | **分类**：yaw 72 bin（5°/bin）、pitch 37 bin；输出 logits 取 argmax | `OCSImageModel` L107-129 |
| 主判据 | exact-bin（必须精确命中 5° 格） | `compute_all_metrics` L141-149 |
| 单 OCS 反演 | **单帧多维标量特征向量**（raw 4-dim 或 enhanced 特征），过 3 层 MLP；**不是光变曲线** | `OCSEncoder` L94-104 |
| 单图像反演 | 6 层灰度 CNN，输入 1 通道；**无任何噪声注入 / 数据增广** | `ImageEncoder` L71-91 |
| 联合反演 | **early-fusion**：image 256 维 + OCS 128 维直接 concat 成 384 维 → **单层线性** predictor；不是结果级融合 | L120-129 |
| 模型先进度 | 纯卷积 + 线性头，无注意力 / transformer / 预训练 backbone / 回归头 / 不确定性输出 | 全文 |

由此推出三条对叙事至关重要的判断：

1. **exact-bin 0% 脆弱性有结构性来源**：分类 + 精确命中判据下，跨 yaw-block 外推几乎注定坍缩。这与 E45A/R80 已确认的"预测系统性坍缩到训练可见 yaw 区间"一致，进一步说明 0% 是**判据放大**的哨兵指标，不能单独承载物理不可观测 claim。
2. **"joint 无增益"不能读成"两通道不互补"**：当前只测了一种最朴素融合（特征 concat + 单层线性），且图像 256 维在数值上**淹没** OCS 128 维。结论只能写成"该早期融合方式下无自动增益"，**不能写成"OCS 与 image 已证明（不）互补"**。
3. **图像零噪声训练是仿真现实性的隐患**：干净理想渲染图无噪声、无增广，模型可能学到渲染伪影/锯齿等**非物理捷径**；这同时回应了专家"仿真偏离真实"的质疑方向。

## 2. 对作者 7 项疑问的逐条回应

### Q1 现在的反演具体怎么做的
见第 1 节。要点：分类而非回归；单 OCS 是单帧多维特征而非光变曲线；单图像无加噪；联合是 early-feature-concat 而非结果级；模型基础。

### Q2 结果偏离最初设想，对投稿与项目影响
- 项目层面：影响有限。已建成**可审计的受控负结果链**，是合格科研资产，负结果 ≠ 失败。
- 投稿层面：影响真实。"纯负结果 + 单一严苛 split + 单指标"易被压低层级；但若叙事为"分布内可学 + 跨弧段外推失败 + pitch>yaw 各向异性 + 早期融合无自动增益"这种**有结构的边界发现**，可发表性明显提升。
- 结论：能发，档位取决于是"只稳定负结果"还是"把可观测性边界讲成正向贡献"。

### Q3 反演本就是分布内训练+验证，需要反演未知角度吗
作者直觉对一半。
- 分布内反演（= random split）下 yaw **可学（~50–70%）**，按最初目标口径其实**部分成功**。
- 但只报 random split 会被质疑数据泄漏 / inverse crime（train/test yaw 高度重叠 → 模型可能在内插/记忆而非学物理）。yaw-block holdout 正是为堵此质疑。
- 正解：**两者都报**，写成可观测性层级——分布内信息可提取（正面）+ 跨弧段外推是当前简单模型/早期融合的边界（诚实）。**当前 R82/R04 把外推失败当主角、分布内成功当配角，主次建议重审。**

### Q4 不改动继续推，三目标能否满意
- 可观测性：能闭合（random vs yaw-block 对比 + pitch>yaw 各向异性）。
- 互补性：**当前不能满意**——只测一种弱融合，结论虚空。需至少对照 mid/late fusion 或信息论互信息分析。
- 置信一致性：能写成 holdout 低置信/拒识 diagnostic，偏弱。
- 结论：不改动 → 得到"诚实的可观测性边界论文"，但**互补性支柱是虚的**，应清醒认识此缺口。

### Q5 V0.3 有成功案例，是否仿真导致而非推翻假设
对，且**可查证**，是必须先做的低风险事实核查。两种可能须分清：
- (A) 评测口径不同：V0.3 若用 random / 弱 holdout / 更粗判据，则与 V0.4 yaw-block 0% **不在同一难度档**，不矛盾——是口径变严所致，非假设被推翻。
- (B) 仿真/数据不同：V0.4 换 Blender-derived OCS、phase63 fixed-roll、特征维度变化，可能覆盖密度或前向模型差异致更难。
- 建议：做一次 **V0.3 vs V0.4 评测协议对齐核查**（同 split 口径、同判据下 V0.3 数是否仍成立）。对齐后若 V0.3 也掉到接近随机 → 真边界；若 V0.3 仍好 → 当前负结果主要是口径+模型容量产物。⚠️ 不得据此简单换回 random split 宣布成功（踩 inverse crime），要的是把差异诊断清楚并解释。

### Q6 只稳定负结果就达不到最初目标
直面：是，"姿态反演成功"与"可观测性边界"之间有真实落差。但非"认命发负结果"一条路，三选项（放行权在 Codex/作者）：

| B 诊断+改进 | 查清 yaw-block 失败主因（容量/特征/融合/数据密度），争取"分布内强+外推改善" | 需新训练 → C 类阶段门，有"追结果"风险 | 想要更强正向论文 |

#### 3A 信息源选择：光变曲线 vs 多维特征向量（回应作者疑问 Q8）

**数据事实核查**（`06_v0.4_code/07_training/dataset.py` L84-90 + `feature_definitions.json`）：
```text
当前 OCS = 单帧、单视角标量（ocs_total + 3 个部件 OCS）。
14 个 C2 特征配置全部是单帧标量组合（比值/密度/像素占比），无任何时间/序列维度。
每条 record = (一个姿态, 一张图, 一组单帧 OCS)。
→ 当前数据中不存在"光变曲线"。
```

两者本质区别：
| | 多维特征向量（当前） | 光变曲线（light curve） |
|---|---|---|
| 本质 | 单时刻多个标量 | 一段时间/几何序列的亮度演化曲线 |
| 信息来源 | 同一瞬间空间分解 | 时间/几何演化（天文/SSA 反演姿态主信号） |
| 真实工程对应 | 几乎不这么用 | **真实望远镜观测空间目标的标准产物** |

判断：
1. 对"贴近真实"目标，**光变曲线明显更对路**。专家明确指出真实工程中光度用途就是"长期观测光变规律→感知异动"，那条规律即光变曲线；当前单帧多维向量不是真实采集光度的方式，是路线一与真实数据之间的隐性裂缝。
2. **路线二真实 GEO 数据库给的是真实光度时间序列**；若路线一用单帧向量、路线二用序列，两者对接不上。光变曲线能让路线一与路线二同形态。
3. 可观测性角度：单帧光度存在严重姿态歧义（不同姿态可能给同样瞬时亮度）；序列通过演化打破歧义。**当前 yaw 外推失败，一部分可能正源于单帧信息不足以消歧。**

建议（梯度，均需放行）：
```text
最佳论文骨架 = "单帧多维 OCS vs 多视角/时序光变曲线，对姿态可观测性的贡献差异"
  → 把当前负结果升级为"为什么单帧不够、序列才够"的正向可观测性发现。

第一步（零成本、红线内）：伪光变曲线验证
  用现有数据，把同一 pitch、连续 yaw 的多帧 OCS 按 yaw 排序串成序列，
  检查是否呈现可辨识曲线结构 + 序列信息是否强于单帧。不重新渲染、不训练新模型。
第二步（C 类，需放行）：正式光变曲线数据生成
  Blender 前向模型可支持（仅改采样脚本）：同一目标沿连续观测几何/自转角渲染一串帧，
  聚合成亮度-角度曲线，配序列模型（1D-CNN / LSTM / Transformer）。属新数据生成，走阶段门。
```
作者可涉足光变曲线，但需重新生成序列数据；当前不动，先做第一步伪光变验证作为低风险探针。

#### 3B 模型架构改进清单（回应作者疑问 Q9）

作者判断"当前 2018 风格纯基础模型（CNN+单层线性头）是失败重要根源"成立——但应区分"根源"与"放大器"。按优先级/风险排序，**逐项走阶段门，每项记录边际贡献**：

```text
A 类 口径/建模修正（最先改，风险最低，可能直接改变结论）：
  A1. 分类 exact-bin → 角度回归（circular/von-Mises loss）或回归+分类双头
      —— 72 硬 bin + 精确命中是悲观的最大人为来源。
  A2. 图像加噪声/数据增广（高斯+泊松+随机平移/亮度抖动）
      —— 更真实，且防止学渲染伪影捷径。

B 类 融合方式（直接救"互补性"这个虚目标）：
  B1. early-concat+线性头 → mid/late fusion 或交叉注意力
      —— 平衡 image 256 维与 OCS 128 维，防图像淹没 OCS，才能真测互补性。

C 类 信息源升级（治本，需新数据，见 3A）：
  C1. 单帧 OCS → 光变曲线序列 + 序列模型。
  C2. 手搓 6 层 CNN → 更强 backbone（ResNet / 预训练 / ViT）。

D 类 服务置信一致性：
  D1. 加不确定性输出（预测分布/置信度），使 holdout 低置信可被标记/拒识。
```

**关键红线**：以上单独看都合理，但**全堆上去 = 把干净的预注册负结果变成调参追结果**，审稿人会质疑（R04 已反复警告）。正确做法：先做 V0.3 口径对齐核查判断是口径问题还是模型问题，再按 A→B→C→D 顺序逐项放行，每改一项记录其对结果的边际贡献——使改进过程本身成为可发表的消融/可观测性分析，而非追结果。

以上每一项都是独立可放行单元，**不得在当前暂停点擅自启动**。
