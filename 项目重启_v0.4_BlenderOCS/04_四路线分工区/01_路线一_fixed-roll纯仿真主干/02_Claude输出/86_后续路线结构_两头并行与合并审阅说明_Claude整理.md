## 0. 核心结论

后续不是"文献检索 → 方法总结 → 回 R04 阶段门"的线性三步。**R04 不是新工作的起点，而是暂停前路线一 C 负结果/图表主线的收口点。**

真实结构是 **"两头 + 一次合并审阅"**：
- 头A：R04 之前那条主线继续闭合（看清"该闭合到哪为止"）。
- 头B：84/85 提出的后续跟进（文献、方法总结、单帧 OCS vs 光变曲线对比设计、模型改正候选）。
- 两头各自边界明确后，做一轮新的 Codex 合并审阅/总裁决，重新决定下一阶段入口。

```
              ┌─ 头A：R04 主线收口 ───────────────────────┐
              │   A-1 E45D-FIX01 审阅（图表定稿，待 Codex） │
              │   A-2 图表/表格资产收尾 + 必要 SI           │
              │   A-3 负结果→24号三问桥接（= 闭合口）       │
先补文献认知 ──┤        任务：看清"闭合到哪里为止"           ├──→ 合并 Codex 审阅/总裁决
              │                                            │    重定下一阶段入口：
              │   头B：84/85 后续跟进 ─────────────────────┐│    · 先闭合 R04 线？
              │   B-1 文献检索（可在 A-1 后并行启动）       ││    · 启动方法改正？
              │   B-2 方法总结（须接在 A-3 之后）           ││    · 设计 OCS vs 光变曲线对比？
              │   B-3 单帧 OCS vs 光变曲线对比设计          ││    · 先做协议对齐核查？
              │   B-4 模型改正候选（架构不提前定死）        ││    · 或排成新阶段门
              └─        任务：把后续方案想清楚 ────────────┘┘
```

一句话：**不是回 R04 继续干，而是先把 R04 这头"该闭合到哪"看清，再把 84/85 这头"后续怎么走"想清，最后两头合并审阅，重新定入口。**

## 1. 头A：R04 主线收口

### 1.1 闭合口定义（关键）
区分"闭合口"与"完工"：头A 不需做到完整 Results 正文才算数，但也不能只审完 E45D-FIX01 就转头。有价值的闭合口是：

```text
头A 闭合口 = 负结果证据链 + 图表/SI 资产 + 三问桥接 三件齐备，
            形成一份"即使后续不做任何新实验，也能独立成文的负结果材料包"。
```

### 1.2 头A 从现在到闭合口的最短链
| 步骤 | 内容 | 谁做 | 状态 |
|---|---|---|---|
| A-1 | E45D-FIX01 审阅（图表草案定稿，核 Figure S5 样本数/版式） | **Codex** | ⏳ 待裁（当前卡点） |
| A-2 | 图表/表格资产收尾（Fig 3/4、Table 2、Fig S5 + 必要 SI） | Claude 执行→Codex | 未做 |
| A-3 | **负结果→24 号三问桥接**（what known / when complementary / when trustworthy） | Claude 执行→Codex | 未做（= 闭合口） |

**A-3 才是真正闭合口**，不是 A-1。A-1/A-2 只是"图做好了"；A-3 把图表翻译成对主线三问的科学回答，头A 才从"一堆负结果图表"变成"能独立站住的科学发现"。

### 1.3 Claude 在头A 能做与不能做
- 能做：梳理"收口清单"（列出从 A-1 到 A-3 各件状态与缺口），供 Codex/作者裁。
- 不能做：自审 E45D-FIX01、自行放行、自定闭合。真闭合要 Codex 裁。

## 3. 两头的衔接节奏（不严格串行）

```text
现在        → 头A 推 A-1（Codex 审 E45D-FIX01）；同时头B 启动 B-1 文献检索（并行，早开早好）
A-1 通过后  → 头A 继续 A-2/A-3；头B 文献检索继续
A-3 闭合后  → 头B 方法总结 B-2/B-3/B-4 接入（因为 A-3 桥接结论是头B 方法设计的输入前提）
两头明确后  → 合并 Codex 审阅/总裁决，重定入口
```

要点：
- **文献检索（B-1）从现在就能并行开**，不依赖头A 任何产物，且耗时长。
- **方法总结/对比设计（B-2~B-4）要接在头A 的 A-3 之后**：A-3 会明确"负结果在三问上回答了什么、还缺什么"，这是头B 设计对比实验/模型改进的前提；头B 不能脱离头A 闭合结论凭空设计。

## 4. 文件重合处理规则（头A/头B 共用资产）

**核心原则：凡 R04 负结果链赖以成立的东西（成果区数据、split、训练代码），一律冻结 + 另存副本，绝不原地改。** 否则负结果链被污染，审稿人会质疑结果被后续改动动过手脚（即 R04 反复警告的"别把干净负结果污染成追结果"在文件层面的体现）。

| 重合类型 | 例子 | 处理 |
|---|---|---|
| 成果区已稳定文件 | 09–15 号证据包、图表资产 | **绝不原地改**。头B 要基于它做对比/改进时，复制一份到 `02_Claude输出/` 作工作副本，原件冻结 |
| 代码 | `train_baseline.py`（头B 要改模型） | **绝不在原文件改**。新建改进版脚本（如 `train_baseline_v2.py` 或新目录），原脚本保留，保证 R04 线负结果可复现 |
| 流程/分析文档 | 84/85/86 号本身（`02_Claude输出/`） | 可直接增量编辑，但每次改留更新日期 |
| 只读共享数据 | OCS 特征 npz、渲染图（头A/头B 都读不改） | **只读共享无需备份**；备份只针对会被修改的东西 |
