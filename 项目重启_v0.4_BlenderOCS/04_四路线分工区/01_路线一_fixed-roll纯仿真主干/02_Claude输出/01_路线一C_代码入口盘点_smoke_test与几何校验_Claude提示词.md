## 1. 文件性质

本文用于生成可交给 Claude 执行的路线一 C 第一组提示词，对应 Codex R02 执行规划中的：

```text
1C-C01：读取路线一 C 指导文件和书籍知识库支撑文件，生成代码入口盘点清单。
1C-C02：设计单姿态 smoke test 与资源估计任务。
1C-C03：设计前向模型几何/可见性校验任务。
```

本文是 Claude 提示词文件，不是路线冻结文件，不修改 `CLAUDE.md`、13/14/24/25、路线总览或代码任务文件。Claude 执行后产生的输出应继续放入路线一的 `02_Claude输出/`，待作者交给 Codex 审阅。

## 4. 提示词 1C-C02：单姿态 smoke test 与资源估计

### 4.1 适用时机

用于 1C-C01 之后。前提是已经知道最小调用链。目标是设计一个最小可运行验证，不进入全量实验。

### 4.2 可直接发送给 Claude 的提示词

```text
请继续 v0.4 BlenderOCS 项目，执行“路线一 C 单姿态 smoke test 与资源估计设计”任务。

一、必须先读的文件
1. CLAUDE.md
2. 04_四路线分工区/01_路线一_fixed-roll纯仿真主干/00_路线冻结文件区/01_路线一_fixed-roll大论文主线与发刊答辩定位.md
3. 04_四路线分工区/00_总览与裁决/04_Codex审阅/R02_Codex_各路线具体执行规划草案.md
4. 上一步 Claude 输出的路线一 C 代码入口盘点清单。

二、本轮任务
请设计一个“单姿态 smoke test”，只验证 v0.4 pixel-level OCS-image 同源前向链路能否端到端跑通。

不要启动全量 yaw-pitch 网格，不要训练，不要做 G1/G3/G5 全实验。

请设计 smoke test 的最小样本：
1. 目标模型：优先选择当前代码中已有、最稳定、能代表路线一 C 的模型。
2. 姿态：选择一个 yaw/pitch/fixed-roll 姿态，roll 明确为受控变量。
3. 几何：选择一个 sun/view 几何，优先对应 G1 或历史 phase63 公平基线。
4. BRDF：主线使用五参数冯 / Phong-like 或当前最接近书中材料参数的配置；如果代码尚未实现，明确列为待实现，不要用 GGX 替代主线。
5. 输出：至少包括图像、OCS/brightness、visibility/mask/depth、manifest/source data、基础指标文件。

三、资源估计
请基于当前代码和历史运行记录，估计：
1. 单姿态耗时；
2. 单姿态输出文件大小；
3. 显存/内存/CPU/GPU 需求；
4. G1/G3/G5 粗略规模；
5. roll sensitivity 探针的最小规模；
6. full 3-DOF 全量为何不作为路线一 C 当前主实验。

四、输出格式
请输出“单姿态 smoke test 与资源估计方案”，建议包含：
1. smoke test 目的；
2. 最小输入配置；
3. 最小运行命令草案或伪命令；
4. 预期输出文件清单；
5. 通过/失败判据；
6. 资源估计表；
7. 后续若进入 G1/G3/G5 的扩展条件；
8. 不能进入全量重跑的闸门清单。

五、建议写入位置
如果需要保存输出，请先请求作者确认。建议路径为：
04_四路线分工区/01_路线一_fixed-roll纯仿真主干/02_Claude输出/03_路线一C_单姿态smoke_test与资源估计_Claude输出.md

六、红线
本轮只设计 smoke test 与资源估计；除非作者明确确认，不实际改代码、不全量运行、不训练。
不要把单姿态 smoke test 写成路线一结果。
不要把 clean benchmark 写成真实性能。
```

## 5. 提示词 1C-C03：前向模型几何/可见性校验

```text
请继续 v0.4 BlenderOCS 项目，执行“路线一 C 前向模型几何/可见性校验设计”任务。

1. CLAUDE.md
2. 04_四路线分工区/01_路线一_fixed-roll纯仿真主干/00_路线冻结文件区/01_路线一_fixed-roll大论文主线与发刊答辩定位.md
3. 04_四路线分工区/00_总览与裁决/04_Codex审阅/R02_Codex_各路线具体执行规划草案.md

二、本轮任务
请设计路线一 C 前向模型几何/可见性校验任务。

本轮只做校验设计，不进入全量数据生成，不训练，不做论文结果解释。

必须覆盖以下校验项：
1. depth round-trip：深度读出、反投影或坐标回查是否一致；
2. Position / WorldCoord：像素级位置、世界坐标、相机坐标是否自洽；
3. sun-view depth：太阳方向、观测方向、目标几何关系是否物理合理；

5. shadow validation：至少设计 20 姿态 shadow validation 的抽样规则；
6. visibility / mask / rendered image 对齐：mask 是否错位，边界是否明显异常；
7. manifest 字段：几何、姿态、BRDF、输出路径、随机种子或版本信息是否可追踪。

三、输出格式
请输出“前向模型几何与可见性校验方案”，建议包含：
1. 校验目的；
2. 每个校验项的输入、执行方式、输出和通过标准；
3. 需要截图/图表/数值日志的项目；
4. 失败时的定位路径；
5. 与后续 G1/G3/G5、roll sensitivity、mismatch 实验的关系；
6. 不允许跳过的硬校验项；
7. 待作者/Codex 确认的问题。

四、建议写入位置
如果需要保存输出，请先请求作者确认。建议路径为：

五、红线
本轮不声称前向模型已真实匹配外场光度。
本轮不把 Blender-derived OCS 写成完整真实测量链路。
本轮不修改冻结文件、总览文件或 CLAUDE.md。
```
