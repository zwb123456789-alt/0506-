# Claude 执行端已知问题与规避规则

最后更新：2026-06-26  
适用范围：路线一 C 后续 Claude 执行任务与 Codex 提示词生成

## 1. Windows 中文路径下 Write 工具 JSON 解析失败

现象：Claude 执行端使用 Write 工具写入 `d:\...` 或 `d:/...` 格式路径时，Windows 盘符、反斜杠转义、中文 UTF-8 编码与 JSON 解析叠加，可能导致工具参数解析失败。

规避规则：

```text
后续凡涉及中文路径写入，Write 工具统一使用 Bash 确认过的 /d/... Unix/Cygwin 风格绝对路径。
```

推荐格式示例：

```text
/d/我的文件/研究生学术/光学项目/0506新/项目重启_v0.4_BlenderOCS/...
```

Codex 后续给 Claude 的提示词如包含写入路径，应优先给出上述 `/d/...` 格式。

## 2. Claude 执行报告过于冗长

现象：Claude 倾向生成过度详细、复述历史、重复已稳定材料的执行报告，增加 Codex 审阅成本。

规避规则：

```text
Codex 给 Claude 的提示词必须明确：
只写关键事实和裁决所需内容，不复述历史，不展开背景，不重复已稳定材料。
执行报告遵循简短必要原则，以足够 Codex 裁决和后续执行为准，不设置固定行数。
相同信息不得重复出现在多个章节。
```

Claude 端报告建议结构：

```text
1. 任务状态
2. 关键产物路径
3. 核心结果或修正点
4. 未完成/需 Codex 裁决事项
5. 红线确认
```

本规则不改变任何科学口径、阶段门或成果区状态。
