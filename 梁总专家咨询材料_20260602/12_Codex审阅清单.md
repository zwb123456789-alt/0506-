# Codex 审阅清单：Claude 补充材料

> 用途：Claude 生成补充材料后，Codex 按本清单审阅、删改、降级和整合。  
> 审阅对象：`梁总专家咨询材料_20260602\Claude输出\` 中的候选文件。  
> 核心原则：不把 Claude 输出直接发给梁总，必须先做事实、口径、篇幅和风险审阅。

---

## 1. 文件完整性检查

Claude 应输出：

```text
Claude输出/01_梁总会前预读材料_正式发送版.md
Claude输出/02_发给梁总的微信或邮件正文.md
Claude输出/03_梁总面谈PPT大纲_10页版.md
Claude输出/04_专家咨询问题矩阵_按优先级.md
Claude输出/05_真实实验补充设计备选方案.md
Claude输出/06_后续技术方向路线图.md
```

检查：

- 文件是否都存在。
- 是否写在 `Claude输出/` 内。
- 是否没有修改外部文件。
- 是否有空文件或明显未完成段落。

---

## 2. 事实准确性检查

逐项核对：

| 项目 | 审阅标准 |
|---|---|
| 项目定位 | 必须写成 controlled simulation benchmark / 受控仿真基准，不写成真实观测系统 |
| ResNet 结果 | 1.69 +/- 0.07 deg 只能写 clean rendered image upper bound |
| OCS 价值 | 写低维、可解释、多几何、对图像像素退化不敏感，不写 clean image 下最强 |
| Fusion | 写条件性互补，不写永远最优 |
| all_raw | 必须标 semi-oracle / diagnostic，不写 operational feature |
| 真实验证 | 必须承认尚无真实光学望远镜验证 |
| 实验设计 | 只能写备选方案，不写已完成或已确定 |
| 场地/合作 | 不得编造具体场地、单位承诺或梁总意见 |
| 投稿 | 不得写某期刊一定合适或一定能中 |

---

## 3. 数值检查

允许使用的数字：

```text
单平板平均相对误差约 0.253%
立方体误差不超过约 0.25%
fast/full OCS mean 差异约 2.0%，max 差异约 0.5%
2701 个 yaw-pitch 姿态
5 个 OCS 观测几何
OCS MLP all_raw 3.98 +/- 0.60 deg，Hit@5=90.7%
OCS MLP per_part_log 5.91 deg 左右
TinyCNN image-only 约 11.87-12.38 deg
Feature fusion per_part_log 4.10 +/- 0.77 deg
ResNet image-only 1.69 +/- 0.07 deg，Hit@5=97.6%
ResNet + per_part_log 1.47 +/- 0.07 deg，Hit@5=99.7%，worst 9.9 -> 6.6 deg
1% Gaussian image noise 下 ResNet 约 85.85 deg，Hit@5=2.2%
OCS-noise fusion gain +1.97 deg -> +6.29 deg
遮挡率约 60-78.5%
Roll OCS 平均相对变化约 20.3%，max 约 26.2%
```

发现其他数字时：

- 若不能在源材料中确认，标 `[待核验]`。
- 不进入正式发给梁总的版本。

---

## 4. 面向梁总的语气检查

材料应表现为：

- 专业。
- 谦逊。
- 问题明确。
- 不卑不亢。
- 尊重专家时间。

需要删除或改写：

- 过度口语化。
- 过度自夸。
- 过度自我否定。
- 像商业合作方案。
- 像完整论文答辩。
- 对梁总提出过强任务要求。

---

## 5. 篇幅检查

正式发送版材料建议：

- 2500-3500 中文字以内。
- 最多 1-2 个简表。
- 不堆路径。
- 不展开代码细节。

微信正文：

- 100-250 字为宜。

PPT 大纲：

- 10 页左右。
- 每页只服务一个目的。

问题矩阵：

- P0 不超过 6 个。
- P1 不超过 8 个。
- P2 可适当多，但现场不一定全问。

---

## 6. 结构检查

正式预读材料应包含：

1. 项目背景。
2. 当前方法框架。
3. 进展与关键结果。
4. 当前论文定位。
5. 想咨询的问题。
6. 相关技术方向。

真实实验方案应包含：

1. 路线名称。
2. 目的。
3. 最低条件。
4. 是否需要 ground truth。
5. 优点。
6. 风险。
7. 对论文支撑方式。
8. 向梁总请教的问题。

技术路线图应包含：

1. 短期。
2. 半年。
3. 一年。
4. 更长期。

---

## 7. 红线检查

若 Claude 输出出现以下内容，必须删除或改写：

- “已经完成真实观测验证”。
- “fusion 一定优于所有方法”。
- “OCS 是唯一主力传感器”。
- “ResNet clean image 结果证明真实观测可达到 1.69 deg”。
- “梁总可以提供某某场地/资源”。
- “某期刊肯定能投中”。
- “必须请梁总半天完整审稿”。
- 未来源的具体设备、场地、团队、经费和时间承诺。

---

## 8. 最终整合建议

Claude 输出审阅通过后，正式发给梁总的材料建议只保留：

```text
最终发送版/梁总会前预读材料_正式版.md
最终发送版/梁总重点请教问题_压缩版.md
```

现场备用材料可保留：

```text
真实实验补充设计备选方案.md
后续技术方向路线图.md
10页PPT大纲.md
```

如果作者要发微信，建议只发：

1. 简短微信正文。
2. 一份预读材料 PDF。
3. 如梁总愿意，再补问题清单。
