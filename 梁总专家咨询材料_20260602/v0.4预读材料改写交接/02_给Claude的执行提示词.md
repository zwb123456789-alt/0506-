请在“项目背景”或新增第一节中说明：

- 如果 OCS 与图像不是同一前向物理模型下的两种读出，那么 OCS-only、image-only 和 fusion 的差异可能混入两套仿真链路差异，而不完全是观测模态本身的信息差异。
- v0.4 的核心目标是统一前向模型：同一 STL、同一姿态、同一 sun/det 几何、同一材料分区、同一 GGX BRDF、同一 camera visibility 和 sun-side visibility 定义。

- Python 负责“如何反光”：GGX BRDF、NoL/NoV、太阳侧可见性 `V_sun_macro`、OCS 积分、per-part OCS、clean image linear response。
- OCS 是同一 clean image linear response 的积分读出，图像是空间分布读出。
- v0.4 不是为了保证指标一定更好，而是为了让 OCS/image/fusion 的比较更公平、更可审计、更容易防守。

### 5. 补充各阶段路线，特别是反演方法

请把方法框架从单条流程图扩展成“阶段化路线”，但保持简洁。这里的阶段不是只有 v0.4，而是整个项目到目前为止的路线：

1. 物理观测建模：STL 几何、材料分区、GGX BRDF、可见性、自遮挡、OCS 与图像定义。
2. OCS-only 探索：用 total/per-part/multi-geometry OCS 特征验证低维光度响应是否能反演 yaw/pitch。
3. 图像反演：引入光度图像，用 TinyCNN/ResNet 验证空间结构、阴影、高光和部件亮度分布对姿态反演的作用。
4. 融合与反演决策：比较 OCS-only、image-only、late fusion、feature fusion，形成“条件性互补”判断。
5. 退化与鲁棒性分析：用噪声、模糊、降采样、背景等退化检验 clean image 结果能否外推真实观测。
6. 方法审计与 v0.4 重建：发现 OCS/image 数据源不同源风险后，改为 Blender-derived pixel-level OCS；先做单姿态 smoke test、depth round-trip、Position/WorldCoord、sun-view depth、20 姿态 shadow validation，再全量生成。
7. 论文与实验补充：基于 v0.4 新 manifest 和 source_data 重跑主实验和补充实验。

反演方法请写清物理和算法逻辑：

- OCS-only：输入 total/per-part OCS 或多观测几何 concat 特征，MLP 输出 `[sin yaw, cos yaw, sin pitch, cos pitch]`，再还原角度。优势是低维、可解释、多几何稳定；局限是可能存在姿态简并。
- image-only：输入单几何光度图像，TinyCNN/ResNet 提取投影形状、阴影、高光和空间亮度分布，输出同样的姿态编码。优势是空间结构强；局限是真实图像退化敏感。
- late fusion：融合 OCS 模型和图像模型的输出向量，可用于分析不同权重下哪个模态更可信。
- feature fusion：OCS 分支与图像分支分别提取特征，再由融合头输出姿态，可学习跨模态互补。
