# Codex 后续审阅清单

最后更新：2026-06-08

用途：Claude 改写完成后，Codex 按本清单审阅 `最终发送版/梁总会前预读材料_正式版.md`，只做把关和提出修改意见，必要时再生成二轮提示词。

## P0 红线

1. 是否仍出现 `Cook-Torrance` 或 `GGX/Cook-Torrance`。
   - 若出现，必须改为 `GGX`、`GGX BRDF` 或 `显式 GGX 反射模型`。

2. 是否把 v0.3 旧结果写成最终投稿结果。
   - 旧数值必须带“前期阶段性结果”或“v0.3 诊断结果”口径。
   - 必须说明 OCS-only、fusion、OCS noise、beta sweep 等依赖旧 OCS 的结果后续要在 v0.4 重跑。

3. 是否声称 v0.4 已经有新主结果。
   - 当前只能写“方法冻结/文档确认/代码实施前准备/等待门控验证”。

4. 是否说 Blender-derived OCS 等于真实观测。
   - 正确口径：更接近投影成像和光度积分过程的合成前向定义，不等同于真实望远镜验证。

5. 是否仍写“融合永远最优”。
   - 正确口径：条件性互补；clean image 是理想上界，退化条件下 OCS 可能更有价值。

## P1 内容完整性

1. 开头是否先说明作用与意义。
   - 应包括非合作目标、缺少姿态遥测、光学观测可获得 OCS/光变和图像、姿态变化反映目标状态。
   - 应明确“不是只输出角度，而是判断不同观测条件下何时可信”。

2. 是否补充调研判断。
   - 至少提到已有多源融合方向：光变 + 测角、光变 + 动力学滤波、图像 + 惯性/星敏、图像 + 深度/点云/LiDAR。
   - 不应编造具体文献。
   - 应说明本项目差异：同一光学散射物理模型下生成 OCS 与图像并比较其姿态反演贡献。

3. 是否把前期关键操作和路线演进讲清，而不是只写 v0.4。
   - 应包含 OCS-only 起步。
   - 应包含加入光度图像的原因。
   - 应包含 OCS-only、image-only、late fusion、feature fusion 的反演比较。
   - 应包含 clean image 很强带来的叙事调整。
   - 应包含退化/鲁棒性补充实验的目的。
   - v0.4 应作为方法审计后重建阶段出现，而不是唯一主线。

4. v0.4 方法审计是否讲清。
   - face-center OCS 与 Blender pixel-level image 不同源。
   - 不同源会导致模态差异混入仿真链路差异。
   - v0.4 目标是统一前向模型，而非简单替换 CSV。

5. 统一前向模型是否讲清。
   - 同一 STL、姿态、sun/det、材料分区、GGX、camera visibility、sun-side visibility。
   - Blender 负责“看见哪里”。
   - Python 负责“如何反光”。
   - 反演代码只负责“如何使用观测量”。
   - OCS 是积分读出，图像是空间分布读出。

6. 阶段路线是否清楚。
   - 物理观测建模。
   - OCS-only 探索。
   - 图像反演。
   - 融合与反演决策。
   - 退化/鲁棒性补充实验。
   - v0.4 方法审计与门控验证：smoke test、depth round-trip、Position/WorldCoord、sun-view depth、20 姿态 shadow validation。
   - 全量生成、反演训练、论文重写与投稿定位。

7. 反演方法是否讲到“怎么反演”。
   - OCS-only：OCS 特征 -> MLP -> sin/cos yaw/pitch -> 角度。
   - image-only：光度图像 -> CNN/ResNet -> 同样姿态编码。
   - late fusion：输出向量加权。
   - feature fusion：双分支特征融合。

## P2 风格与可发送性

1. 是否像发给专家的材料，而不是内部复盘。
   - 内部路径、文件编号、审计编号不要堆太多。
   - 可以保留 v0.4 名称，但不要像项目管理文档。

2. 是否谦逊但不自我否定。
   - 不要写“这个项目可能没有意义”。
   - 应写“希望请您判断论文定位、真实实验补充和后续方向”。

3. 长度是否合适。
   - 建议 2500-4000 中文字。
   - 过长则压缩方法细节和旧结果表格。

4. 请教问题是否具体。
   - 应能引导梁老师给出判断：方向是否成立、统一前向模型是否合理、真实实验怎么补、投稿边界怎么写、后续方向优先级。

5. 是否避免了过度承诺。
   - 不说真实验证已完成。
   - 不说完整大气/探测器/PSF 链路已建模。
   - 不说三轴姿态已完成。
