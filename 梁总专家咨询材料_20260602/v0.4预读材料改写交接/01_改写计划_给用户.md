## 必须吸收的素材

### 1. 专家视角下的作用与意义

建议在原“项目背景”前半部分补强，不要只说“非合作目标缺少姿态遥测”，而要明确实际意义：

- 地基或空间光学观测中，目标-太阳-探测器几何通常可由星历、观测站位置、观测时间和太阳位置计算。
- 在几何关系已知时，目标反射亮度、光变/OCS 和光度图像会随姿态变化而变化，可作为姿态反演依据。
- 对失效卫星、碎片、未知目标、不可通信目标，外部光学观测是重要姿态信息来源。
- 姿态变化可反映翻滚、失稳、异常机动、太阳能板指向变化或结构状态变化。
- 本项目的现实价值不是只输出一个姿态角，而是判断“什么时候信 OCS、什么时候信图像、什么时候融合”。

建议保留的口径：

```text
本研究希望把 OCS/光变这类低维光度响应和光度图像这类空间分布信息，转化为空间目标姿态估计中的有效观测约束；进一步判断在不同观测质量下，哪类观测更可信、怎样融合更稳妥。
```

### 2. 调研与领域定位

来自 0603 汇报的调研口径可简化为一段，不要写成文献综述：

- 多源融合在空间目标姿态感知中已有研究基础，例如光变 + 测角、光变 + 动力学滤波、图像 + 惯性/星敏、图像 + 深度/点云/LiDAR 等。
- 但这些工作通常不在同一套光学散射物理模型下同时生成 OCS 与图像，再比较两者对姿态反演的贡献。
- 因此本项目更像一个受控、可审计的 synthetic benchmark / observation-consistent forward model，用于分析 OCS、图像和融合在不同观测质量下的可靠性。

注意：不要编造具体文献名、作者、年份。若 Claude 想写引用，统一标成 `[待补文献]`。

### 4. 全项目路线、关键操作和方法补充

需要把前期已经做过的关键操作和 v0.4 方法重建一起汇入简约版。不能只写 v0.4，否则会让材料显得像“刚发现问题后准备重做”，看不出前面已经完成的探索、反演链路和决策依据。

建议按“项目如何一步步走到现在”压缩成一段或一个小节：

- 起点是 OCS-only 姿态反演：先证明低维光度响应能不能作为 yaw/pitch 反演观测量。
- 随后加入光度图像反演：因为 OCS 缺少空间结构，而图像包含投影形状、阴影、高光和部件亮度分布。
- 为了公平比较 OCS 与图像，提出统一前向模型：同一几何、姿态、观测几何、材料、GGX 和遮挡定义下，比较两种观测表达。
- 在主反演阶段跑通 OCS-only、image-only、late fusion、feature fusion，发现 clean image 很强，fusion 不能简单写成“永远最优”。
- 因此叙事从“融合最好”调整为“条件性互补”：clean image 是理想上界，OCS 是低维、多几何、可解释的稳定约束，融合价值取决于观测退化和错误模式。
- 随后做图像噪声、模糊/降采样、OCS noise、phase63 公平消融、random split、GGX 敏感性、自遮挡、roll 敏感性、outlier/failure case 等补充实验，目的是判断不同观测条件下该信哪种观测。
- 最后方法审计发现旧 OCS 主要来自 face-level / face-center 采样，而图像来自 Blender pixel-level 渲染链路，两者不完全同源，所以进入 v0.4 方法重建。
- v0.3 旧结果作为阶段性探索和诊断保留，但不作为最终投稿主结果。
- 重启原因是旧 OCS 主要来自 face-level / face-center 采样，而图像来自 Blender pixel-level 渲染链路，两者不完全同源。
- v0.4 的核心是统一前向模型：同一 STL、同一姿态、同一 sun/det 几何、同一材料分区、同一 GGX BRDF、同一 camera visibility 和 sun-side visibility 定义。
- Blender 负责“看见哪里”：STL、姿态、正交投影、depth、normal、part ID、Position/WorldCoord、pixel-level geometry visibility。
- Python 负责“如何反光”：GGX BRDF、NoL/NoV、太阳侧可见性 `V_sun_macro`、OCS 积分、per-part OCS、clean image linear response。
- OCS 是同一 clean image linear response 的积分读出，图像是空间分布读出。
- v0.4 不保证指标一定更好，目的是让 OCS/image/fusion 的比较更公平、更可审计、更容易防守。

### 5. 阶段与反演方法补充

当前正式版“方法框架”太短。建议补成“阶段化路线”，其中 v0.4 是最后的重建与重跑阶段，不是唯一阶段：

1. 物理观测建模阶段：STL 几何、材料分区、GGX BRDF、可见性、自遮挡、OCS 和图像定义。
2. OCS-only 探索阶段：用 total/per-part/multi-geometry OCS 特征验证低维光度响应是否能反演 yaw/pitch。
3. 图像反演阶段：引入光度图像，验证空间结构、阴影、高光和部件亮度分布对姿态反演的作用。
4. 融合与反演决策阶段：比较 OCS-only、image-only、late fusion、feature fusion，形成“条件性互补”而非“融合永远最优”的判断。
5. 观测退化与鲁棒性阶段：用噪声、模糊、分辨率下降、背景等退化判断 clean image 结果能否外推到真实观测。
6. 方法审计与 v0.4 重建阶段：发现 OCS/image 数据源不同源风险后，改为 Blender-derived pixel-level OCS，并通过 smoke test、depth round-trip、Position/WorldCoord、sun-view depth、20 姿态 shadow validation 后再全量生成。
7. 论文与实验补充阶段：根据 v0.4 新 manifest/source_data 重跑主实验和补充实验，更新论文定位。

反演方法建议写清：

- OCS-only：输入 OCS total/per-part 或多观测几何 concat 特征，MLP 输出 `[sin yaw, cos yaw, sin pitch, cos pitch]`，再还原 yaw/pitch。
- image-only：输入单几何光度图像，TinyCNN/ResNet 提取空间结构，输出同样的姿态编码。
- late fusion：融合 OCS 模型和图像模型的输出向量，适合做权重和可靠性分析。
- feature fusion：OCS 分支和图像分支分别提特征，再由融合头输出姿态，适合学习跨模态互补。

注意：这些旧结果数值来自 v0.3，可作为“阶段性结果”，但需要提醒 v0.4 会基于新 manifest 重跑。
